## 2. 알고리즘 분석 개념

### 2.1 입력 크기와 비용 모델

알고리즘 분석에서는 입력 크기를 변수로 정의하고, 입력 크기가 증가할 때 필요한 연산과 메모리의 증가 양상을 비교합니다. 입력이 두 개 이상이면 `n`, `m`처럼 각각의 크기를 유지해야 하며, 서로 같다고 가정하지 않습니다.

MIT 6.006은 알고리즘을 수학적으로 모델링하고 성능 측정과 분석 기법을 다루는 과목으로 설명됩니다. 본문에서는 특정 프로세서의 초 단위 측정보다 입력 크기에 따른 점근적 증가율을 중심으로 설명합니다.

### 2.2 시간 복잡도와 공간 복잡도

- 시간 복잡도: 입력 크기에 따라 알고리즘 실행에 필요한 연산량이 증가하는 양상
- 공간 복잡도: 입력 크기에 따라 알고리즘이 사용하는 전체 메모리 양이 증가하는 양상
- 보조 공간: 입력 저장 공간을 제외하고 알고리즘 실행 중 추가로 사용하는 공간
- 재귀 공간: 재귀 호출이 유지하는 호출 스택을 포함하는 추가 공간

실제 실행 시간은 상수 비용, 캐시, 메모리 접근, 인터프리터·컴파일러, 입출력에 영향을 받습니다. 점근적 복잡도는 이러한 요소를 모두 측정한 실제 시간과 동일하지 않습니다.

### 2.3 평균·최악·상환 비용

Python Wiki는 자료구조 연산 표에서 평균 사례, 최악 사례, 상환된 최악 사례를 구분합니다. 따라서 다음을 혼동하지 않아야 합니다.

| 구분      | 의미                             | 사용 시 주의                      |
|-----------|----------------------------------|-----------------------------------|
| 최선 사례 | 특정 입력에서 가장 적은 비용     | 일반 성능 보장으로 사용하지 않음  |
| 평균 사례 | 입력 분포 가정 아래의 평균 비용  | 분포와 가정을 함께 명시           |
| 최악 사례 | 가능한 입력 중 가장 큰 비용      | 상한과 안정성 분석에 유용         |
| 상환 비용 | 연산 시퀀스 전체의 평균적인 비용 | 개별 연산이 항상 같은 비용은 아님 |

> 상환 분석(Amortized Analysis): 개별 연산이 아니라 연산 시퀀스 전체의 비용을 분산하여 각 연산의 평균 비용을 계산하는 방법입니다. 동적 배열 확장처럼 드물게 큰 비용이 발생하는 연산을 설명할 때 사용합니다.

## 3. 계산 방법 범위

### 3.1 순차·조건·중첩 구조

본문에서 다음 계산 규칙을 사용합니다.

| 코드 구조      | 계산 원리                          | 예시 결과                 |
|----------------|------------------------------------|---------------------------|
| 순차 실행      | 비용을 더한 뒤 지배 항만 유지      | `O(n) + O(n²) = O(n²)`    |
| 조건 분기      | 실행 가능한 경로 중 최대 비용 선택 | `max(O(n), O(n²))`        |
| 독립 중첩 반복 | 반복 횟수를 곱함                   | `n × n = O(n²)`           |
| 의존 중첩 반복 | 실제 반복 횟수의 합을 계산         | `1 + 2 + ... + n = O(n²)` |
| 여러 입력      | 서로 다른 입력 변수를 유지         | `O(n + m)` 또는 `O(nm)`   |

상수 계수와 낮은 차수 항을 제거하는 단순화는 점근적 증가율을 표현하기 위한 표기 규칙입니다. 예를 들어 `3n² + 5n + 10`은 `O(n²)`로 표현하지만, 실제 상수 비용이 사라지는 것은 아닙니다.

### 3.2 로그 반복

반복마다 문제 크기가 일정한 비율로 줄어드는 경우 반복 횟수는 로그에 비례합니다.

```text
1, 2, 4, 8, ..., 2^k
2^k >= n
k >= log2(n)
```

따라서 `i`를 매회 2배로 늘리거나 검색 범위를 절반으로 줄이는 패턴은 `O(log n)`으로 분석합니다. `n`개 항목을 순회하면서 `O(log n)` 연산을 수행하면 `O(n log n)`입니다.

### 3.3 합과 점화식

반복 횟수가 단계마다 달라지면 등차합·기하급수 합 등으로 총 횟수를 계산합니다.

```text
0 + 1 + 2 + ... + (n - 1) = n(n - 1) / 2 = O(n^2)
```

재귀 알고리즘은 점화식으로 표현합니다.

| 알고리즘 패턴          | 점화식                          | 대표 결과    |
|------------------------|---------------------------------|--------------|
| 절반만 재귀            | `T(n) = T(n/2) + O(1)`          | `O(log n)`   |
| 두 부분 분할·선형 병합 | `T(n) = 2T(n/2) + O(n)`         | `O(n log n)` |
| 두 갈래 단순 재귀      | `T(n) = T(n-1) + T(n-2) + O(1)` | 지수 시간    |

점화식의 결과는 재귀 트리, 치환법, 반복 전개 또는 적절한 정리로 확인하며, 본문에서는 대표 패턴의 도출 과정을 우선 설명합니다.

## 4. Python 구현체 비용

### 4.1 `list`

Python Wiki의 CPython 복잡도 표는 다음과 같은 대표 비용을 제시합니다.

| 연산             | 평균 사례    | 상환된 최악 사례    | 해석                           |
|------------------|--------------|---------------------|--------------------------------|
| 인덱스 조회      | `O(1)`       | `O(1)`              | 배열 기반 임의 접근            |
| 마지막 항목 추가 | `O(1)`       | `O(1)`              | 확장 비용을 상환 관점에서 해석 |
| 중간 항목 삭제   | `O(n)`       | `O(n)`              | 뒤쪽 항목 이동                 |
| 순회             | `O(n)`       | `O(n)`              | 모든 항목 확인                 |
| 정렬             | `O(n log n)` | `O(n log n)`        | Wiki의 일반 복잡도 표 기준     |
| 포함 여부 확인   | `O(n)`       | 해당 표의 선형 탐색 | 정렬·별도 인덱스가 없는 경우   |

개별 `append`가 항상 실제 실행 시간상 동일하다는 뜻은 아닙니다. 내부 용량 확장이 발생하는 순간에는 더 큰 비용이 발생할 수 있으므로 상환 분석이라는 전제를 표시합니다.

### 4.2 `deque`

Python 공식 `collections.deque` 문서는 양쪽 끝의 추가·삭제가 대략 `O(1)` 성능이라고 설명합니다. 반면 중간의 인덱스 접근은 `O(n)`으로 느려질 수 있으며, 빠른 임의 접근에는 list를 사용하도록 안내합니다.

| 연산                | 대표 비용   | 근거·조건                      |
|---------------------|-------------|--------------------------------|
| 오른쪽 끝 추가·삭제 | 대략 `O(1)` | 양쪽 끝 연산                   |
| 왼쪽 끝 추가·삭제   | 대략 `O(1)` | 양쪽 끝 연산                   |
| 양 끝 인덱스 접근   | `O(1)`      | 양 끝에 가까운 접근            |
| 중간 인덱스 접근    | `O(n)`      | 빠른 임의 접근 자료구조가 아님 |

### 4.3 `dict`와 `set`

Python Wiki는 `dict`와 `set`의 평균 비용 표에서 해시 함수와 충돌이 충분히 드물다는 가정을 명시하고, 일부 조회·삽입·삭제 연산의 평균 사례를 `O(1)`, 최악 사례를 `O(n)`으로 제시합니다.

본문에서는 다음처럼 조건을 함께 씁니다.

```text
해시 테이블 조회: 평균 O(1), 최악 O(n)
```

이는 모든 입력에서 항상 `O(1)`이라는 뜻이 아니며, 구현·해시 함수·충돌 상황을 고려한 구분입니다.

### 4.4 정렬

Python Sorting HOWTO는 Python 정렬이 안정적이며, Timsort가 이미 정렬된 데이터의 순서를 활용할 수 있다고 설명합니다. 복잡도 표를 사용할 때는 Python Wiki의 CPython 기준 `O(n log n)` 표기와 Python 공식 HOWTO의 안정성·기존 순서 활용 설명을 분리하여 인용합니다.

## 5. 본문 작성 시 주의사항

- `n`이 무엇을 세는지 알고리즘마다 먼저 정의합니다.
- `O(1)`은 입력 크기에 따른 증가율이 일정하다는 뜻이지 실제 실행 시간이 항상 짧다는 뜻이 아닙니다.
- 평균 사례의 입력 분포와 최악 사례의 조건을 함께 설명합니다.
- 상환 `O(1)`을 개별 연산의 항상 일정한 비용으로 표현하지 않습니다.
- Python Wiki의 표는 CPython 구현 기준이므로 Python 언어 전체의 불변 규칙으로 일반화하지 않습니다.
- `deque`의 양 끝 연산과 중간 접근 비용을 구분합니다.
- 정렬 알고리즘의 복잡도, 안정성, 이미 정렬된 입력 활용 여부를 별도 속성으로 다룹니다.
- 시간 복잡도와 공간 복잡도, 보조 공간과 재귀 스택을 구분합니다.
- `n`과 `m`이 독립적인 입력이면 `O(n + m)`과 `O(nm)`을 구분합니다.
- 점근 분석과 실제 벤치마크 결과를 같은 주장으로 섞지 않습니다.
