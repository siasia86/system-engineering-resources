# PLAN Template

복합 작업을 시작할 때 이 템플릿을 복사하여 `PLAN.md`로 사용합니다. 문서별 역할은 [문서 운영 정책](../documentation_policy.md)에서 정의합니다.

저장소 전역 작업은 `.governance/PLAN.md`를 사용합니다. 기존 저장소의 루트 `PLAN.md`는 migration 전까지 legacy 위치로 허용합니다.

🟡 이 템플릿 파일 하단의 푸터는 템플릿 자체에 적용된 것입니다. 복사한 문서의 푸터는 대상 저장소의 규칙을 따릅니다. 푸터를 금지하는 저장소에서는 푸터를 제거하고, 날짜는 복사한 날짜로 갱신합니다.

## 1. 사용 방법

```bash
mkdir -p <target>/.governance
cp templates/plan_template.md <target>/.governance/PLAN.md
```

복사 후 이 `사용 방법` 섹션을 제거하고, 각 섹션의 안내 문구를 실제 내용으로 교체합니다.

기록하지 않는 정보입니다.

- 내부 IP, 호스트명, 사용자명, 개인 경로.
- API key, token, password, SSH key와 같은 자격증명.
- 실제 인프라 구성값과 접속 정보.

환경 종속 값이 필요하면 placeholder로 두고 접근이 제한된 별도 문서에서 관리합니다.

## 2. 배경

- 이 작업이 필요한 이유를 작성합니다.
- 현재 상태에서 무엇이 문제인지 작성합니다.
- 관련 `ISSUE.md` 항목이 있으면 링크합니다.

배경 없이 목표만 적으면 목표 자체가 타당한지 검토할 수 없습니다.

## 3. 목표

- 작업 목표를 한 문장으로 작성합니다.
- 완료를 판단할 기준을 작성합니다.

## 4. 범위

### 포함

- 변경 대상을 작성합니다.

### 제외

- 이번 작업에서 처리하지 않는 항목과 그 이유를 작성합니다.

## 5. 단계

각 단계는 독립적으로 검증 가능한 크기로 나눕니다. 이전 단계가 검증을 통과하기 전에 다음 단계로 넘어가지 않습니다.

### 단계 1

- [ ] 작업 내용을 작성합니다.
- [ ] 검증: 이 단계의 통과 조건을 작성합니다.

### 단계 2

- [ ] 작업 내용을 작성합니다.
- [ ] 검증: 이 단계의 통과 조건을 작성합니다.

단계 수는 작업에 맞게 조정합니다.

## 6. 검증 기준

```bash
# 대상에 맞는 검증 명령을 작성합니다.
```

- [ ] 문법·정적 검사 통과.
- [ ] 링크·스타일 검사 통과.
- [ ] 비밀정보 검사 통과.
- [ ] 변경 범위 확인.
- [ ] CHANGELOG 기록.

검증 실패를 예외 설정으로 숨기지 않습니다. 예외가 필요하면 사유를 함께 기록합니다.

## 7. 롤백

| 단계   | 롤백 방법               | 되돌리기 어려운 지점    |
|--------|-------------------------|-------------------------|
| 단계 1 | 복원 방법을 작성합니다. | 없음                    |
| 단계 2 | 복원 방법을 작성합니다. | 해당 지점을 작성합니다. |

- 파일 변경은 이전 commit 또는 백업으로 복원합니다.
- 백업을 만들 경우 저장소 외부에 두고, 작업 완료 후 정리합니다.
- 되돌릴 수 없는 지점이 있으면 8장에 별도로 기록합니다.

## 8. 비가역 작업

되돌릴 수 없는 작업을 미리 식별합니다. 해당 작업은 실행 직전에 승인을 받습니다.

| 작업                    | 비가역 사유                       | 승인 필요 |
|-------------------------|-----------------------------------|-----------|
| 작업 내용을 작성합니다. | 되돌릴 수 없는 이유를 작성합니다. | ✅        |

비가역 작업이 없으면 `해당 없음`으로 기록합니다. 확인하지 않은 상태로 비워두지 않습니다.

판단 기준입니다.

- 데이터 삭제, 이력 재작성, force push
- 자격증명 삭제 (비활성화는 되돌릴 수 있으므로 삭제와 구분합니다)
- 설정 후 완화할 수 없는 보호 기능 활성화
- 프로덕션 반영, 공유 시스템 변경
