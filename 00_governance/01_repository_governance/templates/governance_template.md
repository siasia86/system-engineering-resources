# GOVERNANCE Template

저장소별 규칙이 필요할 때 이 템플릿을 복사하여 대상 저장소의 `.governance/GOVERNANCE.md`로 사용합니다. 적용 순서와 기술 범위는 [저장소 규칙 우선순위 정책](../governance_precedence.md)에서 정의합니다.

## 사용 방법

```bash
# 대상 저장소에 복사
REPO=$(git -C <path> rev-parse --show-toplevel)
mkdir -p "${REPO}/.governance"
cp templates/governance_template.md "${REPO}/.governance/GOVERNANCE.md"
```

복사 후 아래 안내 문구를 실제 내용으로 교체하고, 이 `사용 방법` 섹션과 목차의 해당 항목을 제거합니다.

전역 규칙만으로 충분한 저장소에는 `.governance/`를 만들지 않습니다. 예외가 실제로 필요한 경우에만 생성합니다.

🟡 이 템플릿 파일 하단의 푸터는 템플릿 자체에 적용된 것입니다. 복사한 `GOVERNANCE.md`의 푸터는 대상 저장소의 규칙을 따릅니다. 푸터를 금지하는 저장소에서는 푸터를 제거합니다.

---

## 1. 적용 범위

이 정책은 다음 경로 하위에만 적용합니다.

```text
<repository-root>/**
```

- 저장소 최상위 경로를 작성합니다.
- 저장소 일부에만 적용할 경우 해당 하위 경로를 명시합니다.
- 다른 저장소를 대상으로 지정하지 않습니다.

## 2. 저장소 성격

- 저장소의 용도를 한두 문장으로 작성합니다.
- 예외가 필요한 배경을 작성합니다.

전역 규칙과 다른 처리가 필요한 이유를 여기에 남깁니다. 배경이 기록되지 않으면 이후에 예외의 타당성을 검토할 수 없습니다.

## 3. 유지하는 전역 규칙

| 전역 규칙                   | 유지 | 예외 | 비고 |
|-----------------------------|------|------|------|
| `work-rules`                | ✅   |      |      |
| `STYLE.md` 표 정렬·문체     | ✅   |      |      |
| `readme-template` 푸터·배지 | ✅   |      |      |
| `git-commit-rule`           | ✅   |      |      |
| `md-link-check`             | ✅   |      |      |
| `code-review`               | ✅   |      |      |
| `testing-guide`             | ✅   |      |      |
| `python-script-template`    | ✅   |      |      |
| `bash-script-template`      | ✅   |      |      |

- 위 표는 자주 조정되는 항목만 나열한 예시입니다. 대상 저장소에 맞게 행을 추가하거나 제거합니다.
- 예외가 있는 항목은 `유지` 열을 비우고 `예외` 열에 `✅`를 표시한 뒤, 4장에 상세를 작성합니다.
- 표에 없는 전역 규칙은 모두 그대로 적용됩니다.

유지하는 규칙을 명시적으로 나열합니다. 예외만 기록하면 나머지 규칙의 적용 여부가 불명확해집니다.

## 4. 저장소 전용 예외

| 대상 전역 규칙 | 예외 내용          | 사유               |
|----------------|--------------------|--------------------|
| `<skill-name>` | 적용하지 않는 항목 | 예외가 필요한 이유 |

각 예외를 아래 형식으로 작성합니다.

```markdown
### <대상 전역 규칙> 예외

전역 `<skill-name>` 규칙 중 다음 항목만 적용하지 않습니다.

- 적용하지 않는 항목
- 적용하지 않는 항목

그 외 `<skill-name>` 규칙은 그대로 적용합니다.

사유: 예외가 필요한 이유를 작성합니다.
```

### 기술 범위

- 전역 규칙 중 특정 항목의 비활성화만 기술합니다.
- 전역 규칙 전체를 재정의하지 않습니다.
- 사용자의 명시적 지시보다 우선한다고 선언하지 않습니다.
- 안전 예외 항목(비가역 작업, 자격증명 취급, 권한 변경, 영향 범위 확대)은 무력화할 수 없습니다.

예외가 전역 규칙 대부분에 걸치면 저장소 분리 또는 전역 규칙 자체의 수정을 먼저 검토합니다.

## 5. 검증

이 저장소에서 변경 후 실행할 검증 명령을 작성합니다.

```bash
# 대상 저장소에 맞는 검증 명령을 작성합니다.
```

- [ ] 문법·정적 검사 통과.
- [ ] 링크·스타일 검사 통과.
- [ ] 비밀정보 검사 통과.
- [ ] 예외로 기술한 항목만 전역 규칙과 다르게 동작하는지 확인.
- [ ] 예외 목록에 없는 전역 규칙이 그대로 적용되는지 확인.

검사 도구가 이 저장소에 없으면 그 사실을 명시하고 대체 검증 방법을 작성합니다.

변경 유형이 여러 가지이고 각각 다른 검증이 필요하면 `.governance/verification.md`로 분리합니다. 작성 시 [VERIFICATION 템플릿](verification_template.md)을 사용합니다.

## 6. 기록 금지 항목

`.governance/`는 저장소와 함께 배포되므로 공개 범위를 저장소 공개 범위와 동일하게 취급합니다.

| 항목                                   | 확인 |
|----------------------------------------|------|
| 내부 IP, 호스트명, 사용자명, 개인 경로 | [ ]  |
| API key, token, password, SSH key      | [ ]  |
| 실제 인프라 구성값과 접속 정보         | [ ]  |
| 운영 환경의 상태·장애·접속 기록        | [ ]  |
| 다른 저장소에 적용되는 규칙            | [ ]  |

환경 종속 정보가 필요하면 `.governance/`가 아니라 접근이 제한된 별도 운영 문서에서 관리합니다.

## 7. 개정 이력

| 날짜         | 변경                         | 재검토 시점            |
|--------------|------------------------------|------------------------|
| `YYYY-MM-DD` | 예외 신설 내용을 작성합니다. | `YYYY-MM-DD` 또는 조건 |

- 예외를 추가·변경·제거할 때마다 한 행을 남깁니다.
- 재검토 시점을 함께 기록합니다. 날짜 또는 조건 형태로 작성합니다.

예외는 한 번 만들면 유지되기 쉽습니다. 재검토 시점을 남기지 않으면 도입 배경이 사라진
뒤에도 예외가 남습니다. 재검토 결과 예외가 계속 필요하면 그 판단을 이 표에 추가합니다.

## 작성 예시

아래는 푸터만 예외로 두는 저장소의 작성 예시입니다.

```markdown
# Zircon Repository Governance

## 1. 적용 범위

<repository-root>/**

## 2. 저장소 성격

외부 공개를 전제하지 않는 내부 프로젝트 저장소입니다. GitHub 통계 배지와
저작권 푸터가 문서 목적에 맞지 않아 해당 항목만 예외로 둡니다.

## 3. 유지하는 전역 규칙

| 전역 규칙                   | 유지 | 예외 | 비고                  |
|-----------------------------|------|------|-----------------------|
| work-rules                  | O    |      |                       |
| STYLE.md 표 정렬·문체        | O    |      |                       |
| readme-template 푸터·배지    |      | O    | 4장 참고              |
| git-commit-rule             | O    |      |                       |
| md-link-check               | O    |      |                       |

## 4. 저장소 전용 예외

### readme-template 예외

전역 readme-template 규칙 중 다음 항목만 적용하지 않습니다.

- 통계 섹션과 GitHub 배지
- 작성일, 마지막 업데이트
- 저작권 푸터

그 외 readme-template 규칙은 그대로 적용합니다.

사유: 외부 공개를 전제하지 않아 배지와 저작권 표기가 불필요합니다.
```
