# TODO Template

앞으로 수행할 작업을 `TODO.md`에 기록할 때 사용합니다. 문서별 역할은 [문서 운영 정책](../documentation_policy.md)에서 정의합니다.

🟡 이 템플릿 파일 하단의 푸터는 템플릿 자체에 적용된 것입니다. 복사한 문서의 푸터는 대상 저장소의 규칙을 따릅니다. 푸터를 금지하는 저장소에서는 푸터를 제거하고, 날짜는 복사한 날짜로 갱신합니다.

## 1. 사용 방법

```bash
cp templates/todo_template.md <target>/TODO.md
```

복사 후 이 `사용 방법` 섹션과 4장 작성 규칙을 제거하고, 목차를 실제 섹션에 맞춰 갱신합니다.

작업 범위가 넓으면 영역별로 섹션을 나눕니다. 단일 영역이면 3장만 남기고 섹션 구분 없이 사용합니다.

## 2. 우선순위 기준

| 우선순위 | 기준                                           | 처리 시점          |
|----------|------------------------------------------------|--------------------|
| 높음     | 이미 문제가 발생했거나 방치 시 악화되는 항목   | 다음 작업으로 착수 |
| 보통     | 현재 동작하지만 확장 시 문제가 되는 항목       | 일정 확보 시 착수  |
| 낮음     | 개선하면 좋으나 현재 문제를 일으키지 않는 항목 | 여유 시 착수       |

우선순위는 작업 난이도가 아니라 방치 비용을 기준으로 정합니다. 쉬운 작업을 높음으로 올리지 않습니다.

## 3. 작업 항목

### 높음

- [ ] 작업 내용을 작성합니다.
      - 배경: 왜 필요한지 작성합니다.
      - 확인: 완료를 판단할 기준을 작성합니다.

### 보통

- [ ] 작업 내용을 작성합니다.
      - 배경: 왜 필요한지 작성합니다.

### 낮음

- [ ] 작업 내용을 작성합니다.

## 4. 작성 규칙

- 미완료 항목만 유지합니다. 완료 항목은 제거하고 `CHANGELOG.md`에 기록합니다.
- 항목마다 완료 판단 기준을 남깁니다. 기준이 없으면 완료 여부를 판정할 수 없습니다.
- 발견 경위가 있으면 함께 적습니다. 나중에 타당성을 재검토할 수 있습니다.
- 원인 분석이 필요한 문제는 `ISSUE.md`로 분리하고 여기서는 링크만 남깁니다.
- 세 단계 이상의 복합 작업은 `PLAN.md`로 분리합니다.
- 비가역 작업이 포함된 항목은 그 사실을 명시합니다.
- 개인 경로, 내부 IP, 자격증명은 기록하지 않습니다.

### 완료 처리 방식

기본은 항목을 제거하고 `CHANGELOG.md`로 옮기는 것입니다. 다만 세션 간 맥락 보존이
필요한 저장소는 완료 항목을 `[x]`로 남길 수 있습니다. 이 예외는 해당 저장소의
`.governance/GOVERNANCE.md`에 기록합니다.

### 파일명 주의

루트 `.md-style-check.toml`의 `exclude_files`에 `TODO.md`가 파일명 기준으로 등록되어
있으면, 하위 디렉토리의 `TODO.md`도 스타일 검사에서 제외됩니다. 하위 디렉토리에
작업 문서를 둘 때는 `<범위>_todo.md` 형태의 파일명을 사용하면 검사 대상이 됩니다.
