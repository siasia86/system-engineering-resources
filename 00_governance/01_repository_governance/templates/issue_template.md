# ISSUE Template

재현 절차나 원인 분석이 필요한 문제를 `ISSUE.md`에 기록할 때 사용합니다. 문서별 역할은 [문서 운영 정책](../documentation_policy.md)에서 정의합니다.

단순 작업은 `TODO.md`, 세 단계 이상의 복합 작업은 `PLAN.md`를 사용합니다. 이 문서는 원인이 불명확한 문제에 사용합니다.

🟡 이 템플릿 파일 하단의 푸터는 템플릿 자체에 적용된 것입니다. 복사한 문서의 푸터는 대상 저장소의 규칙을 따릅니다. 푸터를 금지하는 저장소에서는 푸터를 제거하고, 날짜는 복사한 날짜로 갱신합니다.

## 1. 요약

- 제목:
- 발견일: `YYYY-MM-DD`
- 상태: `open`
- 우선순위: `low` / `medium` / `high`
- 발견 경위: 어떤 작업 중에 발견했는지 작성합니다.

### 상태 값

| 상태            | 의미                             |
|-----------------|----------------------------------|
| `open`          | 확인됨, 원인 분석 전             |
| `investigating` | 원인 분석 진행 중                |
| `resolved`      | 해결 및 검증 완료                |
| `wontfix`       | 해결하지 않기로 결정 (사유 필수) |

## 2. 영향

- 영향을 받는 문서·스크립트·환경을 작성합니다.
- 보안 또는 데이터 손실 영향이 있으면 명시합니다.
- 영향 범위가 확인되지 않았으면 미확인으로 표시합니다.

## 3. 재현

```text
재현 명령과 기대 결과를 작성합니다.
```

- 재현율을 작성합니다. 항상 재현되는지, 조건부인지 구분합니다.
- 재현되지 않으면 그 사실과 확인한 조건을 기록합니다.

## 4. 원인

- 확인된 원인을 작성합니다.
- 확인 방법을 함께 작성합니다. 어떤 명령·로그로 확인했는지 남깁니다.
- 미확인 내용은 추정으로 표시하지 않고 미확인 상태로 남깁니다.

## 5. 임시 조치

- 원인 해결 전에 적용한 완화 조치를 작성합니다.
- 임시 조치임을 명시하고, 해제 조건을 함께 작성합니다.
- 임시 조치가 없으면 `해당 없음`으로 기록합니다.

임시 조치를 기록하지 않으면 나중에 원인이 해결된 뒤에도 조치가 방치됩니다.

## 6. 해결

- [ ] 해결 방법을 작성합니다.
- [ ] 관련 `TODO.md` 또는 `PLAN.md`를 갱신합니다.
- [ ] 5장 임시 조치를 해제합니다.

비가역 작업이 포함되면 실행 직전에 승인을 받습니다.

## 7. 검증

```bash
# 수정 후 실행한 검증 명령을 작성합니다.
```

- [ ] 재현되지 않음.
- [ ] 회귀 검사 통과.
- [ ] `CHANGELOG.md` 기록 여부 확인.

## 8. 재발 방지

- 같은 문제가 다시 발생하지 않도록 할 조치를 작성합니다.
- 검사 도구로 자동 검출할 수 있으면 그 방법을 작성합니다.
- 규칙·정책 보완이 필요하면 해당 문서와 항목을 작성합니다.
- 재발 방지 조치가 불필요하면 그 판단 근거를 작성합니다.

문제를 고치는 것과 재발을 막는 것은 별개입니다. 검사 도구가 놓친 결함이라면 도구 개선 항목을 `TODO.md`에 추가합니다.
