## 1. 문서 역할

| 문서                   | 기록 대상                      | 유지 원칙                          |
|------------------------|--------------------------------|------------------------------------|
| `.governance/ISSUE.md` | 재현과 원인 분석이 필요한 문제 | 증상·영향·원인·해결을 기록합니다.  |
| `.governance/TODO.md`  | 앞으로 수행할 작업             | 우선순위와 작업 범위를 관리합니다. |
| `.governance/PLAN.md`  | 현재 수행 중인 복합 작업       | 단계와 검증 기준을 기록합니다.     |
| `CHANGELOG.md`         | 완료된 변경                    | 완료된 작업만 기록합니다.          |

신규 저장소는 다음 기본 문서를 `.governance/` 아래에 생성합니다.

- `GOVERNANCE.md`: 저장소 성격과 적용 규칙
- `ISSUE.md`: 현재 이슈가 없으면 `활성 이슈 없음`으로 유지
- `TODO.md`: 현재 작업이 없으면 `미완료 항목 없음`으로 유지
- `PLAN.md`: 현재 복합 작업이 없으면 `활성 계획 없음`으로 유지

기존 저장소는 migration 전까지 루트 `ISSUE.md`, `TODO.md`, `PLAN.md`를 legacy 위치로 허용합니다. 새 문서를 추가하거나 해당 문서를 크게 수정할 때 `.governance/`로 이관합니다.

이 문서는 문서의 역할과 생명주기를 정의합니다. 규칙이 충돌할 때의 적용 순서는
[저장소 규칙 우선순위 정책](governance_precedence.md)이 정의합니다. 두 문서는 서로
대체하지 않으며, 이 문서의 문서화·기록 규칙도 우선순위 정책의 적용 순서를 따릅니다.

## 2. 작업 흐름

```text
문제 발견
  v
.governance/ISSUE.md 기록
  v
.governance/TODO.md 작업 등록
  v
.governance/PLAN.md 단계 수립
  v
구현 및 검증
  v
CHANGELOG.md 완료 기록
```

단순한 문서 수정은 `.governance/TODO.md`와 `CHANGELOG.md`를 사용합니다. 원인 분석이 필요하면 `.governance/ISSUE.md`에 기록하고, 세 단계 이상의 작업이면 `.governance/PLAN.md`로 관리합니다.

## 3. 갱신 규칙

- 문서 작성·수정 시 본문은 합니다체로 작성합니다.
- 외부 기술 참조는 공식 출처를 우선합니다.
- `_reference/` 내용은 공식 문서와 직접 대조한 뒤 사용합니다.
- 완료된 `.governance/TODO.md` 항목은 삭제하고 `CHANGELOG.md`에 기록합니다.
- `CHANGELOG.md`의 카테고리와 버전 번호 기준은 해당 문서의 `변경 사항 기록 방법` 절을 따릅니다.
- 한 릴리스 안에서 중간 상태는 기록하지 않습니다. 최종 결과만 남깁니다.
- `.governance/PLAN.md`의 완료 단계는 제거하거나 완료 상태로 정리합니다.
- 개인 경로, 내부 IP, 자격증명은 저장소에 기록하지 않습니다. 판단 기준은 아래 3.1을 따릅니다.

### 3.1 경로와 식별자 기록 기준

| 구분                    | 예                                      | 판단      |
|-------------------------|-----------------------------------------|-----------|
| 사용자 홈이 포함된 경로 | `/home/<user>/.venv`                    | 기록 금지 |
| 계정@호스트             | `<user>@10.200.101.101`                 | 기록 금지 |
| 내부 IP                 | `10.200.90.155`                         | 기록 금지 |
| 자격증명                | 키, 토큰, 패스워드                      | 기록 금지 |
| 도구·저장소 경로        | `/root/32_system-engineering-resources` | 허용      |
| 시스템 디렉터리         | `/root/`, `/opt/`, `/etc/`              | 허용      |
| 작성자 표기             | `created by <author>`, 저작권 표기      | 허용      |

판단 기준은 **환경 종속성**입니다. 사용자명이 들어간 경로는 다른 사용자 환경에서 성립하지 않으므로 기록하지 않습니다. 도구가 설치된 저장소 경로는 동작에 필요하고 사용자와 무관하므로 허용합니다.

사용자명을 경로가 아닌 작성자 표기로 쓰는 것은 허용합니다. 저작권 표기와 스크립트 헤더의 작성자명이 이에 해당합니다.

- 환경 종속 값이 필요하면 환경변수나 placeholder 로 두고 실제 값은 접근이 제한된 문서에서 관리합니다.
- 실행 설정 미러(`02_kiro/`)에도 같은 기준을 적용합니다. 동작에 필요한 도구 경로는 유지하고, 사용자명·IP·자격증명은 기록하지 않습니다.
- 실행하지 않는 원문 보존본은 미러 대상에서 제외합니다. 보존을 위해 내용을 고칠 수 없으므로 공개 범위에서 빼는 방식으로 처리합니다.
- 문서 구조를 변경하면 루트 `README.md`의 링크와 inventory를 함께 확인합니다.

## 4. 검증 기준

```bash
sia-md-link-check .
sia-md-heading-check .
sia-md-style-check .
sia-readme-inventory-check README.md
git diff --check
```

검증 실패를 기존 예외로 숨기지 않습니다. 예외가 필요하면 검사기 설정과 정책 문서에 사유를 함께 기록합니다.

### 4.1 검사 예외 기록

검사 예외는 실행 설정과 근거 기록을 분리하되, 두 곳을 함께 갱신합니다.

- `.md-style-check.toml` 또는 `.md-heading-check.toml`은 검사기가 실제로 읽는 실행 설정입니다.
- `.governance/GOVERNANCE.md` 또는 `exceptions.md`는 예외의 대상, 사유, 영향 범위와 재검토
  시점을 기록합니다. `.governance/`의 문장만으로는 검사 동작이 바뀌지 않습니다.
- `skip_checks`는 저장소 전체에 적용되므로 도구 결함이나 변경할 수 없는 외부 원본처럼
  파일 전체에 공통으로 적용되는 경우에만 사용합니다. 기본값은 빈 배열로 유지합니다.
- 한 파일의 특정 검사만 제외할 때는 검사기가 지원하는 `file_skip` 또는 파일별 제외
  구조를 사용합니다. 파일 전체 제외(`exclude_files`)는 모든 검사 공백을 만들므로 먼저
  항목 단위 제외 가능성을 검토합니다.
- 예외를 추가하기 전에 실제 이슈를 측정하고, 정상 동작을 확인한 뒤에도 재검토 시점을
  기록합니다. 통과 결과를 만들기 위한 무분별한 `skip_checks` 사용은 허용하지 않습니다.
