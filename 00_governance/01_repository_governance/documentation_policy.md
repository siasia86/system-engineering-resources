## 1. 문서 역할

| 문서           | 기록 대상                      | 유지 원칙                          |
|----------------|--------------------------------|------------------------------------|
| `ISSUE.md`     | 재현과 원인 분석이 필요한 문제 | 증상·영향·원인·해결을 기록합니다.  |
| `TODO.md`      | 앞으로 수행할 작업             | 우선순위와 작업 범위를 관리합니다. |
| `PLAN.md`      | 현재 수행 중인 복합 작업       | 단계와 검증 기준을 기록합니다.     |
| `CHANGELOG.md` | 완료된 변경                    | 완료된 작업만 기록합니다.          |

문서가 없는 상태를 억지로 만들지 않습니다. 활성 이슈나 복합 작업이 있을 때만 `ISSUE.md` 또는 `PLAN.md`를 생성합니다.

## 2. 작업 흐름

```text
문제 발견
  v
ISSUE.md 기록
  v
TODO.md 작업 등록
  v
PLAN.md 단계 수립
  v
구현 및 검증
  v
CHANGELOG.md 완료 기록
```

단순한 문서 수정은 `TODO.md`와 `CHANGELOG.md`만 사용합니다. 원인 분석이 필요하면 `ISSUE.md`를 추가하고, 세 단계 이상의 작업이면 `PLAN.md`를 추가합니다.

## 3. 갱신 규칙

- 문서 작성·수정 시 본문은 합니다체로 작성합니다.
- 외부 기술 참조는 공식 출처를 우선합니다.
- `_reference/` 내용은 공식 문서와 직접 대조한 뒤 사용합니다.
- 완료된 `TODO.md` 항목은 삭제하고 `CHANGELOG.md`에 기록합니다.
- `PLAN.md`의 완료 단계는 제거하거나 완료 상태로 정리합니다.
- 개인 경로, 내부 IP, 자격증명은 저장소에 기록하지 않습니다.
- 문서 구조를 변경하면 루트 `README.md`의 링크와 inventory를 함께 확인합니다.

## 4. 검증 기준

```bash
sudo python3 md-link-check.py .
sudo python3 md-heading-check.py .
sudo python3 md-style-check.py .
sudo python3 readme_inventory_check.py README.md
git diff --check
```

검증 실패를 기존 예외로 숨기지 않습니다. 예외가 필요하면 검사기 설정과 정책 문서에 사유를 함께 기록합니다.
