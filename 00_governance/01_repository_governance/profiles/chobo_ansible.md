# chobo_ansible Repository Profile

공통 repository governance를 Ansible 학습·자동화 저장소에 적용할 때 사용하는 저장소별 profile입니다. 실제 인프라 환경과 운영 접속 정보는 기록하지 않고, 문서 역할과 생명주기 예외만 정의합니다.

## 1. 적용 범위

이 profile은 Ansible, Docker, Vagrant, Packer, Terraform, Kubernetes 학습·자동화 자료를 관리하는 저장소의 문서 운영에 적용합니다.

공통 문서 정책은 [`../documentation_policy.md`](../documentation_policy.md)를 우선 적용합니다. 이 문서에 명시된 항목만 저장소별 예외로 인정합니다.

## 2. 문서 역할

| 문서           | 역할                                     | 생명주기                                        |
|----------------|------------------------------------------|-------------------------------------------------|
| `README.md`    | 프로젝트 설명과 운영 Runbook             | 현재 구조와 실행 방법을 유지합니다.             |
| `TODO.md`      | 전체 미완료 작업과 완료 이력             | 미완료 항목을 관리하고 완료 이력을 보존합니다.  |
| `TODO2.md`     | 검증 보고서·우선순위·후속 작업 분석      | 분석 결과와 미해결 항목을 정리합니다.           |
| `PLAN.md`      | 하위 프로젝트별 계획·이슈·검증·롤백 기록 | 진행 중 작업과 해결 이력을 유지합니다.          |
| `CHANGELOG.md` | 완료된 변경과 검증 결과                  | 날짜·작업 영역 기준으로 완료 기록을 보존합니다. |
| `ISSUE.md`     | 저장소 전역 이슈                         | 별도 추적이 필요한 전역 문제에만 생성합니다.    |

## 3. 저장소별 예외

- 하위 프로젝트별 `PLAN.md`를 허용합니다.
- `PLAN.md` 안에 이슈의 증상·원인·해결·검증·롤백 정보를 기록할 수 있습니다.
- 완료된 PLAN 항목은 세션 간 컨텍스트 보존을 위해 삭제하지 않고 완료 상태로 표시할 수 있습니다.
- `TODO.md`의 완료 이력 표를 유지할 수 있습니다. 완료 변경은 `CHANGELOG.md`에도 기록합니다.
- `TODO2.md`는 일반 backlog가 아니라 검증·분석 보고서로 취급합니다.
- 단순 문서 수정은 별도 `PLAN.md`나 `ISSUE.md`를 만들지 않고 `CHANGELOG.md`에 기록합니다.
- 저장소 전역에서 재현·영향 분석이 필요한 문제는 `ISSUE.md`로 분리합니다.

## 4. 검증 기준

- Markdown 문서의 링크·목차·표·푸터 검사를 실행합니다.
- Ansible 변경은 syntax check와 가능한 경우 lint·Molecule 검사를 실행합니다.
- Docker Compose 변경은 config 렌더링과 대상 서비스 검사를 실행합니다.
- Terraform 변경은 format·validate·plan 검사를 실행합니다.
- Packer·Vagrant·Kubernetes 변경은 해당 도구의 dry-run 또는 구문 검사를 우선 실행합니다.
- 보안 관련 변경은 비밀정보 검사와 로그 출력 여부를 확인합니다.
- 변경 전후 `git diff --check`를 실행하고 결과를 작업 문서 또는 `CHANGELOG.md`에 기록합니다.

## 5. 금지 범위

이 profile에는 다음 정보를 기록하지 않습니다.

- 내부 IP, 호스트명, 사용자명, 개인 경로.
- SSH 키 경로, 비밀번호, token, API key와 같은 자격증명.
- 실제 Docker·Hyper-V·VM 구성값과 접속 정보.
- 운영 환경의 상태·장애·접속 기록.
- 실행 환경에 종속된 개인 설정과 세션 상태.

실제 환경 정보가 필요한 경우에도 profile이 아니라 해당 저장소의 접근 제한된 운영 문서에서 별도 관리합니다.
