# Tool Mirror Sync Policy

AI 도구 실행 환경 자료와 저장소 공개 미러 사이의 동기화 기준을 정의합니다. 현재 등록된 미러는 `~/.kiro/`와 `00_governance/02_kiro/`입니다. `03_claude/`는 활성화 조건을 충족하기 전까지 예약 영역으로 유지합니다.

## 1. 원본과 미러

- Kiro 실행 원본은 `~/.kiro/`입니다.
- Kiro 저장소 공개 미러는 `00_governance/02_kiro/`입니다.
- Kiro 동기화 방향은 `~/.kiro/`에서 `00_governance/02_kiro/`로만 제한합니다.
- Claude 등 새 도구를 추가할 때는 원본 경로와 미러 경로를 별도로 정의합니다.
- 원본 경로와 공개 허용 목록을 확정하기 전에는 새 도구를 등록하거나 동기화하지 않습니다.
- 저장소 내용을 실행 환경으로 자동 역동기화하지 않습니다.
- 동기화 결과는 자동 commit하지 않고 diff를 검토한 뒤 반영합니다.

### 새 도구 미러 활성화 조건

새 도구의 미러는 다음 조건을 모두 충족할 때만 활성화합니다. 하나라도 확인할 수
없으면 예약 영역으로 유지하며 manifest, 동기화 스크립트와 실제 원본 파일을 추가하지
않습니다.

1. **원본 경로**: 실행 환경에서 확인 가능한 source root를 확정합니다.
2. **allowlist**: 공개할 파일을 목록으로 고정하고, 목록에 없는 파일은 동기화하지 않습니다.
3. **제외 범위**: 개인 설정, 세션 상태, 내부 환경 정보와 자격증명을 측정해 제외합니다.
4. **동기화 방향**: 원본에서 공개 미러로만 흐르는 단방향 절차와 dry-run을 준비합니다.
5. **검증**: 동기화 전후의 diff, 비밀정보 검사와 Markdown 검사를 실행할 방법을 확인합니다.
6. **관리 책임**: 원본 변경, allowlist 변경과 예외 재검토의 담당 범위를 기록합니다.

Claude는 현재 원본 경로와 allowlist를 확정하지 않았으므로 위 조건을 충족하지 않습니다.

## 2. 허용 범위

| 대상            | 조건                                                  |
|-----------------|-------------------------------------------------------|
| 일반 Skill 문서 | 개인 정보와 환경 종속 경로를 제거한 경우              |
| Hook 설명서     | 실행 스크립트가 아닌 공개 가능한 설명만 포함하는 경우 |
| Markdown 규칙   | 저장소에서 재사용 가능한 규칙만 포함하는 경우         |
| 템플릿          | 자격증명과 개인 환경 정보가 없는 경우                 |

허용 파일은 홈 실행 환경의 manifest에 등록합니다. 현재 Kiro 실행 source of truth는
`/home/siasia/.kiro/manifests/kiro_files.txt`이며, 중앙 mirror 사본은
[`../02_kiro/manifests/kiro_files.txt`](../02_kiro/manifests/kiro_files.txt)입니다.

## 3. 제외 범위

다음 내용은 공개 미러로 동기화하지 않습니다.

- `memory.md`의 개인 기억과 내부 환경 정보.
- 내부 IP, 호스트명, 사용자명, 개인 경로.
- API key, token, password, SSH key와 같은 자격증명.
- 개인용 prompt와 system context.
- `settings/`의 개인 설정과 세션 상태 파일.
- private repository 원문과 운영 정보.
- 실행하지 않는 원문 보존본. 보존 목적상 내용을 고칠 수 없으므로 미러 대상에서 제외합니다.
- 미러 쪽에서만 필요한 파일. `.gitignore` 는 저장소 보호 장치이므로 원본에 두지 않고 저장소에서 직접 관리합니다.

경로와 식별자 기록 기준은 [문서 운영 정책](documentation_policy.md) §3.1을 따릅니다. 도구 경로는 동작에 필요하므로 유지하고, 사용자명·IP·자격증명은 미러에 남기지 않습니다.

### 미러 파일을 저장소에서 수정하지 않습니다

미러는 원본의 사본이므로 저장소에서 수정하면 다음 동기화가 되돌립니다. 봇 커밋도 예외가 아닙니다.

🟡 날짜 갱신 workflow 가 `02_kiro/` 의 `마지막 업데이트` 를 고쳐 동기화와 서로 덮어쓰는 문제가 있었습니다(2026-08-27 수정). workflow 에서 `02_kiro/` 를 제외했습니다. 미러 문서의 날짜는 원본에서 갱신한 뒤 동기화합니다.

## 4. 동기화 절차

1. 도구별 동기화 허용 목록에 등록된 대상만 선택합니다.
2. dry-run으로 추가·수정·삭제 예정 항목을 확인합니다.
3. 개인 정보와 비밀정보를 검색합니다.
4. 해당 도구 미러의 diff를 검토합니다.
5. Markdown 및 링크 검사를 실행합니다.
6. 검증을 통과한 변경만 commit합니다.

`--delete` 옵션은 기본으로 사용하지 않습니다. 삭제가 필요한 경우 대상과 영향을 먼저 확인합니다.

## 5. 검증

```bash
"$HOME/.kiro/02_home-sjyun-kiro.sh" \
  --target central \
  --dry-run
sudo gitleaks detect --source . --no-banner
sia-md-link-check 00_governance/02_kiro/
sia-md-style-check .
```

동기화 manifest가 없는 파일은 동기화 대상에 포함하지 않습니다. `memory.md`,
`memory_private.md`, `.local/`, `settings/`, `sessions/`는 manifest와 rsync에서
이중으로 제외합니다. 미러 원본의 형식 보존이 필요한 경우에도 공개 가능 여부를
먼저 검토합니다.

### 미러 문서의 검사 범위

미러 문서도 Markdown 검사 대상입니다. 디렉토리 단위로 제외하지 않습니다.

| 검사 항목                      | 미러 적용 | 사유                      |
|--------------------------------|-----------|---------------------------|
| 표 정렬, 문체, 링크, 헤딩 구조 | 적용      | 미러도 저장소 문서로 읽힘 |
| 푸터, H1 개수, 다이어그램 한글 | 제외      | 도구 원본 형식을 보존     |

항목 단위 제외는 `md-style-check.py` 의 `KIRO_SKIP` 이 경로(`/.kiro/`, `/02_kiro/`)를
인식하여 처리합니다. 미러를 `exclude_dirs` 로 통째 제외하면 표 정렬·문체 검사가 함께
빠져 검사 공백이 생깁니다.
