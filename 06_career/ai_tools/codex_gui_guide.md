## 1. GUI가 적합한 경우

GUI는 설치 없이 계획·조사·문서화 작업을 시작하거나, 여러 대화와 장시간 작업을 한 화면에서 관리할 때 적합합니다. 로컬 shell 명령, 저장소의 실제 test 실행, 세밀한 파일 권한 제어가 중심이면 [CLI Linux 가이드](codex_cli_linux_guide.md)를 사용합니다. 열린 파일·선택 코드와 함께 짧게 반복하려면 [IDE 가이드](codex_ide_guide.md)가 더 자연스럽습니다.

공통 권한·인증·비용 원칙은 [Codex 공통 개념](codex_concepts.md)을 먼저 확인합니다.

## 2. 웹에서 작업 시작

1. ChatGPT 웹에서 Codex를 열고, 목적에 맞는 project 또는 대화를 선택합니다.
2. 목표, 변경 범위, 제약, 검증 기준을 한 요청에 함께 적습니다.
3. 파일 또는 저장소 연결을 허용하기 전에 접근 범위와 민감정보 포함 여부를 확인합니다.
4. 장시간 작업은 중간 결과와 다음 결정을 확인할 수 있도록 단계별 보고를 요청합니다.
5. 결과를 적용하기 전 diff, test 결과, 생성된 산출물을 직접 검토합니다.

GUI 대화에서 얻은 계획을 로컬에서 실행할 때는 계획 전문을 그대로 신뢰하기보다 현재 branch와 작업공간 상태를 다시 확인합니다. 웹 검색이나 외부 연결 결과도 출처·시점·권한을 검토합니다.

## 3. 데스크톱 앱 사용

데스크톱 앱은 로컬 프로젝트와 파일을 다루거나, 빠른 대화와 장시간 작업을 같은 환경에서 관리할 때 적합합니다. 프로젝트를 열기 전에는 작업 대상 디렉토리와 계정·조직 정책을 확인하고, 필요하지 않은 상위 경로 또는 비밀 파일이 포함된 폴더를 공유하지 않습니다.

로컬 변경이 발생하는 작업은 다음 순서를 권장합니다.

1. 작업 전 `git status`와 기준 commit을 확인합니다.
2. 읽기·분석 범위로 시작해 수정 대상과 실행 명령을 합의합니다.
3. 변경 후 diff와 프로젝트 test를 검토합니다.
4. commit·push·배포 같은 외부 상태 변경은 별도 승인과 팀 절차를 적용합니다.

Linux, Windows, macOS의 지원 환경과 설치 방식은 수시로 바뀔 수 있으므로 OpenAI 공식 문서의 Desktop app 항목을 기준으로 확인합니다.

## 4. 결과 검토와 인수

GUI에서 완료 보고를 받으면 다음 정보를 남겨 다른 인터페이스에서도 작업을 이어갈 수 있게 합니다.

- 해결하려던 문제와 선택한 접근 방식
- 변경된 파일 또는 생성된 산출물
- 실행한 검증과 통과·실패 결과
- 아직 검증하지 않은 가정과 후속 작업
- 되돌릴 기준 commit 또는 rollback 절차

로컬 코드 변경은 GUI의 서술만으로 완료 처리하지 않습니다. IDE 또는 CLI에서 실제 diff와 test 로그를 확인하고, reviewer가 재현 가능한 형태로 결과를 인수합니다.

## 5. 보안 점검

- 화면 공유·첨부·프롬프트에 API key, access token, 개인식별정보, 운영 로그 원문을 넣지 않습니다.
- cloud 환경 또는 저장소 연결은 필요한 repository·branch·권한으로 제한합니다.
- 결과가 외부 서비스 호출, 배포, 삭제를 제안하면 대상과 영향 범위를 별도로 확인합니다.
- 계정 사용량과 API 사용량은 별개일 수 있으므로 사용량 화면과 Platform billing을 각각 확인합니다.
