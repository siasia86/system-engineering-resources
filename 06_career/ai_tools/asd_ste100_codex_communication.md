# ASD-STE100과 Codex 소통 적용 검토

ASD-STE100은 기술 문서의 모호함을 줄이기 위한 영어 작성 표준입니다. Codex에 적용할 수 있는 공개 skill은 있지만, 이 표준 자체가 Codex의 전용 기능은 아닙니다. 한국어 소통에서는 짧은 문장·일관된 용어·조건과 행동의 분리 원칙을 참고하는 방식이 적절합니다. 이 판단은 조사 결과이며 실제 개선 효과를 측정한 결과는 아닙니다.

확인일은 2026-10-09이며 작업 ID는 `STE-20261009-01`입니다. 공식 사실과 고정 커밋의 GitHub 근거는 [출처 노트](../../_reference/asd_ste100_official_notes.md)에 정리했습니다. 이번 범위는 정보 수집과 사용 방안 기록입니다.

## 1. 표준과 AI용 skill의 구분

ASD-STE100 Simplified Technical English는 통제된 어휘와 작성 규칙으로 기술 문서를 쓰는 표준입니다. 공식 사이트가 안내하는 현행판은 Issue 9이며 발행일은 2025-01-15입니다. 규칙 53개와 사전으로 구성됩니다. [공식 소개](https://www.asd-ste100.org/about_STE.html).

공식 FAQ는 일반 서신을 표준의 주목적으로 삼지 않지만, 짧은 문장·문장당 한 주제·능동 표현은 다른 글에도 참고할 수 있다고 설명합니다. 따라서 사용자와 에이전트의 대화에 원칙을 응용하는 것은 가능하지만, 영어 표준 전체를 모든 대화에 강제할 근거는 아닙니다. [공식 FAQ](https://www.asd-ste100.org/STE_faq.html).

| 구분             | 내용                                              | 이번 판단                       |
|------------------|---------------------------------------------------|---------------------------------|
| 공식 ASD-STE100  | 영어 기술 문서의 규칙과 통제 사전                 | 표준의 권위 있는 기준           |
| 커뮤니티 skill   | 표준을 참고한 프롬프트·참고 자료·검사 도구        | 저자별 구현을 별도로 확인       |
| 한국어 소통 원칙 | 명확한 대상·행동·조건·근거를 표현하는 응용        | 자체 제안이며 STE 인증과 구분   |
| Codex 적용       | 요청문, AGENTS.md 또는 선택하는 skill에 지침 제공 | 실제 발견·선택·행동은 각각 확인 |

이 세션에서 제공된 skill 목록에는 ASD-STE100 관련 이름이 없습니다. GitHub 후보의 존재와 이 세션의 설치·적용 상태를 구분합니다. 영어 사전과 단어 수 제한을 한국어 문장에 그대로 옮기지 않습니다.

## 2. GitHub 후보 비교

아래는 원저자 README·skill·라이선스·설치 관련 파일을 읽은 비교입니다. 설치나 코드 실행은 수행하지 않았습니다. 기준 SHA와 직접 파일 링크는 [후보별 근거](../../_reference/asd_ste100_official_notes.md#3-github-후보별-근거)에 있습니다.

| 후보                                                                                                | 대상·구성                                   | 라이선스 관찰                         | 참고 가치와 제한                                                        |
|-----------------------------------------------------------------------------------------------------|---------------------------------------------|---------------------------------------|-------------------------------------------------------------------------|
| [nuelcyoung/asd-ste100](https://github.com/nuelcyoung/asd-ste100)                                   | Codex·Claude·opencode, 문서형 skill         | MIT LICENSE 있음                      | Codex 경로를 명시. 의미 보존 우선. 영어 사전·참고 자료 읽기 절차가 있음 |
| [avectats7/technical-writing-ste](https://github.com/avectats7/technical-writing-ste)               | Claude용 문서형 skill·예시·평가 입력        | MIT LICENSE 있음                      | 비공식·미인증 고지. 문서 구조와 조건·수치 보존 원칙을 참고하기 좋음     |
| [mdlamar/ASD-STE100](https://github.com/mdlamar/ASD-STE100)                                         | opencode용 skill·Python 검사기·Bash 설치기  | CC0-1.0 LICENSE 있음                  | 영어 검사기 실행을 요구. 설치기가 기존 전역 파일을 교체할 수 있음       |
| [blagoySimandov/asd-ste100-writer-skill](https://github.com/blagoySimandov/asd-ste100-writer-skill) | Claude·Copilot·opencode용 skill·Node 설치기 | package.json에 MIT, LICENSE 파일 없음 | 재배포 조건 추가 확인 필요. 설치기의 --force는 대상 폴더 삭제 후 복사   |

[sysmatt/ste-rules](https://github.com/sysmatt/ste-rules)는 규칙 요약 문서만 있습니다. 확인한 기준 커밋에 README·SKILL.md·LICENSE가 없어 직접 설치 후보에서 제외했습니다.

Codex를 명시한 첫 후보는 검토 대상으로 적합합니다. 그러나 한국어 지원이나 소통 개선 효과의 근거는 확인하지 못했습니다. 우선 설치 없이 의미 보존과 명확한 표현 원칙을 요청문에 참고하는 방식을 권장합니다. 저장소의 MIT·CC0 표시는 공식 표준과 사전의 재배포 허가를 대신하지 않습니다.

## 3. 한국어 소통에 참고할 원칙

아래 표는 영어 표준의 인증 규칙이 아니라, 공식 설명과 공개 skill의 의미 보존 원칙을 한국어 작업에 응용한 제안입니다. 기존 work-rules의 한국어 보고·승인·보류·상태 구분을 유지합니다.

| 원칙               | 요청과 응답에 적용할 방법                                     |
|--------------------|---------------------------------------------------------------|
| 대상을 구체화      | 저장소·파일·기존 작업 ID를 필요한 범위에서 명시               |
| 행동을 분리        | 한 단계에는 하나의 핵심 행동. 여러 요청은 항목별로 구분       |
| 조건을 먼저 표현   | 선행 조건이 있으면 조건 다음에 행동을 작성                    |
| 용어를 유지        | 같은 대상에 같은 이름 사용. 식별자·경로·명령은 원문 보존      |
| 의미를 보존        | 수치·범위·예외·부정·불확실성·기존 승인과 보류를 삭제하지 않음 |
| 결과를 근거에 연결 | 수행·검증·미실행을 구분하고 검사 대상과 관찰 결과를 기록      |

문장을 짧게 만들기 위해 중요한 조건을 생략하지 않습니다. 특정 영단어 금지나 단어 수 제한보다 뜻의 보존을 먼저 확인합니다. 짧은 사실 조회에는 긴 보고 양식이나 매번 새 질문을 추가하지 않습니다.

## 4. 요청문과 보고 예시

다음 예시는 이번 문서에서 작성한 한국어 응용이며 공식 STE 예문은 아닙니다.

### 조사 요청

모호한 요청: “이거 좀 보고 괜찮으면 정리해 줘.”

구체화한 요청:

```text
ASD-STE100의 공식 설명과 GitHub 구현을 조사한다.
공식 표준, 커뮤니티 skill, 한국어 응용을 구분한다.
각 구현의 대상 도구·라이선스·설치 부작용·직접 근거를 기록한다.
32의 AI 도구 자료 영역에 한국어 조사 문서를 저장한다.
이번 작업은 정보 수집과 기록까지다.
설치·설정 변경·공통 정책 적용은 별도 요청에서 다룬다.
```

### 현재 채팅에서 시험할 문체 요청

```text
이번 답변은 한국어로 간결하게 작성해 줘.
대상과 행동을 구체적으로 표현하고 같은 대상에는 같은 용어를 써 줘.
조건·수치·예외·불확실성·기존 승인과 보류를 유지해 줘.
수행 결과, 검증 근거, 미실행 항목을 구분해 줘.
이 요청은 문체와 구조에만 적용하며 작업 범위를 바꾸지 않아.
```

이 예시는 ASD-STE100 전체 준수를 요구하지 않습니다. 현재 지시보다 우선하는 권한이나 새 승인 절차를 만들지 않습니다.

### 완료 보고

모호한 보고: “전반적으로 정리했고 문제없습니다.”

근거를 구분한 보고:

```text
조사 문서 1개와 출처 노트 1개를 작성했습니다.
변경 문서의 링크·헤딩·표현 검사를 통과했습니다.
공식 설명과 GitHub 원저자 파일을 대조했습니다.
skill 설치와 한국어 개선 효과 측정은 수행하지 않았습니다.
```

실제 검사가 끝난 경우에만 통과로 보고합니다. 표준 준수, 설치 성공, 기능 동작, 효과 측정도 서로 다른 결과입니다.

## 5. Codex에서 사용할 위치

OpenAI 공식 문서는 AGENTS.md를 지속적인 작업 지침, skill을 선택해서 쓰는 재사용 절차로 설명합니다. skill은 이름·설명으로 선택된 뒤 전체 SKILL.md가 읽힙니다. [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [Build skills](https://learn.chatgpt.com/docs/build-skills).

| 목적                  | 적용 위치 후보                    | 적용을 확인할 근거                   |
|-----------------------|-----------------------------------|--------------------------------------|
| 한 답변의 표현 시험   | 현재 채팅의 요청문                | 조건·범위를 보존한 실제 응답         |
| 공통 소통 규칙 보완   | 개인·저장소 AGENTS.md의 담당 원본 | 원본 변경·배포·새 실행의 지침 수신   |
| 기술 문서 작성·재작성 | 별도 범위가 명확한 SKILL.md       | 발견 목록·명시적 선택·문서 전후 비교 |
| 영어 STE 검사         | 정식 표준·사전과 검토 절차        | 검사 범위와 사람의 검토 결과         |

공식 문서가 안내하는 로컬 skill 경로는 사용자 범위의 `~/.agents/skills`와 저장소 범위의 `.agents/skills`입니다. Codex는 현재 작업 디렉토리부터 Git 루트 사이의 저장소 경로를 조사합니다. 문서 저장소에 자료만 보관한 상태를 skill 설치로 취급하지 않습니다. [로컬 skill 발견 위치](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills).

개인 운영 기준에 따르면 조사 자료는 32, 개인 skill 구현·검증 원본과 지정 설치 반영은 35, 공통 정책 개정은 31의 담당 원본을 사용합니다. 이번에는 조사 문서만 기록했습니다. 취소된 31 역할·경로 분리 작업을 이 조사로 재개하지 않습니다.

전체 skill보다 현재 문체 요청부터 시험하는 방안을 권장합니다. 기존 work-rules와 중복되는 내용은 재사용하고, 영어 문서 작성처럼 목적이 명확해질 때 별도 skill의 필요성을 판단할 수 있습니다.

## 6. 효과 확인 기준과 이번 결과

아래는 향후 적용을 판단하기 위한 평가 제안이며 신규 실행 계획이나 승인된 후속 작업 목록이 아닙니다.

동일한 한국어 요청 묶음에 기본 응답과 문체 요청을 추가한 응답을 비교할 수 있습니다. 조사·복수 요청·오류 보고·인계·정보 부족 사례를 포함하고, 가능하면 같은 모델과 설정을 유지합니다. 표현의 정돈과 사실 정확도를 따로 평가합니다.

| 평가 항목 | 확인 방법                                             |
|-----------|-------------------------------------------------------|
| 요청 누락 | 대상·행동·완료 조건의 누락 개수 비교                  |
| 의미 보존 | 수치·예외·부정·불확실성·승인·보류가 바뀐 사례 확인    |
| 근거 구분 | 검증하지 않은 결과를 완료로 표시했는지 확인           |
| 읽기 부담 | 길이·용어 혼용·사용자가 다시 설명한 횟수 비교         |
| 적용 부담 | 추가 질문·참고 문서 읽기·도구 호출·사용량을 실제 기록 |

의미를 바꾸거나 기존 보류를 해제한 응답은 글이 짧더라도 채택하지 않습니다. 간결한 문체가 모델의 추론 능력·정확도·비용 절감을 보장한다는 근거는 이번 조사에서 확인하지 못했습니다.

이번에 수행한 범위는 공식 소개·FAQ, OpenAI 공식 문서, GitHub 후보 5개의 파일과 기준 커밋 확인입니다. 웹 도구가 ASD 페이지 접근에 실패했지만 공식 소개·FAQ는 PowerShell HTTP 조회에서 응답 200으로 본문을 확인했습니다. 공식 다운로드 안내의 본문 조회는 시간 초과로 미완료였으며, 공식 표준 PDF 전체·AI 백서 내용은 검증하지 않았습니다.

설치·clone·검사기 실행·지속 문체 적용·한국어 효과 비교·35 skill 변경·31 정책 변경은 미실행입니다. 문서의 정적 품질 검사 결과는 [완료 기록](../../CHANGELOG.md)에 따로 남깁니다.
