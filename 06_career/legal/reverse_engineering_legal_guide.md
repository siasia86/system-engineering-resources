# 리버스 엔지니어링 법적 기준 가이드
<!-- reference: _reference/저작권법_law.go.kr.txt, _reference/정보통신망법_law.go.kr.txt, _reference/17USC1201_law.cornell.edu.txt, _reference/37CFR201.40_ecfr.gov.txt -->

AI 에이전트 기반 리버스 엔지니어링 도구(예: [morluto/rea](https://github.com/morluto/rea))가 널리 쓰이면서, 바이너리·앱 분석을 누구나 쉽게 시작할 수 있게 되었습니다. 이 문서는 분석을 시작하기 전에 확인할 **도구 라이선스, 분석 대상의 계약 조건, 법률상 허용 범위**를 정리합니다.

🟡 이 문서는 법령 원문을 정리한 학습 자료이며 법률 자문이 아닙니다. 실제 분석이 허용되는지는 대상·목적·계약에 따라 달라지므로 사내 법무팀이나 전문가에게 확인합니다. 법령 원문은 2026-10-15에 확인했습니다.

## 1. 세 가지 확인 대상

리버스 엔지니어링이 허용되는지는 하나의 기준으로 정해지지 않습니다. 다음 세 가지를 따로 확인해야 합니다.

| 대상                  | 확인할 것                                    | 예 (rea 사용 시)                                  |
|-----------------------|----------------------------------------------|---------------------------------------------------|
| 분석 도구의 라이선스  | 도구를 쓰고 배포할 때의 조건                 | rea는 MIT, Ghidra는 Apache-2.0, Hopper·IDA는 상용 |
| 분석 대상의 계약 조건 | EULA·이용약관의 역분석 금지 조항             | 분석하려는 앱·SDK·게임의 약관                     |
| 법률                  | 역분석 허용 요건, 기술적 보호조치, 무단 접근 | 저작권법, 정보통신망법, 해외 법률                 |

- 도구가 MIT 라이선스라는 것은 **도구를 자유롭게 쓸 수 있다**는 뜻일 뿐, **무엇이든 분석해도 된다**는 뜻이 아닙니다.
- rea도 [DISCLAIMER](https://github.com/morluto/rea/blob/main/DISCLAIMER.md)에서 용도를 보안 연구, 악성코드 분석, CTF·교육, 상호운용성, 본인 소유이거나 허가받은 소프트웨어 분석으로 한정합니다. DRM·라이선스 검사·안티치트 우회와 게임 치트 개발은 지원하지 않는다고 밝히고 있습니다.

## 2. 한국 저작권법

저작권법(법률 제21336호, 2026-08-11 시행)에서 리버스 엔지니어링과 직접 관련된 조항입니다.

### 프로그램코드역분석 (제2조 제34호, 제101조의4)

**정의**: 독립적으로 만든 프로그램과 다른 프로그램의 **호환에 필요한 정보**를 얻기 위해 프로그램 코드를 복제하거나 변환하는 것입니다.

**허용 요건** (제101조의4 제1항): 다음을 모두 충족하면 저작권자의 허락 없이 역분석할 수 있습니다.

| 요건      | 내용                                                            |
|-----------|-----------------------------------------------------------------|
| 이용 권한 | 정당한 권한으로 프로그램을 이용하는 자 또는 그의 허락을 받은 자 |
| 필요성    | 호환에 필요한 정보를 쉽게 얻을 수 없고, 획득이 불가피한 경우    |
| 범위      | 해당 프로그램의 호환에 필요한 부분으로 한정                     |

**얻은 정보의 이용 금지** (제101조의4 제2항):

- 호환 목적 외의 다른 목적으로 이용하거나 제3자에게 제공하는 경우
- 대상 프로그램과 표현이 실질적으로 유사한 프로그램을 개발·제작·판매하거나 저작권 침해에 이용하는 경우

### 조사·연구·시험 목적 복제 (제101조의3 제1항 제6호)

정당한 권한으로 프로그램을 이용 중인 사람은 프로그램의 기초가 되는 **아이디어와 원리를 확인**하기 위해 기능을 조사·연구·시험할 목적으로 복제할 수 있습니다. 단, 저작재산권자의 이익을 부당하게 해치는 경우는 제외됩니다(제1항 단서).

### 기술적 보호조치 무력화 금지 (제104조의2)

암호화·접근 통제·라이선스 검사처럼 저작물 접근을 막는 **기술적 보호조치**(제2조 제28호 가목)를 정당한 권한 없이 제거·변경·우회하는 것은 금지됩니다. 역분석이 허용되는 경우라도 보호조치를 무력화하는 순간 이 조항이 별도로 적용됩니다.

| 예외 (제1항)                                                           | 호  |
|------------------------------------------------------------------------|-----|
| 정당하게 취득한 복제물로 암호 기술의 결함·취약점 연구 (허락 노력 필요) | 1호 |
| 개인 식별 정보를 몰래 수집·유포하는 기능을 확인하고 무력화             | 3호 |
| 정당한 권한으로 쓰는 프로그램의 호환을 위해 필요한 범위의 역분석       | 6호 |
| 정당한 권한을 가진 자가 오로지 컴퓨터·정보통신망 보안성 검사·조사·보정 | 7호 |
| 문화체육관광부장관 고시 (효력 3년)                                     | 8호 |

- **도구 배포도 금지 대상입니다**(제2항). 무력화를 목적으로 홍보되거나, 무력화 외에는 상업적 용도가 제한적이거나, 무력화를 주된 목적으로 만든 장치·프로그램·서비스를 제조·배포·판매·제공하면 안 됩니다. 분석 스크립트나 패치 도구를 공개할 때 확인합니다.
- **책임**: 업으로 또는 영리 목적으로 위반하면 3년 이하 징역 또는 3천만원 이하 벌금(제136조 제3항 제3호의3)입니다. 권리자는 침해 정지·예방과 손해배상을 청구할 수 있습니다(제104조의8). 기존 [DRM 가이드](drm_guide.md)의 제104조의2 설명도 함께 참고합니다.

## 3. 정보통신망법

로컬 바이너리가 아니라 **서버·온라인 서비스**를 분석할 때는 정보통신망법이 적용됩니다.

| 조항         | 금지 내용                                                           |
|--------------|---------------------------------------------------------------------|
| 제48조 제1항 | 정당한 접근권한 없이 또는 허용된 권한을 넘어 정보통신망에 침입      |
| 제48조 제3항 | 대량 신호·부정한 명령으로 정보통신망에 장애를 일으키는 행위         |
| 제48조 제4항 | 정상적인 보호·인증 절차를 우회해 접근하게 하는 프로그램의 설치·유포 |

- 제48조 제1항 위반(침입)은 5년 이하 징역 또는 5천만원 이하 벌금입니다(제71조 제1항 제11호).
- 클라이언트 앱을 분석해 찾은 API를 **허가 없이 실제 서버에 호출**하는 것은 저작권법의 역분석 허용과 별개로 이 조항의 문제가 될 수 있습니다. 서버 쪽 시험은 서비스 운영자의 서면 허가(버그 바운티 범위 포함)가 있을 때만 합니다.

## 4. 미국 DMCA

미국 서비스·제품을 분석하거나 결과를 미국에 공개할 때 참고합니다.

### 17 U.S.C. §1201

| 조항      | 내용                                                                                                               |
|-----------|--------------------------------------------------------------------------------------------------------------------|
| (a)(1)(A) | 저작물 접근을 효과적으로 통제하는 기술적 조치의 우회 금지                                                          |
| (f)       | 상호운용성 예외: 적법하게 사용 권한을 얻은 자가 독립 프로그램의 상호운용성에 필요한 요소를 식별·분석하기 위한 우회 |
| (g)       | 암호 연구 예외: 적법 취득, 연구에 필요, 사전 허락 노력, 다른 법률 위반 아님                                        |
| (j)       | 보안 테스트 예외: 소유자·운영자의 허가를 받은 선의의 보안 결함 시험·조사·수정                                      |

### 3년 주기 예외 (37 CFR §201.40)

미국 저작권청은 3년마다 §1201 예외를 갱신합니다. 가장 최근 개정은 2024-10-28(89 FR 85446)입니다.

- (b)(18) **선의의 보안 연구**: 적법하게 취득한 기기, 또는 소유자·운영자의 허가를 받은 시스템에서 보안 결함을 시험·조사·수정하기 위한 우회를 허용합니다. 사람과 공공에 피해가 없도록 설계된 환경이어야 하고, 얻은 정보는 주로 보안·안전 향상에 써야 합니다.
- 같은 조항은 이 예외가 **컴퓨터사기남용법(CFAA) 등 다른 법률의 책임까지 면제하지 않는다**고 명시합니다.

🟡 EU는 소프트웨어 지침(Directive 2009/24/EC) 제6조에서 상호운용성 목적의 디컴파일을 조건부로 허용하는 것으로 알려져 있습니다. 이번 작성 시에는 EUR-Lex 원문을 받지 못해 원문과 대조하지 않았습니다. EU 대상 분석 시 원문을 직접 확인합니다.

## 5. 계약과 도구 라이선스

### 분석 대상의 EULA·이용약관

- 많은 상용 소프트웨어·게임·SDK의 약관에는 역분석·디컴파일 금지 조항이 있습니다.
- 법률상 예외가 있더라도 약관 위반은 계약 책임(계정 정지, 손해배상 청구 등)의 문제로 따로 남을 수 있습니다. 약관 조항과 법률 예외의 관계는 국가마다 다르므로 법무 검토 대상입니다.
- 회사 업무로 분석하는 경우, 업무 중 만든 분석 스크립트와 결과물의 귀속은 [IP 귀속 가이드](ip_ownership_guide.md)를 참고합니다.

### 분석 도구의 라이선스

| 도구   | 라이선스   | 업무 사용 시 확인                                   |
|--------|------------|-----------------------------------------------------|
| rea    | MIT        | 저작권 고지 유지 (코드를 가져다 쓰거나 재배포할 때) |
| Ghidra | Apache-2.0 | 고지·NOTICE 유지, 특허 조항                         |
| Hopper | 상용       | 개인·상업 라이선스 구분, 데모 모드 제한             |
| IDA    | 상용       | 에디션별 상업 사용 허용 범위                        |

라이선스별 의무와 호환성은 [라이선스 가이드](../../license_guide.md)를 참고합니다. AI 에이전트가 분석 도구를 대신 실행할 때도 그 행위의 책임은 에이전트를 지시한 사용자에게 있습니다.

## 6. 상황별 판단

| 상황                                        | 판단 방향             | 근거·주의                                             |
|---------------------------------------------|-----------------------|-------------------------------------------------------|
| 자사 프로그램·본인이 만든 바이너리 디버깅   | 일반적으로 가능       | 권리자 본인. 외부 라이브러리 라이선스는 별도 확인     |
| 악성코드 샘플 분석 (격리 환경)              | 일반적으로 가능       | 악성코드 전달·유포 금지(정보통신망법 제48조 제2항)    |
| 구매한 SDK와 자사 프로그램의 호환 정보 확보 | 요건 충족 시 가능     | 제101조의4 요건, 얻은 정보의 목적 외 이용 금지        |
| 자사 시스템의 보안 점검                     | 권한 범위 안에서 가능 | 제104조의2 제1항 제7호, 점검 범위를 서면으로 정함     |
| 타사 서비스 취약점 연구                     | 허가 범위 안에서만    | 버그 바운티·서면 허가 범위, 정보통신망법 제48조       |
| DRM·라이선스 검사·안티치트 우회             | 피해야 함             | 제104조의2 무력화·도구 배포 금지, rea도 지원하지 않음 |
| 게임 클라이언트 변조·치트 제작              | 피해야 함             | 약관 위반, 서비스 방해, 저작권 침해 소지              |
| 분석 결과로 유사 프로그램 개발·판매         | 피해야 함             | 제101조의4 제2항 제2호                                |
| CTF·교육용 문제 바이너리                    | 가능                  | 출제자가 분석을 허락한 대상                           |

## 7. 작업 체크리스트

### 시작 전

- [ ] 분석 대상의 소유자가 누구인지, 내가 정당한 이용 권한을 가졌는지 확인
- [ ] 대상의 EULA·이용약관에서 역분석·디컴파일 조항 확인
- [ ] 분석 목적을 한 문장으로 기록 (호환, 보안 점검, 악성코드 분석 등)
- [ ] 타사 시스템이면 서면 허가 또는 버그 바운티 범위 확보
- [ ] 분석 도구의 라이선스가 업무 사용을 허용하는지 확인 (특히 상용 도구)

### 작업 중

- [ ] 격리된 환경(VM·컨테이너)에서 실행하고 실제 서비스 서버에 요청하지 않음
- [ ] 기술적 보호조치를 무력화해야 하는 단계가 나오면 중단하고 예외 해당 여부 검토
- [ ] AI 에이전트에 분석을 맡길 때 대상·범위·금지 행위를 지시문에 명시

### 작업 후

- [ ] 얻은 정보를 목적 범위 안에서만 사용하고 제3자에게 넘기지 않음
- [ ] 취약점은 공개 전에 개발사·운영자에게 먼저 알림 (coordinated disclosure)
- [ ] 분석 스크립트·패치 도구를 공개하기 전에 무력화 도구 배포 금지(제104조의2 제2항) 해당 여부 확인
