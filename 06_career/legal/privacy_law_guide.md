## 1. 개요

개인정보 보호와 관련된 국내 법령은 크게 3개 축으로 구성됩니다.

| 법령            | 소관 기관 | 주요 대상                            |
|-----------------|-----------|--------------------------------------|
| 개인정보 보호법 | 개보위    | 모든 개인정보처리자 (공공·민간 전체) |
| 정보통신망법    | 방통위    | 정보통신서비스 제공자                |
| 신용정보법      | 금융위    | 금융기관·신용정보업자                |

🟡 2020년 데이터 3법 개정(시행 2020-08-05) 이후 정보통신망법의 개인정보 관련 조항 상당수가 개인정보 보호법으로 이관되었습니다. 현재는 개보위가 민간·공공 통합 감독 기관입니다.

## 3. 개인정보 개념

### 정의 (개인정보 보호법 제2조 제1호)

> 살아 있는 개인에 관한 정보로서 성명, 주민등록번호 및 영상 등을 통하여 개인을 알아볼 수 있는 정보

핵심 판단 기준: **"개인을 알아볼 수 있는가"**

### 개인정보 해당 여부

| 정보 유형           | 개인정보 해당 | 비고                                 |
|---------------------|---------------|--------------------------------------|
| 이름 + 주민번호     | ✅            | 명백한 개인정보                      |
| 이메일 주소         | ✅            | 단독으로도 해당                      |
| 휴대폰 번호         | ✅            | 단독으로도 해당                      |
| IP 주소             | ✅            | 다른 정보와 결합 시 식별 가능        |
| 닉네임              | 🟡            | 결합 여부에 따라 판단                |
| 쿠키 ID             | 🟡            | 결합 여부에 따라 판단                |
| 접속 로그 (IP+시간) | ✅            | 결합으로 개인 식별 가능              |
| 암호화된 개인정보   | 🟡            | 복호화 가능 시 개인정보 해당         |
| CI/DI               | ✅            | 본인 식별 정보                       |
| 법인 정보           | ❌            | 개인정보 아님 (법인은 정보주체 아님) |

> 간접 식별: 해당 정보만으로는 특정인을 알 수 없더라도, 다른 정보와 결합하면 식별 가능한 경우 개인정보에 해당합니다.

### "처리"의 범위 (개인정보 보호법 제2조 제2호)

수집, 생성, 연계, 연동, 기록, 저장, 보유, 가공, 편집, **검색**, 출력, 정정, 복구, **이용**, 제공, 공개, 파기 — **조회·열람도 처리에 포함**됩니다.

## 4. 개인정보처리자와 취급자

### 개념 구분

| 구분            | 주체 단위      | 법적 지위                                |
|-----------------|----------------|------------------------------------------|
| 개인정보처리자  | 법인·기관·단체 | 법적 책임 주체 (과징금·과태료 부과 대상) |
| 개인정보 취급자 | 임직원·부서    | 처리자의 지휘·감독 하에 처리하는 자      |
| 수탁자          | 외부 업체      | 처리를 위탁받은 제3자                    |

### 개인정보처리자 판단 기준

| 기준                    | 내용                                 |
|-------------------------|--------------------------------------|
| 업무를 목적으로         | 사업·업무 목적 (개인 사용 제외)      |
| 개인정보파일을 운용     | 체계적으로 정리·관리하는 집합물      |
| 스스로 또는 타인을 통해 | 직접 처리 또는 위탁 처리             |
| 주체                    | 법인·기관·단체·개인 (부서 단위 아님) |

### 취급자 해당 기준

"업무상 개인정보에 **접근 가능한 자**" — 실제 열람 여부 무관

```
(주)OO게임즈  ← 개인정보처리자 (법적 책임 주체)
      │
      ├── 인프라팀   ← 취급자 (서버·DB 인프라 관리)
      ├── DB팀       ← 취급자 (DB 직접 접근·조회)
      ├── 웹팀       ← 취급자 (수집·처리 로직 구현)
      └── CS팀       ← 취급자 (고객정보 조회)
```

### 책임 구조

| 상황                    | 책임 주체                                   |
|-------------------------|---------------------------------------------|
| 개인정보 유출 시 과징금 | 회사 (개인정보처리자)                       |
| 취급자 실수로 유출      | 회사 외부 책임, 취급자는 내부 징계·민사소송 |
| 취급자 고의 유출        | 회사 + 개인 형사처벌 동시 가능              |

## 5. CI와 DI

### 개념

| 구분 | 명칭             | 길이   | 특징                                           |
|------|------------------|--------|------------------------------------------------|
| CI   | 연계정보         | 88자리 | 동일인이면 서비스 달라도 동일값 — 본인 식별    |
| DI   | 중복가입확인정보 | 64자리 | 동일 서비스 내 중복가입 확인용 — 서비스별 상이 |

> CI(Connecting Information): 주민번호를 대체하여 본인인증 기관이 발급하는 88자리 식별값입니다. 동일인이면 서비스가 달라도 동일한 CI가 발급되어 중복가입 방지·본인확인에 사용됩니다.

> DI(Duplication Information): 동일 서비스 내 중복가입 확인용 64자리 값입니다. CI와 달리 서비스별로 다른 값이 발급됩니다.

### CI 처리 구조

```
이용자
  │
  └── 본인인증 요청
        │
        ▼
  본인인증 기관 (PASS/KCB/NICE 등)   ← CI 생성 주체
        │
        └── CI/DI 생성 후 게임사에 전달
              │
              ▼
        게임사 (개인정보처리자)        ← CI 수령·저장·이용
```

### CI 관련 주체별 법적 지위

| 주체                         | 법적 지위      | 역할                            |
|------------------------------|----------------|---------------------------------|
| 본인인증 기관 (NICE 등)      | 개인정보처리자 | CI 생성·발급 (자체 책임)        |
| 게임사                       | 개인정보처리자 | CI 수령·저장·이용 (독립 처리자) |
| 본인인증 SDK 연동 업체       | 수탁자         | 인증 모듈 제공·기술 지원        |
| AWS 등 클라우드 (CI DB 저장) | 수탁자         | 위탁 계약(DPA) 필요             |

### CI가 없는 경우

| 조건                             | CI 보유 여부 |
|----------------------------------|--------------|
| 본인인증 없는 이메일 가입만 운영 | ❌ 없음      |
| 소셜 로그인만 제공 (Google 등)   | ❌ 없음      |
| 전체이용가 게임 + 결제 없음      | ❌ 없음      |
| 청소년 이용 가능 게임            | ✅ 필수      |
| 결제 기능 있음                   | ✅ 필수      |

### SSO (Google Auth 등) 수집 정보

Google OAuth 등 소셜 로그인은 CI를 생성하지 않습니다. 단, 아래 정보는 개인정보에 해당합니다.

| 수신 정보       | 개인정보 해당 |
|-----------------|---------------|
| 이메일 주소     | ✅            |
| 이름            | ✅            |
| 프로필 사진 URL | ✅            |
| Google 계정 ID  | ✅            |
| 접속 IP         | ✅            |

| 항목           | 내용                                                  |
|----------------|-------------------------------------------------------|

### DB팀 특화 사항

| 항목              | 내용                                           |
|-------------------|------------------------------------------------|

## 8. CPO와 CISO

### CPO (개인정보 보호책임자)

| 항목          | 내용                                          |
|---------------|-----------------------------------------------|
| 근거          | 개인정보 보호법 제31조                        |
| 지정 의무     | 모든 개인정보처리자 (규모 무관, 필수)         |
| 미지정 시     | 과태료 1천만원 이하                           |

| 중소기업 특례 | 5인 미만 소상공인은 대표자 겸직 가능          |

> CPO(Chief Privacy Officer): 개인정보 보호법 제31조에 따라 개인정보처리자가 지정해야 하는 개인정보 보호 총괄 책임자입니다.

> CISO(Chief Information Security Officer): 정보보호 최고책임자로, 정보보호 정책 수립·보안 사고 대응·취약점 관리를 총괄합니다.

```
침해사고 발생
```

### 과징금 투자 감경제도 (2026.3.10. 신설)

개인정보 보호를 위해 사전 투자한 사실이 인정되면 과징금을 최대 **40%** 감경합니다.

> 개인정보 보호법 제64조의2 제6항 — 보호위원회는 개인정보 보호를 위하여 예산·인력·설비·장치 등을 투자하고 운영하는 등 대통령령으로 정하는 사유가 있는 경우에는 과징금을 감경한다. 다만, 개인정보처리자의 고의 또는 중대한 과실로 위반행위를 한 경우는 제외한다.

감경 요건 (위반행위 발생 전 직전 3개 사업연도 기준):

| 요건 | 내용                                                                        |
|------|-----------------------------------------------------------------------------|
| 1    | 개인정보 보호를 위하여 투입된 예산·인력·설비·장치 등의 투자 규모 및 지속성  |
| 2    | 사업주·대표자·CPO의 역할, 조직 및 인력 구성 등 개인정보 보호 체계 운영 수준 |
| 3    | 개인정보 안전성 확보 조치 강화를 위한 추가 노력                             |

| 항목        | 내용                                                        |
|-------------|-------------------------------------------------------------|
| 최대 감경률 | **40%** (기준금액의 100분의 40 이하)                        |
| 감경 제외   | 고의 또는 중대한 과실에 의한 위반행위                       |
| 고려 기간   | 위반행위 직전 3개 사업연도 (예외적으로 해당 연도 포함 가능) |

정보주체가 자신의 개인정보를 다른 곳으로 이동시킬 수 있는 권리입니다.

| 구분            | 명칭            | 내용                                           |
|-----------------|-----------------|------------------------------------------------|
| 제3자전송요구권 | 마이데이터 전송 | 본인 개인정보를 **지정한 제3자**에게 전송 요구 |
| 본인전송요구권  | 개인정보 이동   | 본인 개인정보를 **본인**에게 직접 전송 요구    |

> 마이데이터(MyData): 정보주체가 자신의 데이터를 직접 통제하고 원하는 기관에 전송할 수 있는 권리 기반 서비스입니다. 금융 분야에서 먼저 시행되었고 의료·통신·에너지로 확대되었습니다.
