**핵심 순서**: `_reference 생성` → `INDEX.md 갱신` → `.md 작성` (역순 금지)

**Hard Stop**: _reference 없이 .md 작성 시작한 걸 인지하면:
1. 즉시 중단 (문장 중간이어도)
2. `_reference` 파일 먼저 생성 (공식 출처 스캔)
3. `INDEX.md` 갱신
4. `.md` 작성 재개

"빨리 하려고" / "나중에 만들자" 는 **절대 불가**.

## 26. TODO 배치

### 배치 크기
- 기본 3개, 마지막 1~2개여도 Pre/Post 출력 의무 (생략 불가)
- 넘버링: 세션 간 연속 (Batch 1, 2, 3...)

### 실행 전 (Pre-execution Brief)
코드블록으로 출력:
- Step 1: _reference 매핑 (기존/신규/N/A + 사유)
- Step 2~6: 작성 → 정렬 → style-check → fact-check → TODO 갱신
- 신규 _reference 있으면 Step 1 완료까지 Step 2 차단

### 실행 후 (Post-execution Summary)
표로 출력:
- 문서별 md-style-check + fact-check 결과
- 수정 있으면 괄호 기재
- README/CHANGELOG: "deferred to final batch" 또는 "updated"

### fact-check 회차
| 대상                           | 회차                   |
|--------------------------------|------------------------|
| _reference 파일                | 2회 (URL + 내용 대조)  |
| .md (TODO §4, _reference 있음) | 3회                    |
| .md (TODO §4, _reference 없음) | 2회 (Round 1 생략)     |
| .md (기타)                     | 1회 (md-style-check만) |

### 중단/재개
1. TODO.md 상태(✅ /⬜) 확인
2. 다음 ⬜부터 Pre-brief 출력 후 재개
3. 부분 완료 허용 (✅ 건너뛰고 나머지만)

### fact-check 실패 시
1. .md 즉시 수정 → 해당 Round부터 재검증
2. 2회 반복 → 근본 원인 분석:
   - .md가 _reference를 잘못 인용 → .md 수정 (대부분)
   - _reference 자체가 의심됨 → 공식 출처 재대조 **후에만** 수정 가능
   - _reference 수정 시 필수: 공식 출처 확인 + `last_checked` 갱신 + INDEX.md 동기화
3. 추론 기반 _reference 수정 **절대 금지**
