# ioping - 디스크 I/O 지연시간 측정 도구

`ioping`은 `ping`처럼 파일시스템과 저장장치의 I/O 응답시간을 측정하는 도구입니다. 작은 요청의 지연시간, 대용량 요청의 처리량, 캐시 사용 여부에 따른 차이를 빠르게 확인할 수 있습니다.

> Latency(지연시간): I/O 요청을 보낸 시점부터 처리가 완료될 때까지 걸리는 시간입니다. 평균값뿐 아니라 최대값과 편차도 함께 확인해야 순간적인 저장장치 지연을 파악할 수 있습니다.

## 1. 개요

`ioping`은 디렉토리, 파일 또는 블록 디바이스를 대상으로 I/O 요청을 생성하고 지연시간과 처리량을 실시간으로 표시합니다.

주요 용도는 다음과 같습니다.

- 파일시스템의 평균·최대 I/O 지연시간 확인.
- 작은 블록과 큰 블록 요청의 특성 비교.
- 랜덤 접근과 순차 접근 성능 비교.
- 페이지 캐시와 Direct I/O 결과 비교.
- 저장장치 응답시간 변동성 확인.

`ioping`은 정교한 부하 테스트보다는 빠른 상태 점검과 지연시간 확인에 적합합니다.

## 2. 설치 및 확인

배포판 패키지 관리자를 사용하여 설치합니다.

```bash
# Ubuntu/Debian
sudo apt-get install ioping

# RHEL/Fedora 계열
sudo dnf install ioping
```

설치 후 버전과 옵션을 확인합니다.

```bash
ioping --version
ioping --help
man ioping
```

배포판과 패키지 버전에 따라 지원 옵션이 다를 수 있으므로, 문서화하거나 자동화하기 전에 실제 시스템의 `ioping --help`를 확인합니다.

## 3. 기본 사용법

현재 디렉토리가 속한 파일시스템을 기본 설정으로 측정합니다.

```bash
ioping -c 10 .
```

특정 경로를 대상으로 측정합니다.

```bash
ioping -c 10 /var
ioping -c 10 /home
ioping -c 10 /data
```

`-c`를 지정하지 않으면 기본적으로 계속 측정하므로, 단발성 확인에는 요청 횟수나 측정 시간을 지정하는 편이 안전합니다.

```bash
# 20회 측정
ioping -c 20 /data

# 30초 동안 측정
ioping -w 30s /data
```

디렉토리를 대상으로 실행하면 임시 작업 파일을 사용합니다. 읽기 측정은 일반적으로 디렉토리 경로를 대상으로 실행하는 것이 편리합니다.

## 4. 주요 옵션

| 옵션          | 긴 옵션        | 설명                                            |
|---------------|----------------|-------------------------------------------------|
| `-c count`    | `-count`       | 지정한 요청 횟수 후 종료합니다.                 |
| `-i interval` | `-interval`    | 요청 사이의 간격을 지정합니다.                  |
| `-s size`     | `-size`        | 한 번의 I/O 요청 크기를 지정합니다.             |
| `-S size`     | `-work-size`   | 측정에 사용할 작업 영역 크기를 지정합니다.      |
| `-o size`     | `-work-offset` | 작업 영역의 시작 오프셋을 지정합니다.           |
| `-w time`     | `-work-time`   | 지정한 시간 후 측정을 종료합니다.               |
| `-D`          | `-direct`      | `O_DIRECT`를 사용하여 직접 I/O를 수행합니다.    |
| `-C`          | `-cached`      | 캐시된 I/O를 사용하고 캐시 무효화를 생략합니다. |
| `-L`          | `-linear`      | 순차 접근으로 측정합니다.                       |
| `-R`          | `-rapid`       | 3초 동안 빠르게 측정합니다.                     |
| `-J`          | `-json`        | JSON 형식으로 출력합니다.                       |
| `-B`          | `-batch`       | 최종 통계를 원시 형식으로 출력합니다.           |

`-R`은 랜덤 접근 옵션이 아닙니다. `rapid` 측정 모드이며 간격을 0으로 설정하고 약 3초 동안 측정합니다. 기본 접근은 랜덤이며, 순차 접근은 `-L`로 지정합니다.

## 5. 요청 크기와 접근 패턴

`-s`는 한 번의 I/O 요청에서 처리할 데이터 크기입니다. 기본 요청 크기는 `4k`입니다.

| 요청 크기 | 특징                            | 대표적인 확인 대상               |
|-----------|---------------------------------|----------------------------------|
| `4k`      | 작은 요청, 지연시간과 IOPS 확인 | 데이터베이스, VM, 메타데이터 I/O |
| `512k`    | 중간 크기 요청, 순차 처리 비교  | 로그 및 일반 파일 읽기           |
| `1m`      | 큰 요청, 처리량 중심            | 백업, 대용량 파일, 스트리밍      |

> IOPS(Input/Output Operations Per Second): 1초 동안 처리할 수 있는 I/O 요청 수입니다. 요청 크기가 달라지면 IOPS와 처리량도 함께 달라지므로 요청 크기가 다른 결과의 평균 지연시간만 단순 비교하면 안 됩니다.

작은 요청의 랜덤 접근을 확인합니다.

```bash
ioping -D -c 20 -s 4k /data
```

큰 요청의 순차 접근을 확인합니다.

```bash
ioping -D -c 20 -s 512k -L /data
ioping -D -c 20 -s 1m -L /data
```

`-L`을 사용하면 명시적으로 `-s`를 지정하지 않은 경우 기본 요청 크기가 `256k`로 변경됩니다. 요청 크기를 직접 비교하려면 위 예시처럼 `-s`를 함께 지정합니다.

## 6. 캐시 및 I/O 모드

### Direct I/O

```bash
ioping -D -c 10 /data
```

`-D`는 `O_DIRECT`를 사용하여 페이지 캐시의 영향을 줄입니다. 저장장치에 가까운 응답시간을 확인할 때 유용하지만, 파일시스템과 저장장치의 정렬 조건에 영향을 받을 수 있습니다.

### Cached I/O

```bash
ioping -C -c 10 /data
```

`-C`는 캐시된 I/O를 사용합니다. 애플리케이션이 캐시를 통해 데이터를 읽는 상황을 확인할 때 참고할 수 있습니다.

### 쓰기 테스트

```bash
# 디렉토리 대상의 임시 파일에 쓰기
sudo ioping -W -c 10 /data
```

`-W`는 쓰기 I/O를 사용합니다. 디렉토리를 대상으로 실행하면 임시 작업 파일을 사용할 수 있지만, 일반 파일이나 블록 디바이스를 대상으로 실행하면 데이터를 손상시킬 수 있습니다.

`-G`는 읽기와 쓰기를 번갈아 수행하고, `-Y`와 `-y`는 동기화 방식의 쓰기 I/O를 지정합니다. 운영 환경에서는 쓰기 옵션을 사용하기 전에 대상 경로와 매뉴얼을 확인합니다.

## 7. 결과 해석

일반 출력에서 다음 항목을 확인합니다.

| 항목    | 의미                      |
|---------|---------------------------|
| `min`   | 측정된 최소 요청 지연시간 |
| `avg`   | 측정된 평균 요청 지연시간 |
| `max`   | 측정된 최대 요청 지연시간 |
| `mdev`  | 요청 지연시간의 표준편차  |
| `iops`  | 초당 처리된 I/O 요청 수   |
| `speed` | 초당 처리된 데이터 양     |

일반적인 해석 기준은 다음과 같습니다.

- `avg`가 낮을수록 평균 응답시간이 짧습니다.
- `max`가 높으면 순간적인 I/O 지연이 발생했을 가능성이 있습니다.
- `mdev`가 크면 응답시간 변동성이 큽니다.
- 작은 요청은 IOPS와 지연시간을 중심으로 확인합니다.
- 큰 순차 요청은 처리량과 평균 지연시간을 함께 확인합니다.

요청 크기가 다르면 결과를 직접 비교하지 않습니다. 같은 경로, 같은 접근 모드, 같은 캐시 설정으로 측정하고 지연시간·IOPS·처리량을 함께 비교합니다.

JSON 형식이 필요한 자동화에서는 다음과 같이 실행합니다.

```bash
ioping -J -c 10 /data > ioping.json
```

## 8. 실전 측정 패턴

### 기본 지연시간

```bash
ioping -c 10 /var
```

### 캐시 영향을 줄인 작은 랜덤 I/O

```bash
sudo ioping -D -c 20 -s 4k /var/lib
```

### 큰 순차 I/O

```bash
sudo ioping -D -c 20 -s 1m -L /data
```

### 빠른 탐색·처리량 확인

```bash
sudo ioping -R /data
sudo ioping -R -L /data
```

`-R`은 기본적으로 약 3초 동안 빠르게 측정합니다. `-R -L` 조합은 랜덤 탐색 대신 순차 접근에 가까운 빠른 측정을 수행합니다.

### 측정 조건 기록

비교 결과를 남길 때는 명령어와 시스템 조건을 함께 기록합니다.

```bash
{
    date --iso-8601=seconds
    findmnt -T /data
    ioping --version
    ioping -D -c 20 -s 4k /data
} | tee ioping_4k_result.txt
```

## 9. 다른 도구와 비교

| 도구       | 주된 목적                            |
|------------|--------------------------------------|
| `ioping`   | 파일시스템·저장장치 지연시간 확인    |
| `du`       | 디렉토리별 디스크 사용량 확인        |
| `iostat`   | 디스크 처리량, 사용률, 대기시간 확인 |
| `fio`      | 정교한 부하·읽기·쓰기 성능 테스트    |
| `dd`       | 단순한 순차 읽기·쓰기 처리량 확인    |
| `smartctl` | 저장장치 S.M.A.R.T. 상태 확인        |

빠른 지연시간 확인에는 `ioping`을 사용하고, 큐 깊이·읽기/쓰기 비율·블록 크기·병렬성을 통제하는 벤치마크에는 `fio`를 사용합니다.

`ioping`은 디스크 사용량을 확인하는 `du`의 대체 도구가 아닙니다. `du`는 공간 사용량을 확인하고 `ioping`은 I/O 응답 특성을 확인합니다.

## 10. 주의사항

- 운영 디스크에서는 먼저 `-c` 또는 `-w`로 측정 범위를 제한합니다.
- 캐시 사용 여부가 다르면 결과를 직접 비교하지 않습니다.
- `-D`는 일반 파일시스템 I/O와 다른 경로로 동작할 수 있습니다.
- `-W`는 일반 파일이나 블록 디바이스의 데이터를 손상시킬 수 있습니다.
- `-R`은 짧은 시간에 많은 I/O를 발생시킬 수 있습니다.
- 권한 부족으로 일부 경로를 측정하지 못하면 `sudo` 사용 여부를 확인합니다.
- 별도 마운트된 파일시스템을 구분하려면 `findmnt -T <path>`를 함께 확인합니다.
- 단일 측정값보다 동일 조건의 반복 측정과 추세를 우선합니다.

🟡 `ioping` 결과는 저장장치만의 순수한 성능이 아닙니다. 파일시스템, 커널, 페이지 캐시, 디바이스 캐시, 스토리지 네트워크, 가상화 계층의 영향을 함께 받습니다.

## 11. 요약

```text
ioping -c 10 <path>
    └── 기본 I/O 지연시간 확인

ioping -D -c 20 -s 4k <path>
    └── 캐시 영향을 줄인 작은 요청 확인

ioping -D -c 20 -s 1m -L <path>
    └── 캐시 영향을 줄인 큰 순차 요청 확인
ioping -J -c 10 <path>
    └── 자동화용 JSON 출력
```

- `-s`는 요청당 I/O 크기입니다.
- 기본 요청 크기는 `4k`입니다.
- 기본 접근은 랜덤이며, 순차 접근은 `-L`로 지정합니다.
- `-R`은 랜덤 옵션이 아니라 rapid 측정 옵션입니다.
- `-D`는 Direct I/O, `-C`는 cached I/O입니다.
- 쓰기 테스트는 대상에 따라 데이터 손상이 발생할 수 있습니다.
