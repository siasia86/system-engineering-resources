# 저장·불러오기 테스트 (Save/Load Testing)
<!-- reference: _reference/game_testing_official_notes.md -->

저장·불러오기 테스트는 게임 진행 상태를 저장하고 다시 읽어오는 과정에서 데이터의 완전성·정합성·복구 가능성을 검증하는 테스트입니다.

## 1. 개요

저장·불러오기는 정상 호출만 확인해서는 부족합니다. 저장 중 종료·네트워크 오류·스키마 변경·중복 저장·부분 데이터와 같은 조건을 함께 검증합니다.

| 검증 관점 | 질문                                                 |
|-----------|------------------------------------------------------|
| 완전성    | 필요한 진행 상태가 빠짐없이 저장되는가?              |
| 정합성    | 서로 관계있는 데이터가 같은 버전을 가리키는가?       |
| 복구성    | 중단 후 마지막 확정 상태로 복구되는가?               |
| 호환성    | 이전 형식의 데이터를 새 버전에서 읽을 수 있는가?     |
| 멱등성    | 같은 저장·불러오기를 반복해도 결과가 안정적인가?     |
| 보안      | 저장 데이터·로그·백업에 민감 정보가 노출되지 않는가? |

[⬆ 목차로 돌아가기](#목차)

## 2. 저장 대상

| 대상 영역     | 데이터 예시                       |
|---------------|-----------------------------------|
| 진행 상태     | 단계·퀘스트·업적·해금 상태        |
| 플레이어 상태 | 캐릭터·장비·설정·선택 결과        |
| 경제 상태     | 재화·보상·인벤토리·거래 결과      |
| 세션 상태     | 방·매치·작업·마지막 확정 이벤트   |
| 설정 상태     | 사용자 옵션·접근성·지역·언어      |
| 메타데이터    | 스키마 버전·저장 시각·무결성 정보 |

저장 대상과 저장하지 않아야 하는 임시 상태를 구분합니다. 임시 상태를 저장한다면 재실행 시의 복구 정책을 별도로 정의합니다.

## 3. 테스트 유형

| 유형          | 실행 조건                                | 기대 결과                         |
|---------------|------------------------------------------|-----------------------------------|
| 정상 저장     | 변경 후 정상 저장                        | 모든 필수 상태가 저장됨           |
| 정상 불러오기 | 저장된 데이터로 재실행                   | 저장 시점의 확정 상태 복원        |
| 반복 저장     | 같은 상태를 여러 번 저장                 | 중복·손상·불필요한 상태 변화 없음 |
| 저장 중 중단  | 저장 중 앱·프로세스·연결 종료            | 부분 저장을 안전하게 처리         |
| 저장소 오류   | 쓰기 실패·지연·읽기 전용                 | 오류 기록·복구·사용자 안내        |
| 이전 형식     | 이전 버전 데이터 읽기                    | 호환·마이그레이션·명확한 거부     |
| 손상 데이터   | 누락·잘못된 타입·필수 요소가 빠진 레코드 | 결과·복구·원인 자료 확인          |
| 동시 저장     | 같은 대상에 여러 저장 요청               | 충돌 정책과 최종 상태 일치        |

## 4. 중단·복구

### 복구 흐름

```text
저장 시작
   │
   ├── 저장 완료 ─────> 확정 상태 기록
   │
   ├── 연결 종료 ─────> 재시도·보류·실패 정책
   │
   ├── 앱 종료 ───────> 재실행 후 마지막 확정 상태 확인
   │
   └── 저장소 오류 ───> 오류 기록·복구 경로·사용자 안내
```

복구 테스트에서는 다음을 구분합니다.

- 마지막 확정 상태와 저장 중 임시 상태
- 클라이언트 표시와 서버·저장소의 상태
- 재시도 전후의 저장 요청 ID와 중복 여부
- 이전 데이터 복구와 새 데이터 생성의 순서
- 복구 실패 시 안전한 기본 상태와 재시도 방법

## 5. 정합성 판정

| 판정 대상   | 확인 방법                                   |
|-------------|---------------------------------------------|
| 필수 데이터 | 필드·타입·관계·기본값 확인                  |
| 진행 순서   | 저장 이벤트·버전·상태 전이 비교             |
| 중복 처리   | 요청 ID·이벤트 ID·보상·재화 변화 비교       |
| 누락 처리   | 저장 전후 목록·합계·관계 데이터 비교        |
| 호환성      | 이전 형식 입력·마이그레이션 결과 비교       |
| 보안        | 로그·파일·백업의 민감 정보와 접근 권한 확인 |

저장 데이터의 정답은 화면만으로 판정하지 않습니다. 서버 응답·저장 결과·상태 조회·이벤트 기록을 필요한 범위에서 함께 확인합니다.

## 6. 체크리스트

- [ ] 저장 대상·임시 상태·저장하지 않는 데이터가 구분됩니다.
- [ ] 정상 저장·불러오기·반복 저장을 확인합니다.
- [ ] 저장 중 종료·연결 종료·저장소 오류를 포함합니다.
- [ ] 손상·누락·이전 형식 데이터의 정책이 정의됩니다.
- [ ] 동시 저장·재시도·중복 요청을 확인합니다.
- [ ] 마지막 확정 상태와 임시 상태를 구분합니다.
- [ ] 저장·복구 결과와 증적을 추적할 수 있습니다.
- [ ] 민감 데이터와 접근 권한을 검토합니다.
- [ ] 테스트 후 생성 데이터와 상태를 초기화합니다.
