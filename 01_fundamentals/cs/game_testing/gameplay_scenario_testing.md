# 게임 플레이 시나리오 테스트 (Gameplay Scenario Testing)
<!-- reference: _reference/game_testing_official_notes.md -->

게임 플레이 시나리오 테스트는 플레이어 목표와 게임 규칙을 흐름으로 표현하고, 정상·대안·오류·복구 경로를 검증하는 테스트입니다.

## 1. 개요

게임 플레이 시나리오는 단순히 화면을 순서대로 확인하는 절차가 아닙니다. 플레이어 목표, 규칙 판정, 상태 변화, 데이터 결과를 하나의 흐름으로 검증합니다.

| 구분      | 내용                              |
|-----------|-----------------------------------|
| 목표      | 플레이어가 달성하려는 결과        |
| 시작 상태 | 계정·캐릭터·방·콘텐츠의 초기 조건 |
| 기본 흐름 | 규칙에 따라 정상 진행되는 단계    |
| 대안 흐름 | 선택·조건·분기에 따른 다른 진행   |
| 오류 흐름 | 입력·권한·네트워크·의존성 실패    |
| 복구 흐름 | 재접속·재시작·취소·재시도 후 진행 |
| 종료 결과 | 완료·실패·중단과 데이터·보상 결과 |

[⬆ 목차로 돌아가기](#목차)

## 2. 시나리오 구성

### 흐름 구성 요소

```text
플레이어 목표
    │
    v
초기 상태 → 입력·이벤트 → 규칙 판정 → 상태 변화
                              │
               ┌──────────────┴──────────────┐
               v                             v
           성공 결과                      실패·복구 결과
```

| 질문               | 확인 내용                                        |
|--------------------|--------------------------------------------------|
| 목표가 명확한가?   | 완료 조건과 실패 조건이 구분되는가?              |
| 상태가 추적되는가? | 단계별 상태와 허용 이벤트가 정의되는가?          |
| 규칙이 판정되는가? | 클라이언트 표시와 서버·데이터 판정이 일치하는가? |
| 중단을 다루는가?   | 앱 종료·연결 종료·취소 후 결과가 정의되는가?     |
| 결과가 남는가?     | 저장·보상·기록·이벤트를 검증할 수 있는가?        |

[⬆ 목차로 돌아가기](#목차)

## 3. 흐름 도출

1. 플레이어 목표와 완료 조건을 정의합니다.
2. 시작 상태와 필요한 데이터·권한을 준비합니다.
3. 기본 플레이 흐름의 입력·판정·상태 변화를 나열합니다.
4. 선택·실패·취소·재시도·시간 초과 분기를 추가합니다.
5. 저장·보상·이벤트·세션 결과를 연결합니다.
6. 위험도가 높은 분기를 우선 테스트 케이스로 변환합니다.
7. 실행 후 초기화와 재실행 조건을 정의합니다.

### 시나리오 목록 예시

| ID      | 플레이 흐름              | 변형             | 핵심 검증                |
|---------|--------------------------|------------------|--------------------------|
| GPS-001 | 콘텐츠 시작 → 완료       | 정상             | 규칙·상태·완료 기록      |
| GPS-002 | 콘텐츠 시작 → 완료       | 중간 연결 종료   | 재접속 후 진행·중복 없음 |
| GPS-003 | 보상 조건 달성 → 수령    | 수령 요청 재전송 | 보상 중복 없음           |
| GPS-004 | 진행 중 앱 종료 → 재실행 | 저장 중단        | 복구 상태·데이터 정합성  |

## 4. 케이스 변환

시나리오의 각 분기를 테스트 케이스로 변환할 때는 다음을 포함합니다.

- 사전 상태와 테스트 데이터
- 플레이어 입력과 시스템 이벤트
- 규칙 판정과 기대 상태
- 화면·API·저장 데이터·이벤트의 관찰 위치
- 중단·재접속·재시도 조건
- 종료 후 정리와 재실행 방법

시나리오가 지나치게 커지면 목표·상태·오라클이 다른 흐름으로 분리합니다. 상태 전이는 [게임 상태 테스트](game_state_testing.md), 케이스 공통 필드는 [게임 테스트 케이스 설계](game_test_case_design.md)와 연결합니다.

## 5. 검토 체크리스트

- [ ] 플레이어 목표·시작·완료·실패 조건이 명확합니다.
- [ ] 기본·대안·오류·복구 흐름을 구분합니다.
- [ ] 입력·규칙 판정·상태 변화가 연결됩니다.
- [ ] 저장·보상·이벤트·세션 결과를 검증합니다.
- [ ] 중간 종료·재접속·재시도·순서 역전을 포함합니다.
- [ ] 클라이언트 표시와 서버·데이터 판정을 구분합니다.
- [ ] 각 분기가 실행 가능한 테스트 케이스로 변환됩니다.
- [ ] 테스트 데이터와 실행 후 정리 방법이 정의됩니다.
- [ ] 특정 엔진의 UI 흐름을 모든 게임의 규칙으로 일반화하지 않습니다.
