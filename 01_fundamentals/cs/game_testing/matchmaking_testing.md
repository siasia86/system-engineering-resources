# 매칭 테스트 (Matchmaking Testing)
<!-- reference: _reference/game_testing_official_notes.md -->

매칭 테스트는 플레이어·방·세션을 조건에 따라 연결하고, 대기·성공·실패·취소·재시도 상태를 올바르게 처리하는지 검증하는 테스트입니다.

## 1. 개요

매칭은 입력 조건을 만족하는 대상을 선택하고 세션·방·게임으로 연결하는 흐름입니다. 테스트는 매칭 성공만이 아니라 대기·거부·취소·timeout·재접속을 포함합니다.

| 검증 영역 | 예시                               |
|-----------|------------------------------------|
| 자격      | 계정·권한·지역·버전·상태           |
| 조건      | 모드·인원·실력·언어·지연·선호      |
| 대기      | 대기열 등록·순서·중복 등록·이탈    |
| 연결      | 방 생성·참여·세션 발급·상태 동기화 |
| 종료      | 매칭 완료·취소·실패·timeout·재시도 |
| 공정성    | 조건 위반·우회·특정 그룹 편중 여부 |

구체적인 매칭 규칙은 게임 요구사항에 따라 정의하며, 일반 원칙과 프로젝트 정책을 구분합니다.

## 2. 매칭 조건

### 조건 분류

| 조건 유형 | 테스트 항목                          |
|-----------|--------------------------------------|
| 필수 조건 | 충족하지 못하면 매칭되지 않는 조건   |
| 선택 조건 | 우선 적용 후 완화될 수 있는 조건     |
| 우선순위  | 대기 시간·지역·실력·선호의 적용 순서 |
| 제한 조건 | 금지 조합·최대 인원·상태·버전        |
| 완화 정책 | 대기 증가 시 조건을 완화하는 규칙    |
| 고정 조건 | 매칭 중 변경할 수 없는 조건          |

조건 조합이 많으면 정상·경계·불가능 조합을 분리하고 결정 테이블이나 Pairwise 기법을 함께 사용합니다.

## 3. 상태와 흐름

### 매칭 상태 예시

```text
대기 전
  │ join
  v
대기 중 ── match found ──> 매칭 완료
  │                         │
  ├── cancel ─────────────> 취소
  ├── timeout ────────────> 실패·재시도 가능
  └── disconnect ─────────> 이탈·복구 정책
```

### 케이스 예시

| ID      | 초기 상태 | 이벤트                    | 기대 결과                    |
|---------|-----------|---------------------------|------------------------------|
| MAT-001 | 대기 전   | 유효 조건으로 참여        | 대기열 등록·중복 없음        |
| MAT-002 | 대기 중   | 조건을 만족하는 대상 발견 | 방·세션 연결·상태 동기화     |
| MAT-003 | 대기 중   | 사용자가 취소             | 대기열 제거·방 미생성        |
| MAT-004 | 대기 중   | timeout                   | 실패 상태·정책에 따른 재시도 |
| MAT-005 | 완료 직전 | 연결 종료                 | 복구·취소·재접속 정책과 일치 |
| MAT-006 | 완료      | 참여 요청 재전송          | 중복 방·중복 세션 없음       |

## 4. 경계·오류 케이스

- 대기열이 비어 있거나 대상 조건을 만족하지 못하는 경우
- 최대 인원에 도달한 방에 참여하는 경우
- 동일 계정·플레이어·요청이 중복 등록되는 경우
- 매칭 중 조건·권한·버전이 변경되는 경우
- 방 생성·세션 발급·상태 동기화 중 의존성이 실패하는 경우
- timeout 직전에 매칭 성공 이벤트가 도착하는 경우
- 매칭 완료 후 클라이언트가 재접속하거나 다른 방을 요청하는 경우
- 부분 응답·순서 역전·오래된 이벤트가 도착하는 경우

각 오류 케이스는 사용자 안내·상태 정리·재시도·데이터 중복 여부를 함께 판정합니다.

## 5. 판정과 체크리스트

### 판정 대상

| 대상          | 확인 내용                              |
|---------------|----------------------------------------|
| 대기열        | 등록·중복·순서·제거 상태               |
| 조건          | 필수·선택·완화 규칙의 적용             |
| 방·세션       | 생성·참여·종료·중복 여부               |
| 플레이어 상태 | 대기·완료·이탈·재접속 상태             |
| 데이터        | 매칭 결과·기록·보상·세션 데이터 정합성 |
| 관찰 증적     | 요청 ID·매칭 ID·상태·시각·오류         |

### 체크리스트

- [ ] 필수·선택·제한·완화 조건이 정의되었습니다.
- [ ] 정상·불가능·경계 조합을 확인합니다.
- [ ] 대기·성공·취소·실패·timeout·재시도를 포함합니다.
- [ ] 중복 등록·중복 방·중복 세션을 방지합니다.
- [ ] 매칭 중 이탈·재접속·조건 변경을 확인합니다.
- [ ] 매칭 결과와 방·세션·플레이어 상태를 함께 검증합니다.
- [ ] 오류·부분 응답·오래된 이벤트를 처리합니다.
- [ ] 요청·매칭·세션 ID로 실패를 재현할 수 있습니다.
- [ ] 테스트 후 대기열·방·세션·테스트 데이터를 정리합니다.
