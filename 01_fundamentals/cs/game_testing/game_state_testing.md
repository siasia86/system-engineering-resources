# 게임 상태 테스트 (Game State Testing)
<!-- reference: _reference/game_testing_official_notes.md -->

게임 상태 테스트는 게임·세션·방·캐릭터·콘텐츠의 상태와 이벤트에 따른 전이를 검증하는 테스트입니다. 상태가 화면에 표시되는 값과 서버·저장 데이터의 상태로 나뉠 수 있음을 전제로 합니다.

## 1. 개요

상태는 현재 조건을 표현하고, 이벤트는 상태를 바꾸는 입력입니다. 상태 테스트는 유효한 전이뿐 아니라 허용되지 않은 이벤트와 중간 실패를 확인합니다.

| 상태 영역     | 예시 상태                           |
|---------------|-------------------------------------|
| 세션          | 로그인 전·활성·만료·재접속 대기     |
| 방·매치       | 대기·준비·진행·완료·취소            |
| 캐릭터·콘텐츠 | 잠금·해금·진행·완료·실패            |
| 저장          | 미저장·저장 중·저장 완료·복구 필요  |
| 보상·재화     | 지급 전·처리 중·지급 완료·지급 실패 |

상태 이름과 전이 조건은 프로젝트 용어를 사용하되, 상태 진입 조건·종료 조건·허용 이벤트를 명확히 기록합니다.

[⬆ 목차로 돌아가기](#목차)

## 2. 상태 모델

### 상태 전이 표현

```text
[대기]
   │ start
   v
[진행 중] ── complete ──> [완료]
   │                         │
   └── cancel ─────────────> [취소]
```

| 구성 요소 | 질문                                          |
|-----------|-----------------------------------------------|
| 상태      | 시스템이 구분해야 하는 현재 조건은 무엇인가?  |
| 이벤트    | 상태를 바꾸는 입력·시간·외부 결과는 무엇인가? |
| 가드 조건 | 전이가 허용되기 위한 권한·데이터는 무엇인가?  |
| 액션      | 전이 시 저장·이벤트·알림이 발생하는가?        |
| 결과 상태 | 성공·실패·취소 후 어떤 상태가 되는가?         |

상태 모델은 화면 흐름만으로 작성하지 않고 서버 판정·저장 상태·복구 상태를 필요한 범위에서 함께 표현합니다.

[⬆ 목차로 돌아가기](#목차)

## 3. 전이 설계

### 테스트할 전이

| 전이 유형 | 테스트 내용                                |
|-----------|--------------------------------------------|
| 유효 전이 | 허용된 이벤트가 기대 상태로 이동           |
| 무효 전이 | 허용되지 않은 이벤트가 거부되고 상태 불변  |
| 경계 전이 | 완료 직전·만료 직전·자원 한계에서의 결과   |
| 반복 전이 | 같은 이벤트 재전송·중복 호출의 결과        |
| 역순 전이 | 완료 후 취소·처리 후 재처리 등 순서 역전   |
| 동시 전이 | 같은 상태에 여러 이벤트가 동시에 도착      |
| 실패 전이 | 저장·네트워크·외부 의존성 오류 이후의 상태 |

### 전이 케이스 예시

| ID      | 초기 상태 | 이벤트           | 기대 결과                       |
|---------|-----------|------------------|---------------------------------|
| GST-001 | 대기      | start            | 진행 중 상태로 이동             |
| GST-002 | 완료      | start            | 거부·완료 상태 유지             |
| GST-003 | 진행 중   | 연결 종료        | 복구 대기 또는 정책 상태로 이동 |
| GST-004 | 지급 중   | 보상 요청 재전송 | 중복 지급 없이 최종 상태 유지   |
| GST-005 | 저장 중   | 앱 종료          | 재실행 후 복구 정책에 맞는 상태 |

## 4. 복구·재실행

상태 테스트는 정상 전이보다 중간 실패와 재실행 조건에서 데이터 정합성을 확인해야 합니다.

- 상태 전이 중 프로세스·앱·연결이 종료되는 조건
- 재접속 시 마지막 확정 상태와 진행 중 상태의 구분
- 같은 이벤트가 다시 도착했을 때의 멱등 처리
- 저장 실패 후 재시도·취소·복구 경로
- 오래된 이벤트와 현재 상태가 충돌하는 경우
- 복구 완료 후 클라이언트 표시와 서버 상태의 일치

복구 테스트는 “다시 연결됩니다”가 아니라 재연결 후 상태·데이터·부수 효과를 구체적으로 판정합니다.

## 5. 판정과 증적

| 판정 대상     | 증적 예시                         |
|---------------|-----------------------------------|
| 현재 상태     | 상태 조회·서버 로그·상태 덤프     |
| 전이 순서     | 이벤트 ID·시각·순서 로그          |
| 데이터 정합성 | 저장 결과·버전·재화·인벤토리      |
| 중복 처리     | 멱등 키·이벤트 수·부수 효과       |
| 복구 결과     | 재접속 시점·복구 상태·재실행 결과 |
| 사용자 표시   | 화면·알림·오류 메시지·동기화 결과 |

Unity Test Framework나 Firebase Game Loop는 특정 클라이언트 실행 환경의 검증 수단입니다. 상태 모델과 오라클은 게임 규칙·서버 계약·저장 정책을 기준으로 정의합니다.

## 6. 체크리스트

- [ ] 상태·이벤트·가드·액션·결과 상태가 정의되었습니다.
- [ ] 유효·무효·경계·반복·역순 전이를 포함합니다.
- [ ] 동시 이벤트와 중복 이벤트를 확인합니다.
- [ ] 저장·연결·프로세스 중간 실패를 포함합니다.
- [ ] 재접속·재실행 후 상태 복구를 검증합니다.
- [ ] 서버 상태·저장 데이터·클라이언트 표시를 구분합니다.
- [ ] 상태 전이와 데이터 정합성의 증적을 수집합니다.
- [ ] 오래된 이벤트·만료·순서 역전 조건을 검토합니다.
- [ ] 테스트 후 상태와 데이터를 초기화합니다.
