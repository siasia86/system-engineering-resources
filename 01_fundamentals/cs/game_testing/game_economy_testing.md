# 게임 경제 테스트 (Game Economy Testing)
<!-- reference: _reference/game_testing_official_notes.md -->

게임 경제 테스트는 재화·아이템·보상·거래·소비 규칙이 요구사항과 정합성 조건을 만족하는지 검증하는 테스트입니다. 특정 게임의 수치나 상품 정책이 아니라 재사용 가능한 테스트 관점을 다룹니다.

## 1. 개요

게임 경제 테스트는 화면에 표시된 숫자만 확인하지 않고, 재화의 발생·이동·소비·회수와 기록의 관계를 검증합니다.

| 영역      | 검증 예시                          |
|-----------|------------------------------------|
| 재화 생성 | 보상·퀘스트·이벤트·구매 결과       |
| 재화 소비 | 아이템·업그레이드·거래·수수료      |
| 인벤토리  | 추가·사용·삭제·중복·최대 보유 정책 |
| 보상      | 조건·지급·수령·재전송·실패 처리    |
| 거래      | 양측 상태·원자성·취소·중복 처리    |
| 기록      | 잔액·이력·이벤트·감사 로그의 관계  |

[⬆ 목차로 돌아가기](#목차)

## 2. 데이터 흐름

```text
조건 충족
   │
   v
보상·재화 생성 ──> 잔액·인벤토리 반영
   │                         │
   v                         v
이력·이벤트 기록 <── 소비·거래·취소
```

### 정합성 조건

- 재화·아이템의 생성량과 소비량이 정의된 규칙과 일치합니다.
- 한 거래의 양쪽 결과가 서로 모순되지 않습니다.
- 처리 실패·취소·재시도 후 중복 지급이나 유실이 없습니다.
- 화면·API·저장 데이터·이력의 값이 같은 확정 상태를 가리킵니다.
- 권한 없는 계정이나 잘못된 상태가 경제 데이터를 변경하지 못합니다.

## 3. 테스트 유형

| 유형          | 실행 조건                         | 기대 결과                       |
|---------------|-----------------------------------|---------------------------------|
| 정상 지급     | 보상 조건 충족                    | 정책에 따른 지급·이력 기록      |
| 지급 거부     | 조건 미충족·권한 부족             | 지급 없음·명확한 결과           |
| 소비          | 유효한 재화·아이템 사용           | 잔액·인벤토리·이력 일관         |
| 중복 요청     | 같은 보상·구매·소비 요청 재전송   | 중복 부수 효과 없음             |
| 동시 요청     | 같은 계정·아이템에 여러 요청      | 충돌 정책·최종 정합성           |
| 취소·환불     | 처리 중 취소·실패·환불            | 정책에 따른 복구·이력 추적      |
| 데이터 오류   | 누락·잘못된 타입·음수·오래된 상태 | 입력 거부·오류 기록·데이터 보호 |
| 재접속·재실행 | 처리 중 연결·앱 종료 후 재진입    | 중복·유실 없이 확정 상태 복원   |

## 4. 동시성·복구

게임 경제에서 retry와 동시 요청은 중복 지급·중복 소비·잔액 불일치로 이어질 수 있습니다.

- 요청 ID·거래 ID·이벤트 ID로 동일 작업을 식별합니다.
- 처리 중·확정·실패·취소 상태를 구분합니다.
- 재전송 시 이미 확정된 작업을 다시 적용하지 않습니다.
- 양쪽 계정·재화·아이템의 변경 순서와 원자성을 검증합니다.
- 저장·이벤트 기록 중단 후 복구 시 최종 상태와 이력을 비교합니다.
- 오류 응답에도 민감한 내부 정보가 노출되지 않는지 확인합니다.

테스트 케이스의 기대 결과에는 잔액·인벤토리·이력·이벤트를 함께 포함합니다.

## 5. 판정·체크리스트

| 판정 대상 | 확인 내용                         |
|-----------|-----------------------------------|
| 잔액      | 생성·소비·환불의 최종 합계와 정책 |
| 인벤토리  | 수량·중복·삭제·소유 계정          |
| 거래      | 양측 결과·취소·실패·중복 여부     |
| 이력      | 요청·거래·이벤트·시각·상태        |
| 권한      | 계정·역할·소유권별 허용·거부      |
| 복구      | 재접속·재실행 후 확정 상태        |

- [ ] 생성·소비·거래·환불의 규칙이 정의되었습니다.
- [ ] 정상·거부·중복·동시·취소·복구 케이스가 있습니다.
- [ ] 재화·아이템·이력·이벤트의 관계를 검증합니다.
- [ ] 요청·거래·이벤트 ID로 중복을 판정합니다.
- [ ] 권한 없는 변경과 잘못된 데이터를 거부합니다.
- [ ] 실패·재시도·재접속 후 최종 정합성을 확인합니다.
- [ ] 테스트 데이터와 계정·거래 상태를 정리합니다.
