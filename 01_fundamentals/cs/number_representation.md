## 1. 진법과 단위

| 진법   | 접두 표기 | 자리 하나가 나타내는 비트 | 주로 보는 곳                        |
|--------|-----------|---------------------------|-------------------------------------|
| 2진수  | `0b1010`  | 1비트                     | 플래그, 서브넷 마스크               |
| 8진수  | `0o755`   | 3비트                     | 파일 권한(`chmod 755`)              |
| 10진수 | `10`      | -                         | 사람이 읽는 값                      |
| 16진수 | `0xff`    | 4비트(니블)               | 메모리 주소, 덤프, MAC 주소, 해시값 |

16진수 두 자리가 정확히 1바이트(8비트)이므로 덤프와 해시값은 16진수로 표시합니다.

```bash
# 진법 변환 (bash 산술 확장과 printf)
echo $((2#1010))          # 2진수 -> 10진수: 10
echo $((16#ff))           # 16진수 -> 10진수: 255
printf '%x\n' 255         # 10진수 -> 16진수: ff
printf '%o\n' 493         # 10진수 -> 8진수: 755
```

용량 단위는 10진 접두어(kB, MB, GB = 1000의 거듭제곱)와 2진 접두어(KiB, MiB, GiB = 1024의 거듭제곱)를 구분합니다. 디스크 제조사 표기와 `df -h`·`free -h` 출력이 다르게 보이는 주된 이유입니다.

## 2. 부호 없는 정수

n비트 부호 없는 정수(unsigned integer)는 0부터 2^n − 1까지 표현합니다.

| 크기   | 최댓값                     | 자주 보는 곳                  |
|--------|----------------------------|-------------------------------|
| 8비트  | 255                        | IPv4 주소 한 옥텟, 바이트     |
| 16비트 | 65,535                     | TCP/UDP 포트 번호             |
| 32비트 | 4,294,967,295              | IPv4 주소 전체, 32비트 카운터 |
| 64비트 | 18,446,744,073,709,551,615 | 64비트 카운터, 바이트 누계    |

32비트 바이트 카운터는 약 4GiB에서 0으로 돌아갑니다. 10Gbps 링크라면 4초 안팎에 한 바퀴를 돌 수 있으므로, SNMP 같은 모니터링에서 인터페이스 트래픽은 64비트 카운터를 우선 사용합니다.

## 3. 2의 보수

부호 있는 정수(signed integer)는 대부분의 CPU에서 2의 보수(two's complement)로 저장합니다. 음수 −x는 x의 모든 비트를 뒤집고 1을 더한 값입니다.

```text
 +5  = 0000 0101
 invert bits      1111 1010
 add 1          + 0000 0001
 -5  = 1111 1011   (0xFB)
```

n비트 부호 있는 정수의 범위는 −2^(n−1)부터 2^(n−1) − 1까지입니다.

| 크기   | 최솟값                     | 최댓값                    |
|--------|----------------------------|---------------------------|
| 8비트  | −128                       | 127                       |
| 16비트 | −32,768                    | 32,767                    |
| 32비트 | −2,147,483,648             | 2,147,483,647             |
| 64비트 | −9,223,372,036,854,775,808 | 9,223,372,036,854,775,807 |

2의 보수의 장점은 덧셈·뺄셈 회로를 부호 없는 정수와 같이 쓸 수 있다는 점입니다. 같은 비트도 해석에 따라 값이 달라집니다.

```python
import struct

raw = b"\xff"
print(struct.unpack("B", raw)[0])   # unsigned 8-bit: 255
print(struct.unpack("b", raw)[0])   # signed 8-bit:   -1
```

## 4. 정수 넘침

정수 넘침(overflow)은 결과가 표현 범위를 벗어나는 경우입니다. 고정 폭 정수에서는 값이 반대쪽 끝으로 돌아갑니다(wrap-around). C에서 부호 없는 정수의 넘침은 모듈러 연산으로 정의되지만, 부호 있는 정수의 넘침은 정의되지 않은 동작(undefined behavior)입니다.

운영에서 만나는 대표 사례는 다음과 같습니다.

| 사례                        | 원인                                                         |
|-----------------------------|--------------------------------------------------------------|
| 2038년 문제                 | 부호 있는 32비트 `time_t`의 최댓값이 2038-01-19 03:14:07 UTC |
| DB 자동 증가 키 고갈        | `INT`(32비트) 기본 키가 2,147,483,647에서 더 증가하지 못함   |
| 모니터링 그래프의 음수 급락 | 카운터가 돌아갔는데 차이를 그대로 계산                       |
| 파일 크기 2GiB 제한         | 오래된 프로그램이 파일 오프셋을 부호 있는 32비트로 처리      |

```python
from datetime import datetime, timezone

print(datetime.fromtimestamp(2**31 - 1, timezone.utc))  # 2038-01-19 03:14:07+00:00
```

카운터 증가량을 계산할 때는 돌아감을 감안합니다.

```python
def counter_delta(prev: int, curr: int, bits: int = 32) -> int:
    """Return increase of a wrapping unsigned counter."""
    return (curr - prev) % (1 << bits)

print(counter_delta(4_294_967_000, 200))   # 496
```

🟡 카운터가 돌아간 것과 장비 재시작으로 0이 된 것은 값만으로 구분하기 어렵습니다. 장비 가동 시간(uptime)을 함께 수집합니다.

## 5. IEEE 754 부동소수점

부동소수점(floating point)은 실수를 `부호 × 1.가수 × 2^지수` 꼴로 저장합니다. 현재 판은 IEEE 754-2019(Standard for Floating-Point Arithmetic, 2019-07-22 발행, 2026-11-16 확인 시 Active)입니다.

| 형식               | 전체 비트 | 부호 | 지수(bias) | 가수(fraction) | 유효 자릿수(10진) |
|--------------------|-----------|------|------------|----------------|-------------------|
| binary32(`float`)  | 32        | 1    | 8 (127)    | 23             | 약 7자리          |
| binary64(`double`) | 64        | 1    | 11 (1023)  | 52             | 약 15~17자리      |

정규화된 수는 가수 앞의 `1.`을 저장하지 않으므로 binary64의 정밀도는 53비트입니다.

```text
binary32 layout (1.0 = 0x3F800000)

 31 30        23 22                                 0
 +--+-----------+------------------------------------+
 |S | exponent  |            fraction                |
 +--+-----------+------------------------------------+
  0  01111111    00000000000000000000000
     (127 - 127 = 0)  -> +1.0 x 2^0 = 1.0
```

특수 값도 정의되어 있습니다.

| 값        | 지수 비트 | 가수 비트 | 의미                                   |
|-----------|-----------|-----------|----------------------------------------|
| ±0        | 모두 0    | 0         | 양의 0과 음의 0이 따로 있음            |
| 비정규 수 | 모두 0    | 0이 아님  | 0 근처의 아주 작은 수(정밀도 감소)     |
| ±Infinity | 모두 1    | 0         | 넘침, 0으로 나누기                     |
| NaN       | 모두 1    | 0이 아님  | 정의되지 않은 결과, 자기 자신과도 다름 |

```python
import struct

print(struct.pack(">f", 1.0).hex())    # 3f800000
print(struct.pack(">f", -2.5).hex())   # c0200000
print(float("nan") == float("nan"))    # False
```

## 6. 부동소수점 오차와 비교

대부분의 10진 소수는 2진 소수로 정확히 나타낼 수 없습니다. Python 공식 튜토리얼은 0.1이 실제로는 `3602879701896397 / 2**55`로 저장된다고 설명합니다.

```python
print(0.1 + 0.2)              # 0.30000000000000004
print(0.1 + 0.2 == 0.3)       # False
print((0.1).hex())            # 0x1.999999999999ap-4

import math
print(math.isclose(0.1 + 0.2, 0.3))   # True
```

자주 생기는 문제와 대응은 다음과 같습니다.

| 문제                                      | 대응                                                  |
|-------------------------------------------|-------------------------------------------------------|
| `==` 비교 실패                            | 허용 오차 비교(`math.isclose`), 또는 정수 단위로 변환 |
| 큰 수에 작은 수를 더해도 값이 변하지 않음 | 합산 순서 조정, `math.fsum` 같은 보정 합산            |
| 2^53보다 큰 정수가 `double`에서 뭉개짐    | 큰 ID는 문자열로 전달                                 |
| binary32에서 16,777,217이 16,777,216이 됨 | 카운터·ID에 `float` 사용 금지                         |

```python
print(float(2**53) + 1 == float(2**53))   # True: 9007199254740993 cannot be stored
```

JSON 숫자를 `double`로 읽는 언어·도구(예: JavaScript의 `Number`)는 2^53 − 1(9,007,199,254,740,991)보다 큰 정수를 정확히 보존하지 못합니다. 64비트 ID나 Snowflake 계열 ID는 API에서 문자열로 내보내는 것이 안전합니다.

## 7. 정확한 소수 계산

금액·과금·재고처럼 10진 자릿수가 정확해야 하는 값은 부동소수점을 쓰지 않습니다.

| 방법                 | 예시                                           | 비고                            |
|----------------------|------------------------------------------------|---------------------------------|
| 최소 단위 정수       | 1,234.56원 → 123456(센트·전 단위)              | 가장 단순하고 빠름              |
| 10진 고정소수점 타입 | SQL `DECIMAL(p,s)`/`NUMERIC`, Python `decimal` | 반올림 규칙을 명시              |
| 유리수               | Python `fractions.Fraction`                    | 1/3 같은 값을 정확히 표현, 느림 |

```python
from decimal import Decimal, ROUND_HALF_UP

price = Decimal("19.99")
qty = 3
total = (price * qty).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
print(total)                        # 59.97
print(Decimal.from_float(0.1))      # 0.1000000000000000055511151231257827021181583404541015625
```

🟡 `Decimal(0.1)`처럼 `float`에서 만들면 이미 생긴 오차가 그대로 들어갑니다. 문자열에서 만듭니다.

## 8. 엔디언

엔디언(endianness)은 여러 바이트로 된 값을 메모리나 전송 순서에 놓는 방식입니다.

```text
value 0x12345678 at address 0x100

             0x100  0x101  0x102  0x103
big-endian     12     34     56     78    (most significant byte first)
little-endian  78     56     34     12    (least significant byte first)
```

| 구분       | 사용처                                                     |
|------------|------------------------------------------------------------|
| 빅엔디언   | 네트워크 바이트 순서(IP·TCP·UDP 헤더), 많은 파일 형식 헤더 |
| 리틀엔디언 | x86-64, 대부분의 ARM 리눅스 환경의 메모리 표현             |

RFC 791 부록 B는 여러 옥텟으로 된 값을 "가장 중요한 옥텟부터" 전송한다고 정합니다. byteorder(3) man page도 인터넷의 네트워크 바이트 순서를 최상위 바이트 우선으로, i386의 호스트 순서를 최하위 바이트 우선으로 설명합니다. 그래서 C 소켓 프로그램은 `htons()`·`htonl()`(호스트 → 네트워크)과 `ntohs()`·`ntohl()`(네트워크 → 호스트)로 변환합니다.

```bash
# 현재 시스템의 바이트 순서 확인
lscpu | grep -i 'byte order'          # Byte Order: Little Endian
python3 -c 'import sys; print(sys.byteorder)'
```

```python
import struct

print(struct.pack(">I", 0x12345678).hex())   # 12345678 (big-endian)
print(struct.pack("<I", 0x12345678).hex())   # 78563412 (little-endian)
```

## 9. 덤프에서 값 읽기

같은 바이트도 읽는 단위와 엔디언에 따라 다르게 보입니다. `od`·`xxd`·`hexdump`로 확인합니다.

```bash
# 4바이트 값 0x12345678을 리틀엔디언으로 파일에 기록
printf '\x78\x56\x34\x12' > /tmp/sample.bin

xxd /tmp/sample.bin
# 00000000: 7856 3412                                xV4.

od -An -tx1 /tmp/sample.bin      # 바이트 단위:   78 56 34 12
od -An -tx4 /tmp/sample.bin      # 4바이트 단위(호스트 순서로 해석): 12345678
```

`od -tx4`는 호스트 바이트 순서로 묶어 보여 주므로, 리틀엔디언 서버에서는 원래 값 `12345678`이 보입니다. 네트워크 패킷은 빅엔디언이므로 `tcpdump -X`에서 포트 번호 443은 `01bb` 순서로 보입니다.

| 확인할 질문                 | 방법                                   |
|-----------------------------|----------------------------------------|
| 이 필드는 몇 바이트인가     | 프로토콜·파일 형식 명세                |
| 빅엔디언인가 리틀엔디언인가 | 명세, 알려진 값(매직 넘버)으로 검증    |
| 부호 있는 값인가            | 명세의 타입 정의                       |
| 정수인가 부동소수점인가     | 명세, `struct.unpack`으로 두 해석 비교 |

파일 형식의 매직 넘버(magic number)는 엔디언 판별에도 씁니다. 예를 들어 ELF 헤더의 `EI_DATA` 바이트는 파일이 리틀엔디언(1)인지 빅엔디언(2)인지 나타냅니다.

```bash
# ELF 헤더의 Data 항목에서 엔디언 확인
readelf -h /bin/ls | grep -E 'Class|Data'
```

## 10. 운영 점검표

| 점검 항목                                                               | 확인 |
|-------------------------------------------------------------------------|------|
| 트래픽·바이트 카운터는 64비트를 쓰고 돌아감을 처리하는가                | ☐    |
| 자동 증가 키의 타입과 현재 최댓값 대비 사용률을 감시하는가              | ☐    |
| 시간 값을 32비트로 저장하는 구성 요소(오래된 바이너리·DB 칼럼)가 없는가 | ☐    |
| 금액·과금 계산에 `float`·`double`을 쓰지 않는가                         | ☐    |
| 64비트 ID를 JSON·JavaScript로 넘길 때 문자열로 보내는가                 | ☐    |
| 부동소수점 비교에 허용 오차를 쓰는가                                    | ☐    |
| 바이너리 프로토콜·파일 해석 시 엔디언을 명세로 확인했는가               | ☐    |
| 용량 표기가 10진(GB)인지 2진(GiB)인지 문서에 밝혔는가                   | ☐    |
