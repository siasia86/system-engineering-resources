# 시나리오 기반 테스트 (Scenario-Based Testing)
<!-- reference: _reference/software_testing_official_notes.md -->

시나리오 기반 테스트(Scenario-Based Testing)는 사용자·시스템·업무의 흐름을 시나리오로 표현하고, 정상·대안·오류·복구 경로를 테스트 케이스로 변환하는 설계 방법입니다.

## 1. 개요

시나리오는 사용자의 목표와 시스템의 흐름을 설명하는 상위 단위입니다. 하나의 시나리오는 여러 테스트 케이스로 분해될 수 있습니다.

| 구분          | 설명                                           |
|---------------|------------------------------------------------|
| 시나리오      | 목표를 달성하는 기능·업무·사용자 흐름          |
| 테스트 케이스 | 시나리오의 조건·단계·기대 결과를 검증하는 단위 |
| 시나리오 변형 | 정상·대안·오류·복구 조건에 따른 흐름           |
| 커버리지      | 요구사항·상태·위험·경로가 검증된 범위          |

시나리오 기반 테스트는 E2E에만 사용하는 기법이 아닙니다. 유닛·통합·API·인프라 테스트에서도 흐름의 일부를 시나리오로 표현할 수 있습니다.

## 2. 시나리오 구성

| 구성 요소 | 질문                                            |
|-----------|-------------------------------------------------|
| 주체      | 누가 또는 무엇이 동작을 시작하는가?             |
| 목표      | 어떤 결과를 달성하려는가?                       |
| 시작 조건 | 어떤 상태·권한·데이터에서 시작하는가?           |
| 트리거    | 어떤 입력·이벤트·시간 조건이 흐름을 시작하는가? |
| 기본 흐름 | 정상적인 단계 순서는 무엇인가?                  |
| 대안 흐름 | 선택·조건에 따라 달라지는 경로는 무엇인가?      |
| 오류 흐름 | 입력·권한·의존성 오류 시 어떻게 동작하는가?     |
| 복구 흐름 | 실패 후 재시도·취소·재개가 가능한가?            |
| 종료 조건 | 성공·실패·중단을 어떻게 판정하는가?             |

시나리오에 기본 흐름만 작성하면 실제 운영에서 발생하는 예외와 복구 경로가 빠질 수 있습니다. 기본·대안·오류·복구 흐름을 별도로 확인합니다.

## 3. 시나리오 도출

### 요구사항에서 도출하는 순서

1. 사용자 목표와 시스템 책임을 식별합니다.
2. 시작 상태와 종료 상태를 정의합니다.
3. 기본 흐름의 이벤트와 상태 변화를 나열합니다.
4. 각 단계에서 선택·실패·취소·재시도 가능성을 확인합니다.
5. 외부 의존성·권한·데이터·시간 조건을 추가합니다.
6. 위험도가 높은 흐름을 우선순위가 높은 테스트 케이스로 변환합니다.
7. 요구사항과 시나리오 ID를 연결합니다.

### 시나리오 목록 예시

| ID      | 흐름               | 변형              | 주요 위험             |
|---------|--------------------|-------------------|-----------------------|
| SCN-001 | 계정 생성 → 로그인 | 정상              | 계정·세션 생성        |
| SCN-002 | 계정 생성 → 로그인 | 중복 계정         | 중복 방지·오류 안내   |
| SCN-003 | 파일 업로드 → 처리 | 처리 중 연결 종료 | 부분 처리·재시도      |
| SCN-004 | 주문 생성 → 완료   | 결제 지연         | 상태 일관성·중복 요청 |

시나리오 ID는 테스트 케이스·결함·요구사항의 추적 키로 사용할 수 있어야 합니다.

## 4. 케이스 변환

시나리오의 각 분기와 위험을 실행 가능한 테스트 케이스로 변환합니다.

```text
시나리오
  │
  ├── 기본 흐름 ───────> 정상 케이스
  ├── 대안 흐름 ───────> 조건별 케이스
  ├── 오류 흐름 ───────> 오류·거부 케이스
  ├── 복구 흐름 ───────> 재시도·취소·재개 케이스
  └── 경계 조건 ───────> 경계·리소스·시간 케이스
```

### 변환 예시

```text
시나리오: 파일 업로드 후 처리 완료 확인

TC-001 정상 파일 → 업로드 성공 → 처리 완료 상태 확인
TC-002 지원하지 않는 형식 → 업로드 거부 → 오류 코드 확인
TC-003 최대 크기 파일 → 업로드·처리 결과 확인
TC-004 처리 중 연결 종료 → 재연결 또는 재시도 → 중복 처리 없음 확인
TC-005 저장소 오류 → 실패 상태 기록 → 재처리 경로 확인
```

각 케이스에는 사전 조건·입력·실행 절차·기대 결과를 작성합니다. 시나리오 설명만 있고 판정 기준이 없으면 테스트 케이스로 완료된 것으로 보지 않습니다.

## 5. 커버리지

### 커버리지 관점

| 관점        | 확인 질문                                     |
|-------------|-----------------------------------------------|
| 요구사항    | 모든 핵심 요구사항에 시나리오가 있는가?       |
| 흐름        | 기본·대안·오류·복구 흐름이 포함되었는가?      |
| 상태        | 시작·중간·종료 상태가 검증되는가?             |
| 데이터      | 유효·무효·경계 데이터가 포함되었는가?         |
| 권한        | 허용·거부 역할과 권한 조합이 있는가?          |
| 외부 의존성 | timeout·실패·부분 응답이 다루어지는가?        |
| 시간·동시성 | 순서 역전·중복 실행·만료 조건이 필요한가?     |
| 복구        | 실패 후 재시도·취소·재개 결과가 정의되었는가? |

모든 조합을 무조건 전수 테스트하지 않습니다. 위험도와 조건 조합에 따라 결정 테이블·상태 전이·페어와이즈 같은 기법을 함께 적용합니다.

## 6. 검토 체크리스트

- [ ] 시나리오의 주체·목표·시작·종료 조건이 명확합니다.
- [ ] 기본 흐름과 대안·오류·복구 흐름이 구분됩니다.
- [ ] 각 분기가 하나 이상의 테스트 케이스로 연결됩니다.
- [ ] 테스트 케이스에 관찰 가능한 기대 결과가 있습니다.
- [ ] 요구사항·위험·결함과 추적할 ID가 있습니다.
- [ ] 데이터·권한·외부 의존성·시간 조건을 검토했습니다.
- [ ] 상태 전이와 중복 실행 가능성을 확인했습니다.
- [ ] 테스트 간 데이터와 환경이 격리됩니다.
- [ ] 실행 후 상태와 테스트 데이터 정리 방법이 있습니다.
- [ ] 시나리오 범위가 과도하게 커지지 않았습니다.
