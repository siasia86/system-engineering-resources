# 테스트 데이터 관리 (Test Data Management)
<!-- reference: _reference/software_testing_official_notes.md -->

테스트 데이터 관리(Test Data Management)는 테스트에 필요한 데이터를 준비하고, 격리·재사용·초기화·정리하는 방법을 정의하는 활동입니다. 데이터가 불명확하거나 테스트 간 공유되면 결과 재현성과 신뢰성이 낮아집니다.

## 1. 개요

테스트 데이터는 단순한 입력값뿐 아니라 테스트 전후의 상태와 외부 의존성이 사용하는 데이터까지 포함합니다.

| 데이터 영역 | 예시                              |
|-------------|-----------------------------------|
| 입력 데이터 | 요청값·파일·메시지·환경 변수      |
| 기준 데이터 | 사용자·상품·권한·설정·참조 테이블 |
| 상태 데이터 | 세션·작업·주문·처리 단계          |
| 기대 데이터 | 저장 결과·이벤트·로그·응답        |
| 오류 데이터 | 만료·중복·잘못된 형식·권한 부족   |
| 대량 데이터 | 목록·파일·이력·동시 처리 대상     |

테스트 케이스는 데이터의 출처·생성 방법·수명·정리 방법을 함께 정의해야 합니다.

## 2. 데이터 분류

### 생성 방식

| 방식          | 특징                                        | 주의 사항                        |
|---------------|---------------------------------------------|----------------------------------|
| 고정 Fixture  | 반복 실행 시 같은 데이터를 사용             | 오래되면 실제 스키마와 불일치    |
| 시드 데이터   | 환경 초기화 시 기준 데이터를 생성           | 버전·순서·중복 관리 필요         |
| 실행 중 생성  | 테스트가 API·Factory로 필요한 데이터를 생성 | 생성 실패·정리 실패 처리 필요    |
| 스냅샷 복원   | 준비된 상태를 빠르게 복원                   | 스냅샷 유효기간·환경 의존성 확인 |
| 합성 데이터   | 실제 정보 없이 테스트 목적에 맞게 생성      | 실제 분포와 차이 검토            |
| 익명화 데이터 | 실제 데이터의 식별 요소를 제거·변환         | 재식별 위험·변환 정합성 확인     |

운영 데이터를 테스트 환경으로 복사할 때는 승인·최소화·마스킹·접근 통제를 먼저 확인합니다. 실제 자격증명과 개인정보를 테스트 데이터로 사용하지 않습니다.

### 테스트 목적별 데이터

| 목적        | 필요한 데이터 특성                     |
|-------------|----------------------------------------|
| 정상 동작   | 유효한 상태·권한·관계                  |
| 오류 처리   | 누락·잘못된 형식·만료·권한 부족        |
| 경계 검증   | 허용 범위의 안쪽·경계·바깥 값          |
| 동시성 검증 | 같은 대상에 대한 동시 요청과 충돌 조건 |
| 회귀 검증   | 이전 결함을 재현하는 최소 데이터       |
| 성능 검증   | 대표 크기·분포·처리량을 반영한 데이터  |

## 3. 생명주기

```text
요구사항·케이스 분석
        │
        v
데이터 스키마·민감도 분류
        │
        v
생성·시드·마스킹·준비
        │
        v
테스트 실행과 증적 수집
        │
        v
초기화·정리·폐기
        │
        v
유효성·잔존 데이터 점검
```

### 단계별 관리 항목

| 단계   | 확인 내용                                 |
|--------|-------------------------------------------|
| 설계   | 필요한 필드·관계·상태·민감도              |
| 준비   | 생성자·Fixture·시드·스냅샷의 버전         |
| 실행   | 데이터 ID·소유 테스트·동시 사용 여부      |
| 초기화 | 테스트 전 상태 보장과 기존 데이터 제거    |
| 정리   | 생성 데이터·파일·큐·세션·로그의 제거      |
| 검증   | 잔존 데이터·오염·중복·민감 정보 노출 확인 |

데이터 정리는 테스트 성공 여부와 관계없이 수행되어야 합니다. 실패한 테스트가 남긴 중간 상태가 다음 실행의 결과에 영향을 주지 않도록 합니다.

## 4. 격리와 재현성

### 격리 방법

| 격리 수준   | 방법                                         |
|-------------|----------------------------------------------|
| 식별자 격리 | 테스트 실행 ID를 데이터 키에 포함            |
| 계정 격리   | 테스트별 사용자·권한·소유 데이터 사용        |
| 스키마 격리 | 테스트용 DB·스키마·테이블 분리               |
| 환경 격리   | 테스트 실행별 컨테이너·네임스페이스 사용     |
| 시간 격리   | 시간·만료·스케줄을 제어 가능한 방식으로 설정 |
| 의존성 격리 | Stub·Mock·Sandbox·계약 테스트 환경 사용      |

### 재현성 조건

- 동일한 데이터 버전과 초기 상태를 사용할 수 있어야 합니다.
- 난수·시간·외부 응답의 변동을 기록하거나 제어해야 합니다.
- 데이터 생성 실패와 정리 실패를 테스트 결과에 남겨야 합니다.
- 테스트 실행 ID와 데이터 소유 관계를 추적할 수 있어야 합니다.
- 재실행 시 이전 실행의 데이터가 남아 있지 않아야 합니다.

데이터 격리는 테스트 간 간섭을 줄이지만, 실제 통합 환경의 공유 자원 문제를 대신 검증하지는 않습니다. 격리 테스트와 공유 환경 테스트의 목적을 구분합니다.

## 5. 보안·정합성

### 보안 기준

| 항목      | 확인 내용                                    |
|-----------|----------------------------------------------|
| 개인정보  | 테스트 환경 반입 전 최소화·마스킹·익명화     |
| 자격증명  | 문서·코드·로그에 실값 기록 금지              |
| 접근 권한 | 테스트 계정과 데이터 접근 범위 최소화        |
| 보존 기간 | 테스트 종료 후 데이터·증적·로그 보존 기준    |
| 외부 전송 | 운영 결제·알림·분석 시스템으로의 실전송 차단 |

### 정합성 기준

- 참조 관계가 있는 데이터는 생성 순서와 삭제 순서를 정의합니다.
- 중복 실행 시 중복 데이터가 생성되지 않는지 확인합니다.
- 테스트 실패 중간 상태가 정상 데이터로 오인되지 않아야 합니다.
- 기대 결과를 판정할 기준 데이터와 실행 데이터의 버전을 기록합니다.
- 테스트 데이터의 변경은 원인과 담당 테스트를 추적할 수 있어야 합니다.

## 6. 체크리스트

- [ ] 테스트 케이스별 필요한 데이터가 정의되었습니다.
- [ ] 데이터 생성 방식과 버전이 기록되었습니다.
- [ ] 정상·오류·경계·동시성 데이터가 포함되었습니다.
- [ ] 테스트 간 데이터와 계정이 적절히 격리됩니다.
- [ ] 실행 전 초기 상태를 보장합니다.
- [ ] 실행 후 생성 데이터와 중간 상태를 정리합니다.
- [ ] 실패 시에도 정리 절차가 동작합니다.
- [ ] 난수·시간·외부 응답이 재현 가능하거나 기록됩니다.
- [ ] 개인정보·자격증명·민감 데이터가 보호됩니다.
- [ ] 잔존 데이터·오염·중복을 점검합니다.
