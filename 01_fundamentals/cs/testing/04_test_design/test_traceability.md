# 테스트 추적성 (Test Traceability)
<!-- reference: _reference/software_testing_official_notes.md -->

테스트 추적성(Test Traceability)은 요구사항·위험·테스트 케이스·결함·실행 결과 사이의 연결을 기록하고 유지하는 활동입니다. 무엇을 검증했는지와 무엇이 아직 검증되지 않았는지를 확인할 수 있게 합니다.

## 1. 개요

추적성은 테스트 케이스 수를 늘리는 목적이 아니라, 요구사항의 검증 범위와 결과를 설명하는 근거를 만드는 목적이 있습니다.

| 질문                                   | 추적성이 제공하는 답                  |
|----------------------------------------|---------------------------------------|
| 이 요구사항을 검증했는가?              | 연결된 테스트 케이스와 실행 결과 확인 |
| 이 테스트는 무엇을 검증하는가?         | 요구사항·위험·시나리오 연결 확인      |
| 변경 시 어떤 테스트를 다시 실행하는가? | 변경 영향에 연결된 케이스 확인        |
| 결함이 어떤 요구사항에 영향을 주는가?  | 결함·요구사항·실행 결과 연결 확인     |

추적성은 문서·이슈 트래커·테스트 관리 도구·코드 주석 등 프로젝트에서 유지 가능한 방식으로 구현합니다.

## 2. 추적성 관계

### 양방향 추적성

```text
요구사항 ───> 위험 ───> 테스트 시나리오 ───> 테스트 케이스
    ^                                           │
    │                                           v
결함 <── 실행 결과 <─────────────────────────────┘
```

| 방향          | 확인 내용                                        |
|---------------|--------------------------------------------------|
| 정방향 추적성 | 요구사항이 테스트 케이스와 결과로 연결되는가?    |
| 역방향 추적성 | 테스트 케이스가 실제 요구사항·위험을 검증하는가? |
| 변경 추적성   | 변경된 항목과 영향받는 테스트가 연결되는가?      |
| 결함 추적성   | 실패 결과와 결함·수정·재검증이 연결되는가?       |

### 식별자 규칙

각 항목은 변경되어도 추적할 수 있는 고유 ID를 사용합니다.

```text
REQ-AUTH-001  요구사항
RSK-AUTH-001  위험
SCN-AUTH-001  시나리오
TC-AUTH-001   테스트 케이스
BUG-AUTH-001  결함
RUN-20260915  실행 결과
```

실제 ID 형식은 프로젝트 규칙에 맞추되, 동일 ID를 서로 다른 의미로 재사용하지 않습니다.

## 3. 추적성 매트릭스

### 기본 구조

| 요구사항     | 위험         | 시나리오     | 테스트 케이스 | 결과    | 결함         |
|--------------|--------------|--------------|---------------|---------|--------------|
| REQ-AUTH-001 | RSK-AUTH-001 | SCN-AUTH-001 | TC-AUTH-001   | Pass    | -            |
| REQ-FILE-001 | RSK-FILE-001 | SCN-FILE-001 | TC-FILE-001   | Fail    | BUG-FILE-001 |
| REQ-ROLE-001 | -            | SCN-ROLE-001 | TC-ROLE-001   | Not Run | -            |

매트릭스의 목적은 행 수를 채우는 것이 아니라 공백을 드러내는 것입니다.

- 요구사항에 테스트 케이스가 없으면 미검증 영역입니다.
- 테스트 케이스에 요구사항 연결이 없으면 근거 없는 테스트일 수 있습니다.
- 결과가 `Not Run`이면 실행되지 않은 이유와 다음 실행 계획이 필요합니다.
- `Fail` 결과에는 결함 ID 또는 실패 원인이 필요합니다.

## 4. 작성·유지 절차

1. 요구사항과 위험에 고유 ID를 부여합니다.
2. 시나리오와 테스트 케이스에 상위 ID를 연결합니다.
3. 테스트 실행 결과와 증적을 케이스 ID에 연결합니다.
4. 실패 결과에는 결함·수정 commit·재검증 결과를 연결합니다.
5. 변경 시 영향받는 요구사항·위험·케이스를 갱신합니다.
6. 삭제·병합·분리된 항목은 이력을 남기고 ID 재사용을 피합니다.
7. 정기적으로 미연결·중복·오래된 링크를 점검합니다.

### 추적성 품질 기준

| 상태        | 의미                                          |
|-------------|-----------------------------------------------|
| Complete    | 요구사항부터 실행 결과까지 필요한 연결이 있음 |
| Partial     | 일부 연결이 없거나 결과가 아직 미확정         |
| Not Covered | 검증할 테스트가 정의되지 않음                 |
| Obsolete    | 요구사항·케이스·결함이 더 이상 유효하지 않음  |
| Blocked     | 환경·데이터·의존성 문제로 실행할 수 없음      |

상태를 숨기지 않고 기록해야 추적성 매트릭스가 실제 의사결정에 사용될 수 있습니다.

## 5. 변경 영향

### 변경 유형별 확인 대상

| 변경 유형          | 재검토할 연결 범위                        |
|--------------------|-------------------------------------------|
| 요구사항 변경      | 해당 요구사항·위험·시나리오·케이스·결함   |
| 테스트 케이스 변경 | 상위 요구사항·위험과 실행 결과            |
| 구현 변경          | 변경 파일에 연결된 요구사항·회귀 케이스   |
| 데이터 구조 변경   | 데이터 케이스·통합·회귀·마이그레이션 검증 |
| 환경·의존성 변경   | 통합·계약·장애·복구 케이스                |
| 결함 수정          | 원인 케이스·재현 케이스·회귀 검증         |

변경 영향 분석 결과 테스트 범위가 바뀌면 추적성 매트릭스와 실행 계획을 같은 변경에서 갱신합니다.

## 6. 체크리스트

- [ ] 요구사항·위험·시나리오·테스트 케이스에 고유 ID가 있습니다.
- [ ] 정방향·역방향 추적이 모두 가능합니다.
- [ ] 실행 결과와 증적이 테스트 케이스에 연결됩니다.
- [ ] 실패 결과에 결함 또는 원인 기록이 있습니다.
- [ ] `Not Run`·`Blocked`·`Not Covered` 상태를 구분합니다.
- [ ] 변경 시 영향받는 테스트 범위를 확인합니다.
- [ ] 삭제·병합·분리된 항목의 이력이 유지됩니다.
- [ ] 오래된 링크와 미연결 항목을 정기적으로 점검합니다.
- [ ] 추적성 정보에 불필요한 개인정보나 비밀값을 기록하지 않습니다.
