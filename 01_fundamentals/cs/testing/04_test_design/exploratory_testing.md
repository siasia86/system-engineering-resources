# 탐색적 테스트 (Exploratory Testing)
<!-- reference: _reference/software_testing_official_notes.md -->

탐색적 테스트(Exploratory Testing)는 테스트를 설계·실행·관찰·학습하는 활동을 동시에 진행하는 접근 방식입니다. 사전에 모든 절차를 고정하지 않고, 실행 중 얻은 정보를 다음 테스트의 방향에 반영합니다.

## 1. 개요

탐색적 테스트는 테스트 케이스가 없다는 뜻이 아닙니다. 목적·범위·시간·기록 방식을 정한 상태에서 실행 중 관찰 결과를 이용해 테스트를 확장합니다.

| 구분        | 사전 정의 중심 테스트           | 탐색적 테스트                      |
|-------------|---------------------------------|------------------------------------|
| 설계 시점   | 실행 전에 절차와 기대 결과 고정 | 실행 중 학습에 따라 다음 방향 조정 |
| 강점        | 반복 실행·자동화·추적성         | 예상하지 못한 위험·상호작용 발견   |
| 주의점      | 알려진 경로에 편중될 수 있음    | 기록 부족 시 재현·범위 판정 어려움 |
| 적합한 상황 | 안정된 요구사항·회귀 검증       | 신규 기능·불명확한 위험·탐색 단계  |

탐색적 테스트는 명시적 테스트 케이스와 대체 관계가 아니라 보완 관계입니다.

## 2. 테스트 차터

테스트 차터(Test Charter)는 탐색 활동의 목적과 경계를 정의하는 짧은 작업 지시서입니다.

| 항목      | 작성 내용                              |
|-----------|----------------------------------------|
| 목표      | 무엇을 배우고 어떤 위험을 찾을 것인가? |
| 대상      | 기능·모듈·환경·데이터 범위             |
| 접근법    | 사용할 입력·상호작용·변형·도구         |
| 제외 범위 | 이번 세션에서 다루지 않을 영역         |
| 시간 상자 | 탐색 세션의 시작·종료 조건             |
| 중단 조건 | 심각한 결함·환경 오류·추가 정보 필요   |
| 기록 방법 | 메모·영상·로그·재현 절차·결함 티켓     |
| 종료 결과 | 발견 사항·미확인 위험·추가 테스트 제안 |

### 차터 예시

```text
목표: 파일 업로드 처리의 오류와 복구 경로 탐색
대상: 파일 형식·크기·네트워크 상태·업로드 중 취소
접근: 정상·빈 입력·경계 크기·연속 취소·재시도 조합
제외: 외부 저장소의 실제 장애 주입
증적: 요청 ID, 응답, 로그, 재현 절차
종료: 주요 변형을 확인하고 결함·미확인 위험을 기록할 때
```

## 3. 탐색 절차

1. 기능·요구사항·최근 변경·과거 결함을 읽습니다.
2. 테스트 차터와 시간 상자를 정합니다.
3. 대표적인 정상 흐름으로 기준 동작을 확인합니다.
4. 입력·상태·권한·시간·환경 변형을 적용합니다.
5. 관찰한 결과에 따라 다음 테스트 방향을 조정합니다.
6. 의심스러운 동작을 최소 재현 절차로 줄입니다.
7. 발견 사항·미확인 위험·추가 케이스를 기록합니다.

### 변형 아이디어

| 축   | 질문                                         |
|------|----------------------------------------------|
| 입력 | 빈 값·긴 값·특수값·잘못된 형식은 어떤가?     |
| 상태 | 초기·중간 실패·재시작·만료 상태는 어떤가?    |
| 순서 | 작업 순서를 바꾸거나 반복하면 어떤가?        |
| 권한 | 역할·소유자·권한 변경 조건은 어떤가?         |
| 시간 | 지연·timeout·동시 실행·만료는 어떤가?        |
| 환경 | 네트워크·브라우저·파일·의존성 변화는 어떤가? |
| 조합 | 둘 이상의 변형이 동시에 발생하면 어떤가?     |

탐색 중 발견한 변형은 이후 명시적 테스트 케이스·회귀 케이스·자동화 후보로 승격할 수 있습니다.

## 4. 기록과 증적

탐색적 테스트는 기록이 없으면 결과를 재현하기 어렵습니다.

| 기록 항목   | 내용                                    |
|-------------|-----------------------------------------|
| 세션 정보   | 차터·실행자·환경·시작·종료 시각         |
| 실행 흐름   | 실제로 수행한 입력·순서·변형            |
| 관찰 결과   | 응답·상태·성능·오류·예상 밖 동작        |
| 증적        | 로그·스크린샷·영상·요청 ID·데이터 ID    |
| 결함        | 재현 절차·영향·발견 조건·중복 여부      |
| 미확인 영역 | 확인하지 못한 조건과 후속 테스트        |
| 승격 후보   | 자동화·회귀·추가 시나리오로 만들 케이스 |

결함 보고서에는 탐색 세션의 차터와 실행 환경을 연결합니다. “재현되지 않음”으로 끝내지 않고 재현에 필요한 조건을 기록합니다.

## 5. 범위 관리

### 테스트 결과 분류

| 결과           | 처리 방법                                      |
|----------------|------------------------------------------------|
| 결함 발견      | 최소 재현·영향·증적을 기록하고 결함 등록       |
| 정상 동작 확인 | 기준 동작과 환경을 기록                        |
| 추가 정보 필요 | 필요한 로그·권한·데이터·환경을 명시            |
| 미확인 위험    | 후속 차터·케이스·담당자를 지정                 |
| 자동화 후보    | 안정된 절차·오라클·데이터를 분리해 자동화 검토 |

탐색적 테스트의 종료는 결함을 찾았을 때만이 아닙니다. 차터의 목표를 달성했는지, 남은 위험이 무엇인지, 다음 활동이 무엇인지 판단할 수 있어야 합니다.

[⬆ 목차로 돌아가기](#목차)

## 6. 체크리스트

- [ ] 테스트 차터에 목표·대상·접근법·제외 범위가 있습니다.
- [ ] 실행 환경과 테스트 데이터를 기록합니다.
- [ ] 정상 기준 동작을 먼저 확인합니다.
- [ ] 입력·상태·순서·권한·시간·환경 변형을 탐색합니다.
- [ ] 실행 중 얻은 정보를 다음 테스트에 반영합니다.
- [ ] 발견 사항을 최소 재현 절차로 정리합니다.
- [ ] 결함·미확인 위험·자동화 후보를 구분합니다.
- [ ] 세션 종료 시 증적과 후속 작업을 남깁니다.
- [ ] 안정된 탐색 결과를 회귀 테스트로 승격합니다.
