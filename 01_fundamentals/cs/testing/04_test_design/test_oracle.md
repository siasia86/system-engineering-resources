# 테스트 오라클 (Test Oracle)
<!-- reference: _reference/software_testing_official_notes.md -->

테스트 오라클(Test Oracle)은 테스트 실행 결과가 올바른지 판단하기 위한 기준이나 메커니즘입니다. 입력을 실행하는 것만으로는 테스트가 완료되지 않으며, 실제 결과를 기대 결과와 비교할 수 있어야 합니다.

## 1. 개요

테스트 오라클은 “무엇이 정답인가”와 “어떻게 정답 여부를 판단하는가”를 정의합니다.

| 요소      | 질문                                          |
|-----------|-----------------------------------------------|
| 기대 결과 | 어떤 값·상태·메시지가 나와야 하는가?          |
| 관찰 방법 | 결과를 어디에서 어떻게 확인하는가?            |
| 판정 규칙 | 일치·허용 범위·불변 조건을 어떻게 판단하는가? |
| 실패 증적 | 실패를 재현·분석할 자료가 남는가?             |

오라클은 테스트 케이스의 기대 결과와 연결되며, 테스트 케이스가 실행 가능하고 판정 가능하도록 만듭니다.

[⬆ 목차로 돌아가기](#목차)

## 2. 오라클의 구성

### 입력과 기대 결과의 관계

```text
입력 + 사전 상태 + 실행 이벤트
              │
              v
        시스템 실행
              │
              v
실제 결과 ────────> 오라클 판정 ────────> Pass / Fail / Inconclusive
                         ^
                         │
              기대 결과·불변 조건·참조 모델
```

### 관찰 대상

| 관찰 대상   | 판정 예시                                |
|-------------|------------------------------------------|
| 반환값      | 값과 타입이 기대 결과와 일치             |
| 상태        | 상태 전이가 허용된 경로를 따름           |
| 데이터      | 저장·갱신·삭제 결과가 정합성 조건을 만족 |
| 오류        | 오류 유형·코드·메시지가 정책과 일치      |
| 부수 효과   | 이벤트·로그·알림이 필요한 횟수만큼 발생  |
| 비기능 결과 | 정의된 성능·보안·호환성 기준을 만족      |

오라클은 화면에 표시된 결과만 보지 않고, 필요한 경우 API 응답·저장 데이터·이벤트·로그를 함께 확인합니다.

## 3. 오라클 유형

| 유형                   | 기준                                | 적합한 상황                      |
|------------------------|-------------------------------------|----------------------------------|
| 명시적 기대 결과       | 요구사항에 정의된 값·상태           | 계산 결과·오류 코드·상태         |
| 불변 조건(Property)    | 실행 전후 항상 유지되어야 하는 조건 | 정렬·합계·중복 방지              |
| 참조 모델              | 독립적인 모델·계산·기존 구현과 비교 | 복잡한 계산·변환                 |
| 상태 전이 규칙         | 허용된 상태와 이벤트 전이           | 승인·세션·작업 흐름              |
| 계약(Contract)         | 요청·응답 스키마와 의미             | 모듈·서비스 간 인터페이스        |
| 변환 관계(Metamorphic) | 입력 변환에 따른 결과 관계          | 정답을 직접 계산하기 어려운 함수 |
| 차분(Differential)     | 여러 구현·버전의 결과 비교          | 호환성·마이그레이션              |
| 허용 범위              | 오차·순서·시간 범위를 포함한 판정   | 부동소수점·비동기·성능 결과      |

여러 유형을 함께 사용할 수 있습니다. 예를 들어 응답 스키마는 계약 오라클로, 데이터 합계는 불변 조건으로 검증할 수 있습니다.

[⬆ 목차로 돌아가기](#목차)

## 4. 설계 절차

1. 요구사항에서 관찰 가능한 결과를 추출합니다.
2. 정상 결과와 오류 결과를 구분합니다.
3. 상태·데이터·부수 효과 중 검증해야 할 대상을 선택합니다.
4. 정확히 일치해야 하는 항목과 허용 범위가 있는 항목을 구분합니다.
5. 결과를 확인할 독립적인 관찰 방법을 정합니다.
6. 실패 시 필요한 증적과 정리 절차를 정의합니다.
7. 테스트 케이스의 기대 결과와 오라클 규칙을 연결합니다.

### 판정 표현 예시

| 모호한 표현           | 판정 가능한 표현                                 |
|-----------------------|--------------------------------------------------|
| 정상적으로 처리됩니다 | 응답 상태·필수 필드·저장 상태가 각각 조건과 일치 |
| 빠르게 응답합니다     | 사전에 정의한 latency budget 이내                |
| 데이터가 올바릅니다   | 필수 필드·타입·관계·중복 조건을 모두 만족        |
| 오류가 발생합니다     | 정의된 오류 코드와 재시도 가능 여부를 반환       |

성능 기준처럼 환경에 따라 달라지는 값은 출처나 서비스 SLO를 함께 기록합니다. 근거 없는 수치를 일반 규칙처럼 사용하지 않습니다.

## 5. 오라클 문제

### Oracle Problem

복잡한 시스템은 모든 입력에 대한 정답을 독립적으로 계산하기 어려울 수 있습니다. 이때 테스트 자체가 실행되더라도 결과를 완전하게 판정하지 못하는 문제가 발생합니다.

### 대응 방법

| 상황                          | 대응 방법                                 |
|-------------------------------|-------------------------------------------|
| 정답을 직접 계산하기 어려움   | 불변 조건·부분 속성·변환 관계 사용        |
| 외부 시스템 결과에 의존       | 계약·스키마·범위·상태를 분리해 검증       |
| 비결정적 순서                 | 순서가 아닌 집합·관계·허용 범위로 판정    |
| 응답이 부분적으로만 검증 가능 | 검증 가능한 필드와 미검증 필드를 구분     |
| 오라클 자체가 구현과 동일함   | 독립 모델·참조 데이터·다른 관찰 경로 사용 |

`Inconclusive`는 실패와 다릅니다. 판정에 필요한 증적이 없거나 오라클이 적용되지 않는 경우에는 별도 상태로 기록하고 원인을 보완합니다.

## 6. 검토 체크리스트

- [ ] 기대 결과가 입력과 사전 상태에 대응합니다.
- [ ] 성공뿐 아니라 오류·거부·복구 결과가 정의됩니다.
- [ ] 판정 대상이 값·상태·데이터·부수 효과로 구체화됩니다.
- [ ] 허용 범위와 정확 일치 조건이 구분됩니다.
- [ ] 테스트 구현과 독립적인 관찰 방법이 있습니다.
- [ ] 비동기 결과와 순서 조건이 명확합니다.
- [ ] 실패 시 로그·응답·상태를 재현할 증적이 남습니다.
- [ ] 판정 불가 상태를 실패로 오인하지 않습니다.
- [ ] 오라클에 사용하는 수치와 정책에 근거가 있습니다.
