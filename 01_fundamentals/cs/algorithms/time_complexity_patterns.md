## 1. 복잡도 분석 개요

시간 복잡도(Time Complexity)는 입력 크기가 증가할 때 알고리즘의 연산량이 증가하는 양상을 나타냅니다. 공간 복잡도(Space Complexity)는 입력 크기에 따라 알고리즘이 사용하는 메모리 양의 증가 양상을 나타냅니다. 분석 기준에 따라 입력 저장 공간을 포함한 전체 공간과 입력 외에 추가로 사용하는 보조 공간을 구분합니다.

복잡도 분석은 특정 컴퓨터에서 측정한 실행 시간과 다릅니다. 프로세서, 구현 언어, 컴파일러, 캐시, 메모리 접근, 입출력에 따라 실제 시간은 달라지지만, 점근적 분석은 입력 크기에 따른 증가율을 비교하는 데 사용합니다.

> 점근적 분석(Asymptotic Analysis): 입력 크기가 커질 때 알고리즘의 비용이 어떤 비율로 증가하는지 분석하는 방법입니다. 작은 입력에서의 상수 비용보다 증가율 비교에 초점을 둡니다.

### 분석의 목적

- 입력 크기가 커졌을 때 실행 시간이 감당 가능한지 판단합니다.
- 알고리즘과 자료구조의 선택을 비교합니다.
- 성능 요구사항과 자원 제한을 설계 단계에서 확인합니다.
- 코드 변경이 연산량과 메모리 사용량에 미치는 영향을 추정합니다.

## 2. 입력 크기와 비용 모델

### 2.1 입력 크기 정의

먼저 알고리즘이 처리하는 입력의 크기를 변수로 정의합니다. 배열 순회에서는 `n`을 원소 수로 둘 수 있지만, 그래프에서는 정점 수 `V`와 간선 수 `E`를 함께 사용해야 합니다.

| 문제 유형   | 입력 크기 예시          | 복잡도 표현 예시  |
|-------------|-------------------------|-------------------|
| 배열 하나   | 원소 수 `n`             | `O(n)`            |
| 두 배열     | 각 배열의 길이 `n`, `m` | `O(n + m)`        |
| 행렬        | 행 `r`, 열 `c`          | `O(rc)`           |
| 그래프      | 정점 `V`, 간선 `E`      | `O(V + E)`        |
| 문자열 비교 | 문자열 길이 `n`, `m`    | `O(min(n, m))` 등 |

`n`과 `m`이 독립적인 입력이면 임의로 `n = m`이라고 가정하지 않습니다. 입력 크기가 여러 개일 때는 각각의 변수를 유지해야 실제 비용 구조가 보존됩니다.

### 2.2 기본 연산과 비용 모델

비용 모델은 어떤 연산을 일정한 비용으로 볼지 정하는 분석 기준입니다. 일반적인 알고리즘 분석에서는 대입, 비교, 산술 연산, 배열 인덱스 접근 등을 기본 연산으로 단순화합니다.

```python
for value in values:
    if value == target:
        return True
return False
```

`values`의 길이를 `n`이라고 하면 최악의 경우 비교를 `n`회 수행하므로 시간 복잡도는 `O(n)`입니다. 실제로 비교 대상이 복잡한 객체이거나 문자열 길이가 별도의 입력 변수라면 기본 연산 하나의 비용도 추가로 분석해야 합니다.

### 2.3 시간·공간 복잡도의 범위

| 구분        | 포함하는 비용                               |
|-------------|---------------------------------------------|
| 시간 복잡도 | 반복, 비교, 정렬, 해시, 재귀 호출 등 연산량 |
| 공간 복잡도 | 입력 저장 공간과 실행 중 사용하는 메모리    |
| 보조 공간   | 입력 저장 공간을 제외한 추가 메모리         |
| 재귀 공간   | 호출 스택에 유지되는 재귀 프레임            |

문제에서 공간 복잡도를 별도로 요구하면 입력 저장 공간을 포함한 전체 공간인지, 보조 공간만 의미하는지 명시합니다.

## 3. 점근 표기법

### 3.1 Big-O, Big-Theta, Big-Omega

| 표기      | 일반적인 의미                      | 사용 목적                   |
|-----------|------------------------------------|-----------------------------|
| `O(g(n))` | `g(n)`보다 빠르게 커지지 않는 상한 | 최악 비용 또는 상한 표현    |
| `Θ(g(n))` | `g(n)`과 같은 증가율               | 점근적으로 정확한 차수 표현 |
| `Ω(g(n))` | `g(n)` 이상으로 필요한 하한        | 최소 비용 또는 하한 표현    |

Big-O는 상한 표기이므로 엄밀하게는 실제 복잡도가 `O(n)`이면서 동시에 `O(n²)`일 수 있습니다. 실무와 알고리즘 설명에서는 가장 유용하거나 가장 가까운 상한을 관례적으로 제시하는 경우가 많습니다. 증가율이 정확히 일치한다는 의미를 강조하려면 `Θ`를 사용합니다.

### 3.2 항 단순화

점근 표기에서는 입력이 커질 때 지배적인 항을 남깁니다.

```text
O(3n² + 5n + 10) = O(n²)
O(n + log n)      = O(n)
O(n² + n log n)   = O(n²)
O(2n + 100)       = O(n)
```

이 단순화는 상수 계수와 낮은 차수 항이 실제로 사라진다는 뜻이 아닙니다. 상수 계수는 실제 실행 시간과 메모리 사용량에 영향을 줄 수 있지만, 입력 크기에 따른 증가 차수를 표현할 때는 생략합니다.

### 3.3 복잡도 증가율 비교

| 증가율       | 입력 증가 시 특징                      | 대표 사례          |
|--------------|----------------------------------------|--------------------|
| `O(1)`       | 입력과 무관한 일정한 증가              | 배열 인덱스 접근   |
| `O(log n)`   | 입력이 커져도 매우 느리게 증가         | 이진 탐색          |
| `O(n)`       | 입력에 비례해 증가                     | 선형 탐색          |
| `O(n log n)` | 선형 증가와 로그 증가의 결합           | 병합 정렬          |
| `O(n²)`      | 입력이 2배이면 대략 4배 증가           | 모든 쌍 비교       |
| `O(2ⁿ)`      | 원소가 하나 늘 때 비용이 대략 2배 증가 | 모든 부분집합 탐색 |
| `O(n!)`      | 가능한 순열 수에 비례해 급격히 증가    | 모든 순열 탐색     |

## 4. 기본 계산 규칙

### 4.1 순차 실행은 더합니다

```python
for value in values:       # O(n)
    process(value)

for pair in pairs:         # O(m)
    process_pair(pair)
```

두 반복이 순차적으로 실행되므로 전체 복잡도는 다음과 같습니다.

```text
O(n) + O(m) = O(n + m)
```

`n = m`이라고 문제에서 보장하는 경우에만 `O(n)`으로 단순화할 수 있습니다.

### 4.2 중첩 실행은 곱합니다

```python
for i in range(n):
    for j in range(m):
        process(i, j)
```

안쪽 반복이 바깥쪽 반복마다 실행되므로 총 실행 횟수는 `n × m`입니다.

```text
O(n × m) = O(nm)
```

두 반복의 범위가 모두 `n`이면 `O(n²)`가 됩니다.

### 4.3 조건 분기는 가장 큰 경로를 봅니다

```python
if condition:
    scan(values)          # O(n)
else:
    compare_all(values)   # O(n²)
```

한 번의 실행에서는 한 경로만 선택되므로 최악의 시간 복잡도는 다음과 같습니다.

```text
max(O(n), O(n²)) = O(n²)
```

반대로 조건문 내부의 두 작업이 모두 순차 실행되면 분기가 아니라 합산 대상입니다.

### 4.4 함수 호출 비용을 포함합니다

```python
for value in values:
    binary_search(sorted_values, value)  # O(log m)
```

`n`회 반복하면서 각 호출이 `O(log m)`이면 전체 복잡도는 다음과 같습니다.

```text
O(n log m)
```

함수 이름만 보고 `O(1)`이라고 가정하지 않고, 호출하는 함수의 내부 비용까지 확인해야 합니다.

## 5. 반복문과 합 계산

### 5.1 일정한 간격의 반복

```python
for i in range(n):
    process(i)
```

`process`가 `O(1)`이면 `n`회 실행되므로 `O(n)`입니다. `i += 2`처럼 일정한 간격으로 증가해도 반복 횟수는 `n / 2`이므로 상수 계수를 제거하면 `O(n)`입니다.

### 5.2 의존 범위의 중첩 반복

```python
for i in range(n):
    for j in range(i):
        process(i, j)
```

안쪽 반복 횟수가 `i`에 따라 달라지므로 단순히 `n × n`으로만 설명하지 않고 총합을 계산합니다.

```text
0 + 1 + 2 + ... + (n - 1)
= n(n - 1) / 2
= Θ(n²)
```

따라서 이 코드의 시간 복잡도는 `O(n²)`입니다.

### 5.3 삼각형·사각형 반복

| 반복 범위                       | 총 반복 횟수      | 시간 복잡도 |
|---------------------------------|-------------------|-------------|
| `i: 0..n`, `j: 0..n`            | `n × n`           | `O(n²)`     |
| `i: 0..n`, `j: 0..i`            | `n(n - 1) / 2`    | `O(n²)`     |
| `i: 0..n`, `j: i..n`            | 약 `n(n + 1) / 2` | `O(n²)`     |
| `i: 0..n`, `j: 0..n`, `k: 0..n` | `n³`              | `O(n³)`     |

반복 횟수의 정확한 식이 달라도 지배적인 증가 차수가 같으면 같은 점근 복잡도로 표현할 수 있습니다.

### 5.4 조기 종료

```python
for value in values:
    if value == target:
        return value
```

최선의 경우 첫 번째 항목에서 종료하여 `O(1)`이지만, 최악의 경우 끝까지 확인하므로 `O(n)`입니다. 평균 복잡도는 입력 분포와 `target`의 위치 가정에 따라 달라지므로 별도 가정 없이 단정하지 않습니다.

## 6. 로그 패턴

### 6.1 반복마다 크기를 배수로 변경

```python
i = 1
while i < n:
    process(i)
    i *= 2
```

`i`의 값은 `1, 2, 4, 8, ...`로 증가합니다. `k`회 후 `i = 2^k`이므로 `2^k >= n`이 되는 최소 `k`를 구하면 됩니다.

```text
2^k >= n
k >= log₂ n
```

따라서 시간 복잡도는 `O(log n)`입니다.

### 6.2 반복마다 문제 크기를 나누는 경우

```python
while high - low > 1:
    middle = (low + high) // 2
    narrow_range(middle)
```

검색 범위가 매회 절반 정도로 줄어들면 남은 범위가 1이 될 때까지의 반복 횟수는 `O(log n)`입니다. 이진 탐색이 대표적인 사례입니다.

### 6.3 선형 반복과 로그 작업의 결합

```python
for value in values:                 # n회
    binary_search(index, value)      # log m회
```

전체 복잡도는 다음과 같습니다.

```text
O(n log m)
```

`m = n`인 경우에만 `O(n log n)`으로 표현합니다.

### 6.4 로그의 밑

`log₂ n`, `log₁₀ n`, `ln n`은 밑이 상수인 경우 다음 관계를 가집니다.

```text
log_a n = log_b n / log_b a
```

밑 변환으로 생기는 상수 계수는 점근 표기에서 생략하므로 모두 `Θ(log n)`으로 표현할 수 있습니다. 다만 실제 반복 횟수를 계산하거나 구현 비용을 비교할 때는 밑을 구분해야 합니다.

## 7. 재귀와 점화식

### 7.1 재귀 분석 절차

재귀 알고리즘은 다음 순서로 분석합니다.

1. 입력 크기 `n`을 정의합니다.
2. 한 번의 호출에서 수행하는 비재귀 작업 비용을 계산합니다.
3. 재귀 호출의 개수와 각 호출의 입력 크기를 확인합니다.
4. 점화식 `T(n)`을 작성합니다.
5. 재귀 트리, 반복 전개 또는 적절한 정리로 결과를 구합니다.
6. 재귀 호출 스택의 최대 깊이를 공간 복잡도에 반영합니다.

### 7.2 한 번에 절반으로 줄이는 재귀

```python
def search(values, target, low, high):
    if low >= high:
        return False
    middle = (low + high) // 2
    if values[middle] == target:
        return True
    if values[middle] < target:
        return search(values, target, middle + 1, high)
    return search(values, target, low, middle)
```

재귀 호출이 한 번이고 입력 크기가 절반으로 줄어들며, 현재 호출의 작업이 `O(1)`이면 다음과 같습니다.

```text
T(n) = T(n / 2) + O(1)
T(n) = O(log n)
```

재귀 깊이도 `O(log n)`이므로 재귀 구현의 보조 공간은 `O(log n)`, 반복 구현은 추가 호출 스택을 사용하지 않아 `O(1)`로 볼 수 있습니다.

### 7.3 분할 정복

분할 정복(Divide and Conquer)은 문제를 작은 부분 문제로 나누고, 부분 문제를 해결한 뒤 결과를 결합하는 방식입니다.

```text
T(n) = aT(n / b) + f(n)
```

- `a`: 생성되는 부분 문제 수
- `n / b`: 각 부분 문제의 크기
- `f(n)`: 분할·결합에 필요한 현재 호출 비용

대표 사례는 다음과 같습니다.

| 알고리즘       | 점화식                  | 시간 복잡도  |
|----------------|-------------------------|--------------|
| 이진 탐색      | `T(n) = T(n/2) + O(1)`  | `O(log n)`   |
| 병합 정렬      | `T(n) = 2T(n/2) + O(n)` | `O(n log n)` |
| 선형 분할 결합 | `T(n) = T(n-1) + O(n)`  | `O(n²)`      |

점화식 결과를 외우기보다 `부분 문제 수 × 부분 문제 크기 × 결합 비용`을 먼저 확인해야 합니다.

### 7.4 중복 재귀 호출

```python
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)
```

두 재귀 호출이 같은 부분 문제를 반복 계산하므로 호출 트리가 빠르게 커집니다.

```text
T(n) = T(n - 1) + T(n - 2) + O(1)
```

단순 재귀 피보나치의 시간 복잡도는 지수 시간이며, 메모이제이션이나 반복형 동적 계획법으로 중복 계산을 제거하면 `O(n)` 시간으로 개선할 수 있습니다. 개선된 방식의 공간 복잡도는 결과 저장 방식에 따라 `O(n)` 또는 두 상태만 유지하는 `O(1)`이 될 수 있습니다.

## 8. 대표 복잡도 패턴

| 복잡도       | 코드·알고리즘 패턴                | 분석 핵심                     |
|--------------|-----------------------------------|-------------------------------|
| `O(1)`       | 인덱스로 원소 한 개 접근          | 입력 크기와 무관한 일정 연산  |
| `O(log n)`   | 이진 탐색, 범위 절반 축소         | 매 단계 문제 크기 감소        |
| `O(n)`       | 배열 한 번 순회                   | 각 원소를 최대 일정 횟수 확인 |
| `O(n log n)` | 정렬, `n`회 반복 안의 이진 탐색   | 선형 작업과 로그 작업 결합    |
| `O(n²)`      | 모든 원소 쌍 비교, 이중 중첩 순회 | 두 입력 축의 조합             |
| `O(2ⁿ)`      | 원소마다 선택·비선택을 모두 탐색  | 부분집합 수 증가              |
| `O(n!)`      | 가능한 모든 순열 생성             | 순서 조합 수 증가             |

복잡도만 보고 알고리즘의 우열을 절대적으로 판단하지 않습니다. 입력 크기, 상수 계수, 메모리 접근, 조기 종료, 구현 언어를 함께 고려해야 합니다.

## 9. 공간 복잡도

### 9.1 입력 공간과 보조 공간

```python
def copy_values(values):
    result = []
    for value in values:
        result.append(value)
    return result
```

입력 길이가 `n`이면 결과 배열이 `n`개 원소를 저장하므로 추가 공간은 `O(n)`입니다. 입력 자체가 이미 사용하는 공간을 포함할지 여부는 분석 기준에 명시해야 합니다.

### 9.2 재귀 호출 스택

```python
def countdown(n):
    if n == 0:
        return
    countdown(n - 1)
```

호출 깊이가 `n`이므로 시간 복잡도는 `O(n)`, 재귀 스택 공간도 `O(n)`입니다. 같은 동작을 반복문으로 작성하면 추가 스택 공간은 `O(1)`로 줄어듭니다.

### 9.3 시간과 공간의 trade-off

| 방법                    | 시간 복잡도 | 추가 공간 | 특징                    |
|-------------------------|-------------|-----------|-------------------------|
| 단순 재귀 피보나치      | 지수 시간   | `O(n)`    | 중복 계산               |
| 메모이제이션            | `O(n)`      | `O(n)`    | 결과 저장으로 시간 절약 |
| 반복형 두 상태 피보나치 | `O(n)`      | `O(1)`    | 필요한 상태만 유지      |

메모리를 더 사용하여 계산 결과를 재사용하면 시간을 줄일 수 있습니다. 반대로 메모리를 제한하면 반복 계산이나 추가 시간이 필요할 수 있습니다.

## 10. 사례별 주의사항

### 10.1 Python 자료구조 비용

Python의 자료구조 연산 비용은 언어 문법 자체와 특정 구현체의 구현 비용을 구분해야 합니다. CPython 기준 복잡도 표를 사용할 때는 구현체와 버전을 함께 표시합니다.

| 자료구조·연산           | 대표 복잡도              | 전제·주의                   |
|-------------------------|--------------------------|-----------------------------|
| `list[i]`               | `O(1)`                   | 인덱스 접근                 |
| `list` 선형 탐색        | `O(n)`                   | 별도 인덱스 없음            |
| `list.append()`         | 상환 `O(1)`              | 확장 시 개별 비용 증가 가능 |
| `list.insert(0, value)` | `O(n)`                   | 기존 원소 이동              |
| `deque.appendleft()`    | 대략 `O(1)`              | 양 끝 연산                  |
| `value in set`          | 평균 `O(1)`, 최악 `O(n)` | 해시 충돌과 구현 조건 고려  |
| `value in dict`         | 평균 `O(1)`, 최악 `O(n)` | 해시 충돌과 구현 조건 고려  |

### 10.2 정렬 여부와 탐색

정렬되지 않은 배열에서 선형 탐색은 `O(n)`입니다. 정렬된 배열에서 이진 탐색을 적용하면 `O(log n)`으로 탐색할 수 있지만, 정렬 자체에 드는 비용과 정렬 상태 유지 비용을 별도로 계산해야 합니다.

한 번만 탐색한다면 정렬 비용이 이득을 상쇄할 수 있습니다. 반복 탐색이 충분히 많거나 정렬된 상태를 재사용할 수 있을 때 정렬 비용을 분산할 수 있습니다.

### 10.3 그래프 표현

그래프 알고리즘의 복잡도는 정점 수 `V`, 간선 수 `E`와 그래프 표현 방식에 따라 달라집니다.

| 표현 방식   | 인접 여부 확인   | 모든 이웃 순회 | 저장 공간  |
|-------------|------------------|----------------|------------|
| 인접 리스트 | 구현에 따라 다름 | `O(degree(v))` | `O(V + E)` |
| 인접 행렬   | `O(1)`           | `O(V)`         | `O(V²)`    |

따라서 BFS·DFS를 설명할 때도 알고리즘만 나열하지 않고 입력 그래프의 표현 방식을 함께 명시합니다.

### 10.4 문자열과 복합 객체

문자열 비교, 해시, 복사처럼 원소 하나를 처리하는 비용이 문자열 길이에 비례할 수 있습니다. 자료구조 원소 수만 `n`으로 세면 내부 문자열 길이 `k`에 따른 비용을 놓칠 수 있으므로 필요하면 `n`, `k`를 별도 변수로 둡니다.

## 11. 실제 성능과의 차이

점근 복잡도는 알고리즘 선택의 중요한 기준이지만 실제 성능을 완전히 결정하지는 않습니다.

- `O(1)` 연산도 큰 상수 비용이나 메모리 접근 비용을 가질 수 있습니다.
- 작은 입력에서는 `O(n²)` 알고리즘이 `O(n log n)` 알고리즘보다 빠를 수 있습니다.
- 연속 메모리 접근은 캐시 효율이 높을 수 있습니다.
- 동적 메모리 할당, 해시 충돌, 입출력은 기본 연산 가정을 바꿀 수 있습니다.
- Python 구현체와 버전은 자료구조의 실제 비용에 영향을 줄 수 있습니다.
- 실제 운영 성능은 대표 입력을 사용한 벤치마크로 별도 검증해야 합니다.

복잡도 분석은 벤치마크를 대체하지 않습니다. 반대로 벤치마크 하나만으로 입력 크기가 커졌을 때의 증가율을 보장할 수도 없습니다. 두 방법을 목적에 맞게 함께 사용합니다.

### 복잡도와 벤치마크의 역할

| 방법             | 답하는 질문                             | 한계                              |
|------------------|-----------------------------------------|-----------------------------------|
| 점근적 분석      | 입력이 커질 때 비용이 어떻게 증가하는가 | 상수·하드웨어·실제 입력 영향 약함 |
| 마이크로벤치마크 | 특정 환경에서 얼마나 빠른가             | 다른 입력·환경으로 일반화 어려움  |
| 프로파일링       | 실제 실행에서 어디가 병목인가           | 실행 경로와 workload에 의존       |

## 12. 분석 체크리스트

알고리즘의 시간·공간 복잡도를 분석할 때 다음 순서를 사용합니다.

1. 입력 크기 `n`, `m`, `V`, `E`를 정의합니다.
2. 기본 연산 하나의 비용을 정합니다.
3. 순차 코드의 비용을 더합니다.
4. 중첩 코드의 반복 횟수를 곱하거나 실제 합으로 계산합니다.
5. 조건 분기에서 최선·평균·최악 경로를 구분합니다.
6. 반복마다 입력 크기가 줄어드는지 확인하여 로그 패턴을 찾습니다.
7. 함수 호출 내부의 비용을 포함합니다.
8. 재귀 호출의 수와 입력 축소 비율로 점화식을 작성합니다.
9. 반복 전개나 재귀 트리로 점화식 결과를 확인합니다.
10. 상수 계수와 낮은 차수 항을 제거하여 점근 표기로 단순화합니다.
11. 보조 배열, 해시 테이블, 재귀 스택의 공간을 계산합니다.
12. 평균·최악·상환 비용의 전제와 구현체를 명시합니다.
13. 실제 병목이 중요하면 벤치마크와 프로파일링으로 별도 확인합니다.

### 최종 기록 예시

```text
입력: 정렬된 배열 길이 n, 검색 요청 수 m
시간: 정렬이 이미 완료되었다는 전제에서 m회 이진 탐색 → O(m log n)
보조 공간: 반복형 이진 탐색 → O(1)
조건: 재귀형 구현이면 호출 스택 O(log n)
```
