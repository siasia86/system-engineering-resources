# 32_system-engineering-resources 문제 기록

## 1. 기록 범위

실제 현장의 이슈를 복제하지 않은 초기 후보입니다. 기존 이슈·원인·복구 근거를 유지하며 다음 항목을 실제 관찰로 작성합니다.

## 2. 작성과 원인 분석

ID·발견일·담당·증상·재현 조건·기대/관찰 결과·영향·확인 사실·가설·미확인·다음 검사·완료 조건을 기록합니다. 실패하면 영향받는 작업·게시를 멈추고 기존 변경과 증거를 보존합니다.

32에서 출처·확인일·버전·지원 근거·미확인을 기록합니다. 필요한 실제 참고 clone은 41, agent/skill 구현·설치는 35의 담당 범위입니다. 조사 기록을 운영 호스트 변경 승인으로 해석하지 않습니다. 운영 원문·개인 정보는 기록 본문에 넣지 않습니다. 실행 단계는 [PLAN](../PLAN.md) 한 곳에서 관리하고 상태는 [TODO](../TODO.md)에 연결합니다.

## 3. 종료 기준

원인 파악만으로 해결 처리하지 않습니다. [필수 검증](verification.md)과 실제 수정 결과를 확인하고 [완료 기록](../CHANGELOG.md)에 근거를 남깁니다. 미수행·잔여 조건은 명확히 유지합니다.
