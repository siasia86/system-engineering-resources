# 32_system-engineering-resources Codex 운영 기준

## 1. 대상과 권한

공식·웹·저장소 자료 조사와 기술 문서의 저장소 작업에 적용할 병합 후보입니다. 현재 사용자 요청·적용 지침·플랫폼 정책·OS 권한을 따릅니다. 기존 AGENTS·운영 기준이 있으면 원문을 보존하고 실제 차이를 검토합니다.

32에서 출처·확인일·버전·지원 근거·미확인을 기록합니다. 필요한 실제 참고 clone은 41, agent/skill 구현·설치는 35의 담당 범위입니다. 조사 기록을 운영 호스트 변경 승인으로 해석하지 않습니다.

## 2. 책임과 변경 보존

Git 루트·branch·기존 변경·담당 파일을 확인합니다. 같은 이름의 모듈·다른 환경의 규칙을 현재 대상에 자동 적용하지 않습니다.

현행 PLAN·TODO·CHANGELOG와 공통 관리 문서는 .governance에 통일합니다. 이전 루트 상태·이력을 실제 적용에서 보존·병합하고 TODO2 상세 설계 과제를 일반 작업에 일괄 적용하지 않습니다. 초기 후보로 기존 상태나 검증 근거를 덮어쓰지 않습니다.

## 3. 기록과 결과물

[TODO](TODO.md)는 현행 상태, [PLAN](PLAN.md)은 실행·의존성·검증·복구, [ISSUE](ISSUE.md)는 원인·영향, [완료 기록](CHANGELOG.md)은 실제 결과를 맡습니다.

새 결과물 위치가 필요하면 대상 Git 루트 기준 `.governance/outputs/<작업ID_작업명>/YYYYMMDD_markdown/`·`YYYYMMDD_image/`처럼 날짜가 앞에 오는 유형 폴더를 사용합니다. 실제 결과가 생기는 폴더만 만들고 관리 문서에서 연결합니다. 기존 산출물·도구 고정 경로·개인 업데이트 보관 구조는 그대로 유지합니다. private 원문은 검증한 Git 제외 위치에서 보존하고 원격에는 필요한 비민감 요약만 기록합니다.

일반 문서에는 이 문서 끝과 같은 작성일·마지막 업데이트·권리 고지를 둡니다. 두 날짜 사이에는 빈 줄 한 개를 두며 새 문서는 실제 작성일, 수정한 현행 문서는 마지막 업데이트만 실제 수정일로 적습니다. 최초 작성일·과거 발생일·원문 날짜와 라이선스를 임의로 바꾸거나 자동 날짜 변경을 추가하지 않습니다.

이미지에는 대체 텍스트를 넣고 관리 파일은 상대 경로로 연결합니다. 출처가 필요한 문서는 말미의 `## 참고 자료`에 실제 URL·판본·내부 문서를 목록으로 연결합니다. 기존 비교표·근거표를 일괄 변경하지 않습니다.

#### DOCS-32 예외

- 주제 문서 파일명은 소문자와 밑줄을 사용합니다. `README.md`·`AGENTS.md`·관리 문서·도구 고정 파일명은 유지하며 기존 파일과 링크를 일괄 변경하지 않습니다.
- 관리 이미지는 `98_image/<문서명>/` 아래에 두고 문서 기준 상대 경로로 연결합니다.
- 출처 목록의 외부 자료에는 `— ★★☆☆☆`처럼 자료 유형에 따른 별점을 붙입니다. 블로그·튜토리얼은 별 두 개를 기본으로 하고 공식 문서는 별 세 개를 사용합니다. 단순 참고는 별 한 개, RFC·주요 도서는 별 네 개를 사용할 수 있으며 별 다섯 개는 확인 근거가 있을 때만 사용합니다. RFC·논문·책·내부 문서에는 생략할 수 있습니다. 별점만으로 내용의 정확성을 검증했다고 표시하지 않습니다.
- `_reference/` 원문은 푸터 대신 `sources`·`last_checked` frontmatter를 유지합니다. 이를 인용한 문서는 H1 바로 아래 `<!-- reference: _reference/<파일>.md -->`로 원본을 연결하고 참고 자료도 기록합니다. 보존 원문을 형식 검사 때문에 재작성하지 않습니다.
- 통계 배지는 푸터 앞의 `## 통계`에 둡니다. 대상은 실제 원격 `siasia86/system-engineering-resources`이며 stars·forks·watchers·last commit·license 배지를 사용합니다. Actions 배지는 `.github/workflows/update-date.yml`의 실제 검사 workflow에 연결합니다. 이 파일은 확인일 2026-10-15 현재 `Markdown validation`이며 날짜 자동 갱신 기능이 아닙니다. 원격·workflow가 달라지면 해당 배지만 대조합니다.

#### 검사와 적용

기존 저장소 설정과 예외를 보존하며 공통 TOML로 덮어쓰지 않습니다. 중앙 profile의 공통 TOML은 유지하고 현장과의 차이·제외 범위를 실제 적용 기록에 남깁니다. 푸터 예외 파일을 검사할 때는 확정한 정확한 파일 경로만 `--no-footer` 호출로 분리합니다. 일반 문서와 README는 기본 호출로 검사하며 디렉터리 재귀에서 제외되는 루트 README는 직접 지정합니다. 경로 패턴이 검사기의 glob으로 작동한다고 가정하지 않습니다. 검사 통과·중앙 게시·현장 병합·실제 사용을 구분합니다.
