## 2. AX 환경 적용

### 2.1. 작업 형태 고르기

단계가 미리 정해지는 일은 고정 흐름으로, 단계 수를 예측할 수 없는 일만 자율 에이전트로 맡깁니다. 자율에 맡길수록 비용과 오류 누적이 커지므로 검사와 정지 조건을 함께 둡니다.

| 상황                          | 권하는 형태                       | AX 환경에서의 예                         |
|-------------------------------|-----------------------------------|------------------------------------------|
| 순서가 고정된 반복 작업       | 단계 연결(Prompt chaining)        | 작성 → 검사 → 게시를 정해진 순서로 실행  |
| 입력 종류에 따라 처리가 갈림  | 분기(Routing)                     | 요청 종류별로 다른 skill·지침 선택       |
| 서로 독립인 작업 여러 개      | 병렬(Parallelization)             | 파일별 검토를 하위 에이전트에 나눠 맡김  |
| 하위 작업을 미리 정할 수 없음 | 지휘·작업자(Orchestrator-workers) | 총괄 세션이 작업을 쪼개 다른 세션에 배정 |
| 기준에 맞을 때까지 고쳐야 함  | 평가·개선(Evaluator-optimizer)    | 작성 세션과 검토 세션을 나눠 반복        |

### 2.2. 지침 파일의 수준 맞추기

저장소 지침 파일은 매 세션 문맥에 들어가므로 짧고 구체적으로 씁니다. 상황마다 다른 절차는 지침 파일이 아니라 skill로 옮겨, 필요할 때만 읽히게 합니다.

| 증상                             | 조치                                                 |
|----------------------------------|------------------------------------------------------|
| 같은 실수가 두 번 나옴           | 지침 파일에 한 줄 규칙으로 추가                      |
| 지침 파일이 길어져 지시가 무시됨 | 일부 상황에만 쓰는 내용을 skill·경로별 규칙으로 분리 |
| 지시가 서로 충돌함               | 우선순위를 한 곳에 적고 오래된 지시를 삭제           |
| 반드시 지켜야 하는 금지 사항     | 지침 문장 대신 도구 호출 전 hook으로 강제            |

표의 "같은 실수가 두 번 나오면 규칙 추가"와 "금지 사항은 hook으로 강제"는 두 글이 아니라 Claude Code 문서(Extend Claude Code, memory)에 나오는 권고입니다.

도구별 지침 파일 차이는 [지침 파일 노트](../_reference/agent_instruction_files_official_notes.md), skill 형식은 [Agent Skills 규격 노트](../_reference/agent_skills_spec_official_notes.md)에서 확인합니다.

### 2.3. 문맥 예산 관리

| 기법               | 뜻                                               | AX 환경 장치                                     |
|--------------------|--------------------------------------------------|--------------------------------------------------|
| 필요할 때 읽기     | 내용 대신 경로·링크를 들고 있다가 필요할 때 읽음 | 지침에는 문서 위치만 두고 본문은 작업 때 읽게 함 |
| 요약(compaction)   | 한도에 가까운 대화를 요약하고 새로 이어감        | 요약 직후 다시 읽을 파일과 남길 항목을 미리 정함 |
| 구조화된 메모      | 문맥 밖 파일에 진행 상태를 적고 나중에 다시 읽음 | 저장소 인계 파일, TODO, 작업 기록                |
| 하위 에이전트 분리 | 큰 탐색은 별도 문맥에서 하고 요약만 돌려받음     | 조사·검토를 하위 에이전트나 별도 세션에 맡김     |

### 2.4. 도구 설계

에이전트가 쓰는 도구(스크립트, 검사기, MCP 도구)는 사람이 써도 헷갈리지 않게 만듭니다.

- 기능이 겹치는 도구를 줄이고 이름만 보고 고를 수 있게 합니다.
- 입력 형식과 예시, 다른 도구와의 경계를 설명에 적습니다.
- 실수하기 어려운 형태로 받습니다. 첫 글은 상대 경로 대신 절대 경로만 받게 바꿔 오류를 없앤 사례를 듭니다.
- 결과는 필요한 만큼만 돌려줘 문맥을 아낍니다.

## 3. 점검표

- [ ] 이 작업이 정말 자율 에이전트가 필요한가, 고정 흐름으로 충분한가
- [ ] 저장소 지침 파일이 짧고, 상황별 절차는 skill로 분리됐는가
- [ ] 반드시 막을 행동은 hook·권한 설정으로 강제되는가
- [ ] 긴 작업의 진행 상태가 문맥 밖 파일(인계 파일·TODO)에 남는가
- [ ] 큰 탐색·검토를 별도 문맥으로 분리했는가
- [ ] 각 단계에 검사와 정지 조건이 있는가
